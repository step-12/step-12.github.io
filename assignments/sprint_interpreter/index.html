      Build Your Own Sprint Interpreter#

      You have run Sprint programs by hand. You read a cell, did what it said, and moved on to the next one.

      Now you will write a JavaScript program that does this for you. It is called an interpreter.

      You will build it in small parts. Each part adds one or more instructions to the interpreter from the previous part.

      For each part:

      1. Read it and trace the examples by hand.
      2. Write the code and run it on the examples.
      3. Commit your code before you move on.

      How it works#

      You give the interpreter a Sprint program as a string. The cells are separated by spaces.

      It runs the program and returns an array with the contents of all the cells at the end.

      interpret("1 2 3 4 9"); // [1, 2, 3, 5, 9]

      The project#

      You will be given a repository with this structure:

      sprint-interpreter/
├── index.js
├── lib/
│   └── sprint.js
└── tests/
    └── sprint.test.js

      1. Stop#

      Every program needs a way to end. Start with that.

      Instruction 9 is halt. It has no other numbers after it. When the interpreter reaches it, it stops and returns the cells as they are.

      interpret("9"); // [9]

      Cells after a halt are never run, so they can hold any numbers.

      interpret("9 1 2 3 4"); // [9, 1, 2, 3, 4]

      2. Add#

      Now teach the interpreter to add.

      Instruction 1 is add:

      1 [First Cell] [Second Cell] [Result Cell]

      It adds the values in the first and second cells and puts the answer in the result cell. The next instruction is 4 cells ahead.

      interpret("1 2 3 4 9"); // [1, 2, 3, 5, 9]

      Cell 2 holds 2 and cell 3 holds 3. The answer, 5, goes in cell 4. Then the interpreter moves 4 cells ahead to cell 5, which is the halt.

      Another one:

      interpret("1 2 3 4 1 4 4 8 9"); // [1, 2, 3, 5, 1, 4, 4, 10, 9]

      3. Subtract#

      Instruction 2 is subtract. It looks like add:

      2 [First Cell] [Second Cell] [Result Cell]

      It subtracts the value in the second cell from the value in the first cell. The next instruction is 4 cells ahead.

      interpret("2 3 2 4 9"); // [2, 3, 2, -1, 9]

      Cell 3 holds 2 and cell 2 holds 3. So 2 - 3 = -1, and -1 goes in cell 4.

      The order matters: a - b is not the same as b - a.

      Add, subtract and halt should work together in the same program.

      4. Jump#

      Until now, the interpreter has only moved forward, one instruction after another. A jump lets it go somewhere else.

      Instruction 3 is jump:

      3 [Target Cell]

      The next instruction is at the target cell.

      interpret("3 7 1 2 2 2 9"); // [3, 7, 1, 2, 2, 2, 9]

      The jump at cell 1 goes to cell 7, which is the halt. The add at cell 3 is skipped. If it had run, cell 2 would have changed from 7 to 14.

      5a. Jump If Equal#

      Now let the interpreter make a choice.

      Instruction 4 is jump if equal:

      4 [First Cell] [Second Cell] [Target Cell]
      • If the values in the first and second cells are equal, go to the target cell.
      • If not, go to the instruction 4 cells ahead.

      Equal values:

      interpret("4 5 6 9 1 1 1 1 9"); // [4, 5, 6, 9, 1, 1, 1, 1, 9]

      Cells 5 and 6 both hold 1, so the interpreter jumps to cell 9, the halt. The add at cell 5 is skipped.

      Different values:

      interpret("4 5 6 9 1 2 1 1 9"); // [9, 5, 6, 9, 1, 2, 1, 1, 9]

      Cell 5 holds 1 and cell 6 holds 2. They are not equal, so the interpreter goes to cell 5 and runs the add. You can see this because cell 1 changed.

      5b. Jump If Less Than#

      Instruction 5 is jump if less than. It has the same format:

      5 [First Cell] [Second Cell] [Target Cell]
      • If the value in the first cell is less than the value in the second cell, go to the target cell.
      • If not, go to the instruction 4 cells ahead.

      First value is smaller:

      interpret("5 5 6 9 1 2 1 1 9"); // [5, 5, 6, 9, 1, 2, 1, 1, 9]

      First value is not smaller:

      interpret("5 5 6 9 2 1 1 1 9"); // [0, 5, 6, 9, 2, 1, 1, 1, 9]

      6. Labels#

      Counting cells is hard. If you add one instruction at the top, every jump target below it is wrong.

      A label is a name for a cell. Write the name, a colon, and then the cell’s value: n1:3. This gives the name n1 to that cell. Anywhere else, n1 means the number of that cell.

      1 2 n1:3 4 1 n1 2 8 9

      n1:3 is cell 3. It still holds 3, and its name is n1. Later, n1 is replaced by 3. The program becomes:

      1 2 3 4 1 3 2 8 9
      interpret("1 2 n1:3 4 1 n1 2 8 9"); // [1, 2, 3, 5, 1, 3, 2, 5, 9]

      Remember:

      • A label does not change the value in its cell.
      • A label can be used before or after the cell it names.
      • Labels are not instructions. The array you return has only numbers.
