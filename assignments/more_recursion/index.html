    A Few More Loops to Avoid#

    Liked the recursion problems?

    Here are a few more.

    Same rules as before: try to solve each problem by making the problem smaller, and let the function call itself.

    Two Ways to Recur#

    There are two common ways we will write recursive functions.

    They do the same sort of work, but they keep track of things differently.

    1. The Accumulator#

    Sometimes we pass the answer-so-far as an argument.

    For example, suppose we want to add all the numbers from 1 to x:

    f(x, total)
  = total when x = 0
  = f(x - 1, total + x)

    We might start with:

    f(3, 0)

    which becomes:

    f(3, 0)
→ f(2, 3)
→ f(1, 5)
→ f(0, 6)
→ 6

    The total argument carries our partial answer through the recursion.

    2. The Smaller Answer#

    The other approach is perhaps more familiar.

    Instead of carrying the answer-so-far, we ask the smaller problem for its answer:

    f(x)
  = 0 when x = 0
  = x + f(x - 1)

    So:

    f(3)
→ 3 + f(2)
→ 3 + (2 + f(1))
→ 3 + (2 + (1 + f(0)))
→ 6

    Here, the answer is built as the recursive calls return.

    No Global Variables#

    There is another important idea hiding here.

    When writing functions in this mathematical style, we don’t declare some global variable and quietly change it as the function runs.

    If a recursive function needs to remember something, pass it as an argument.

    That is why the accumulator version has total as a parameter.

    The information a function needs should be visible in its arguments.

    Two styles. Same recursion. Different places to keep the information.

    1. Digit by Digit#

    Write a recursive function that calculates the sum of the digits of a positive integer.

    For example:

    f(7)   = 7
f(12)  = 3
f(123) = 6
f(501) = 6

    Think about how you can separate the last digit from the rest of the number.

    2. How Many?#

    Write a recursive function that calculates the number of digits in a positive integer.

    f(7)    = 1
f(42)   = 2
f(1234) = 4

    What is the smallest number you can solve immediately?

    What happens to the number when you remove one digit?

    3. Power Trip#

    Write a recursive function that calculates (x^n).

    For example:

    power(2,1) = 2
power(2,2) = 4
power(2,3) = 8
power(3,4) = 81

    Remember that:

    $$ x^n = x \times x^{n-1} $$

    So the recursive part is practically writing itself.

    Almost.

    4. Division, Revisited#

    Earlier, you calculated the remainder of a division.

    Now calculate the quotient.

    Write a recursive function that calculates how many times y can be subtracted from x before x becomes smaller than y.

    For example:

    quotient(10,3) = 3
quotient(5,3)  = 1
quotient(12,4) = 3

    You may find it useful to think of:

    10 → 7 → 4 → 1

    as three subtractions.

    What should the function return when x < y?

    5. Letter Counter#

    Write a recursive function that counts how many times a particular letter occurs in a word.

    For example:

    count("hello", "l") = 2
count("banana", "a") = 3
count("hello", "z") = 0

    You already have functions for getting the first letter of a word and everything after it.

    You will also need to decide whether two letters are the same.

    You could define a small helper function:

    same(x,y)
  = true when x and y are the same letter
  = false otherwise

    Then ask:

    How many times does x occur in this word?

    The answer depends on whether the first letter is x, and how many times x occurs in the rest of the word.

    6. Palindrome Patrol#

    A palindrome is a word that reads the same forwards and backwards.

    For example:

    "level"
"radar"
"racecar"

    Write a recursive function that determines whether a word is a palindrome.

    For example:

    palindrome("level") = true
palindrome("hello") = false
palindrome("a")     = true
palindrome("")      = true

    You may want to define some helper functions first:

    first(x) = first letter of x

last(x) = last letter of x

middle(x) = everything except the first
           and last letters of x

    You already know how to get the first letter and remove the first letter.

    Can you build last and middle from those?

    Then the real question becomes:

    Are the first and last letters the same, and is everything in between also a palindrome?

    That’s recursion hiding in plain sight.
