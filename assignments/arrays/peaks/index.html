      Peaks#

      A peak is a value that is greater than the values immediately before and after it.

      Your task is to detect peaks in an array of numbers and draw a line chart that highlights them.

      Reference output

      Requirements#

      • Create an array of numbers yourself. Start with fixed values so you can reason about the expected output. Once your program is working, experiment with randomly generated data.
      • Draw a line chart representing the values in your array.
      • Identify peaks and highlight them with red circles.
      • A value is a peak only if it is strictly greater than both its immediate neighbours. The first and last elements cannot be peaks. Equal values and plateaus do not count as peaks.
      • Determine the horizontal and vertical scales from the data and the dimensions of the screen.
      • Scale the vertical axis so that the maximum value maps to 90% of the screen height.
      • Calculate the horizontal spacing of the data points appropriately. Each point must occupy at least one pixel horizontally. If the data exceeds the available screen width, it is truncated.
      • Allow the screen width and height to be configured.
      • Use only the following colours: r.SKYWHITE, r.BLACK, and r.RED.

      Before you begin#

      Resist the temptation to start writing code immediately.

      Take a moment to understand the problem. What does it mean for a value to be a peak? How should the values in your array correspond to positions on the screen? How will you distinguish the peaks from the other points?

      Think about the problem before deciding how to solve it. A little planning now can save you from having to untangle a complicated implementation later.

      Getting started#

      Start with the following array of 10 numbers:

      const data = [12, 45, 78, 23, 91, 56, 34, 67, 89, 40];

      Before writing any code, write down a checklist of the tasks you need to complete. Break the problem down and think about what you need to figure out before you begin implementing it.

      Once your program works with the initial data, test it with other arrays. Try different lengths and values, including randomly generated data.

      As you work#

      Test your program with different arrays. What happens when the array contains only two values? What happens when neighbouring values are equal? What happens when several consecutive values form a plateau?

      Consider what happens when you change the screen dimensions or when the data extends beyond the available screen width.

      As your program evolves, keep revisiting your code. Refactor when you discover a clearer way to express an idea or when responsibilities have become tangled. Avoid accumulating patches on top of patches just to make the program work.

      Once you are confident that your program handles fixed data correctly, try generating random values. Different inputs often expose assumptions that were easy to overlook when working with a single example.

      The goal is not merely to produce a chart that looks right for one array. It is to build a program that correctly identifies and displays peaks across different inputs and screen dimensions.
