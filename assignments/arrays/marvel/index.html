      Marvellous filters#

      Wolverine has a face that is hard to miss. But what happens when we stop thinking of it as a picture and start thinking of it as data?

      In this set of assignments, we will explore images using JavaScript. We will flip them, rotate them, crop them, change their brightness, add colour, blur them, and even look for interesting patterns hidden inside them.

      Our subject is Wolverine. Our tool is the bitmap.

      What is a bitmap?#

      An image on your screen is made up of tiny elements called pixels. Each pixel represents a small part of the image. Put enough pixels together, and they form a picture.

      A bitmap is a way of representing an image using these pixels. There are different ways to represent a bitmap, depending on what information we want to store and how we want to use it.

      For our assignments, we will use a simplified representation. We will work with grayscale images, where each pixel is represented by a single number.

      This number represents the brightness of the pixel:

      • 0 represents black.
      • 255 represents white.
      • Values between 0 and 255 represent shades of gray.

      But how does a single number become a pixel on the screen?

      From a number to a pixel#

      Screens display colours using three colour channels: red, green, and blue, commonly called RGB.

      Each channel has a value between 0 and 255. By combining different amounts of red, green, and blue, we can represent a wide variety of colours.

      For example:

      RedGreenBlueColour
      000Black
      255255255White
      25500Red
      02550Green
      00255Blue
      128128128Gray

      In our representation, we store just one number for each pixel. When we display that pixel, we use the same number for all three colour channels.

      Suppose a pixel has the value 128. We display it as:

      {
  r: 128,
  g: 128,
  b: 128,
  a: 255
}

      All three channels have the same intensity, so the resulting pixel is gray.

      If the value is 0, all three channels are zero, producing black. If the value is 255, all three channels are at their maximum, producing white.

      This is how our single number represents a grayscale pixel on a screen.

      Later, we will experiment with changing the colour channels independently. For now, we only need to understand how to turn our numbers into grayscale pixels.

      How will we represent a bitmap?#

      We will represent each bitmap as a JavaScript object with three properties:

      • width: the number of pixels in each row.
      • height: the number of rows.
      • points: a two-dimensional array containing the brightness of every pixel.

      Here is a small example:

      {
  width: 3,
  height: 2,
  points: [
    [0, 128, 255],
    [255, 128, 0]
  ]
}

      This bitmap is three pixels wide and two pixels tall. Its first row contains a black pixel, a gray pixel, and a white pixel. The second row contains the same brightness values in reverse order.

      Notice that points is an array of arrays. Each inner array represents one row of pixels.

      The number at points[0][1] is 128. It describes the pixel in the first row and second column. When displayed, that pixel becomes {r: 128, g: 128, b: 128}.

      This is our representation of a bitmap, not the only way to represent one. We have chosen it because it gives us a simple way to work with images using the JavaScript concepts we already know.

      A few rules before we begin#

      1. The original bitmap must not change.

      When we transform an image, we must leave the original bitmap untouched. If we flip an image, for example, we should be able to look at both the original and the flipped version afterwards.

      This matters because JavaScript objects and arrays can be modified. Be careful about changing an array that belongs to the original bitmap.

      2. Work with the data, not just the picture.

      An image may look complicated, but underneath it is a collection of numbers. Our task is to manipulate those numbers to produce the desired result.

      3. Pay attention to what the numbers represent.

      In our bitmap, a number represents the brightness of a grayscale pixel. When we display it, that number becomes three equal RGB values. In later assignments, we will explore what happens when we treat those colour channels differently.

      4. Let the result guide you.

      You will be given a reference image of Wolverine in the starter template. Use it to experiment with your transformations and inspect the results.

      Some assignments will produce a new bitmap. Others will help us discover information about an image or display it in a different way. Pay attention to what each problem asks you to achieve.

      You do not need to solve everything at once. Start small, test your ideas, and build from there.

      1. The Sentinel#

      Before we start changing Wolverine, we need to see him.

      Your first task is to display the bitmap provided in the starter template. Take the bitmap’s width and height into account, and make sure that every pixel appears in the correct position with the correct brightness.

      Remember that the bitmap stores a single number per pixel, but the screen displays a colour. For this assignment, turn each number into a grayscale pixel by using the same value for its red, green, and blue channels.

      Compare your result with the reference image. Does the picture look right? Are the dark and light regions where you expect them to be? Does the displayed image have the same dimensions as the bitmap?

      Once you can display Wolverine correctly, you have established the foundation for everything that follows.

      2. Mirror, Mirror#

      Wolverine looks into a mirror. But something is wrong: his reflection is upside down!

      Transform the image so that the top becomes the bottom and the bottom becomes the top. The left and right sides should remain where they are.

      Look carefully at the result. Did the image turn upside down? Is Wolverine’s left side still on the same side of the image?

      Remember: the original bitmap must remain unchanged.

      3. Looking Glass#

      This time, Wolverine looks into a different mirror. His left and right sides have switched places.

      Transform the image so that the left side becomes the right side and the right side becomes the left side. The top and bottom should remain where they are.

      Compare this result with the previous assignment. Both transformations rearrange pixels, but they do so in different directions.

      Can you explain the difference between the two results?

      4. The Rotator#

      Wolverine is used to moving in unexpected directions. Now, turn the entire image clockwise by a quarter turn.

      The image should rotate by 90 degrees. What was at the top should now be on the right. What was on the right should now be at the bottom.

      Pay attention to the dimensions of the image. If the original image is wider than it is tall, what should happen to its width and height after the rotation?

      The picture must remain intact. Every pixel should appear in its new position, with its original brightness.

      5. The Danger Room#

      The Danger Room is a place for focused training. Sometimes, Wolverine needs to concentrate on just one part of the action.

      For this assignment, select a rectangular region of the image and keep only that region. Everything outside the selected rectangle should be excluded from the result.

      You should be able to choose where the rectangle begins and how wide and tall it is.

      Try selecting Wolverine’s face, just his eyes, or another interesting region. What happens to the dimensions of the resulting image when you select a smaller rectangle?

      The original image should remain available even after you crop it.

      6. Darken the Shadows#

      Wolverine disappears into the shadows. We want to remove the brighter parts of the image and keep the darker ones.

      Choose a brightness threshold. Every pixel whose value is greater than the threshold should become black (0). All other pixels should retain their original values.

      Experiment with different thresholds. What happens when the threshold is very low? What happens when it is very high?

      Notice that we are not removing pixels from the image. We are changing some of their values to zero. The dimensions of the image should remain the same.

      7. Extinguish the Highlights#

      Now reverse the effect. We want to remove the darker parts of the image and keep the brighter ones.

      Choose a brightness threshold. Every pixel whose value is less than the threshold should become black (0). All other pixels should retain their original values.

      Try a few different thresholds and compare the results with the previous assignment.

      What happens to a pixel whose value is exactly equal to the threshold? Think carefully about the difference between greater than and less than.

      As before, pixels should not be removed from the image. Only their brightness values change.

      8. The X-Gene#

      Wolverine’s mutations make him unique. Let’s give his image a different appearance by changing its colour.

      Until now, we have displayed each brightness value as three equal RGB values. For example, a brightness of 128 becomes:

      { r: 128, g: 128, b: 128 }

      What happens if we use that brightness only for the red channel?

      { r: 128, g: 0, b: 0 }

      The pixel now appears red. Its intensity depends on the original brightness, but it no longer contains any green or blue.

      Create red, green, and blue versions of the reference image by using the original brightness values in the corresponding colour channel and setting the other two channels to zero.

      Notice that the grayscale brightness data and the displayed colour are two different things. We can use the same underlying image to produce several different colour representations.

      What do the dark regions look like in each version? What happens to the brightest pixels?

      9. The Blur#

      Wolverine moves so quickly that his image becomes blurred.

      A blur softens the sharp boundaries between light and dark regions. Instead of displaying each pixel using only its own brightness, we can use the brightness of nearby pixels to determine its new value.

      Imagine a pixel surrounded by eight other pixels. We can calculate a new brightness by taking the average of the values in this neighbourhood, including the pixel itself.

      For pixels near the edge of the image, some neighbours will fall outside the bitmap. Ignore those neighbours and use only the pixels that exist.

      Try applying the blur repeatedly. Each application should use the result of the previous application.

      What happens after one application? What happens after several? How does the image change as you repeat the process?

      Remember that the original bitmap must remain unchanged, even when you apply the blur multiple times.

      10. Cerebro#

      Cerebro helps the X-Men locate mutants. For our final assignment, we will search the image for something much smaller: pixels that stand out from their immediate surroundings.

      A peak is a pixel whose brightness is greater than the brightness of its immediate neighbours above, below, to the left, and to the right.

      Diagonal neighbours do not count.

      Consider this small bitmap:

      {
  width: 3,
  height: 3,
  points: [
    [10, 20, 10],
    [20, 50, 20],
    [10, 20, 10]
  ]
}

      The centre pixel has a value of 50. Its four immediate neighbours each have a value of 20, so the centre pixel is a peak.

      The corner pixels are not peaks because each has at least one neighbour with a greater value.

      Pixels along the edge have fewer neighbours than pixels in the middle. Consider only the neighbours that actually exist. A pixel qualifies only if its value is strictly greater than every one of them.

      Your task is to find all the peaks in the reference image.

      Once you have found the peaks, use them to create a colour visualisation. Display the original grayscale image, but colour each detected peak red. All other pixels should retain their original grayscale appearance.

      Try this on the reference image. Where do the peaks appear? Are they clustered in certain regions, or spread across the image?

      You have now gone beyond transforming an image. You have used its data to discover something about it, and then used that discovery to create a new visualisation.

      Where to go from here#

      You have rearranged pixels, changed their brightness, altered their colour, blurred their values, and searched for local peaks.

      All of these operations began with the same simple representation: an object containing a width, a height, and a two-dimensional array of numbers.

      The challenge was never just to change a picture. It was to understand the data behind it and discover how that data could be manipulated.

      What other transformations can you imagine?
