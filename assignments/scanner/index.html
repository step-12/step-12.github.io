    Scanning for Particles#

    Imagine that we have sent a particle detector into space.

    The detector is looking at a small region of space around it. It moves from one side of the region to the other, scanning for particles as it goes.

    Our job is to build a simulation of this detector.

    You will build the simulation in several steps. Each step adds one small idea to the previous one.

    Do not try to build the whole thing at once.

    After you have successfully completed each step, commit your work and push it to Git before moving on.

    You should also take a moment at the end of each step to look at your code. Ask yourself whether it is still organized sensibly. If you have duplicated something, introduced a variable in the wrong place, or have a function that is becoming difficult to understand, this is a good time to fix it.

    The Region of Space#

    Your simulation will show a rectangular region of space.

    For simplicity, we will represent this region using the entire height of the screen.

    For example, if your window is 300 pixels wide and 200 pixels high, the region of space is:

    0                                      300
+----------------------------------------+
|                                        |
|                                        |
|                                        |
|                                        |
|                                        |
|                                        |
+----------------------------------------+
                    200

    The important dimension for our problem is the horizontal dimension.

    We will represent things in space as ranges.

    A range has a start and an end.

    For example:

           start              end
         |                 |
         v                 v
         +-----------------+
         |      range      |
         +-----------------+

    If a range starts at 100 and ends at 150, it occupies every position between 100 and 150.

    Visually, we will draw this as a vertical strip extending across the entire height of the screen:

                 100             150
              |               |
              v               v
              +---------------+
              |               |
              |     RANGE     |
              |               |
              |               |
              +---------------+

    We are therefore using the horizontal position to represent our range, while the range occupies the entire height of the screen.

    This will make it easier to see what is happening.

    Step 1 — Build the Scanner#

    Start with just the particle detector.

    The detector itself is a range.

    Give it a width. For example, you might make it 20 pixels wide.

    It should start somewhere on the left side of the region and move horizontally.

    When it reaches one edge, it should change direction.

    When it reaches the other edge, it should change direction again.

    The result should look something like this:

    The scanner should continue moving back and forth for the duration of your program.

    Your task#

    Make the scanner:

    • move horizontally;
    • reverse direction when it reaches an edge;
    • remain completely inside the region of space;
    • occupy the full height of the screen.

    You will need to work out how to represent the scanner’s position, width and direction.

    You already know enough Raylib to do this.

    Do not move on until the scanner works.

    Then:

    1. Review your code.
    2. Refactor anything that is unnecessarily complicated.
    3. Commit your changes.
    4. Push your commit to Git.

    Step 2 — A Particle Field#

    Our detector is now moving through space.

    But there is nothing to detect yet.

    Let’s introduce a particle field.

    For now, imagine that a group of particles occupies a fixed range of space.

    Draw one blue range somewhere in the region.

    For example:

                             blue range
                              |
                              v
              +---------------+
              |               |
              |               |
              |               |
              +---------------+

    The blue range should also occupy the entire height of the screen.

    Use approximately:

    • start: 100
    • width: 50

    The scanner should continue behaving exactly as it did in Step 1.

    It should move back and forth, while the blue range remains stationary.

    Your task#

    Add the blue particle field without breaking the scanner.

    Think carefully about how you represent the particle field.

    It is a range.

    That means you should be able to describe it using its start and end.

    It should not matter that we have chosen these particular values. Your program should work if the particle field is moved somewhere else or given a different width.

    Then:

    1. Look over your code.
    2. Consider whether your new variables are in the right place.
    3. Consider whether anything should be extracted into a function.
    4. Commit your changes.
    5. Push your commit to Git.

    Step 3 — Detect an Overlap#

    Now we have a problem worth solving.

    The detector is moving through the region of space.

    At some point, the detector will encounter the particle field.

    When the detector and the particle field occupy some of the same space, we say that their ranges overlap.

    For example:

    Scanner:

          +----------------+
          |                |
          +----------------+

Particle field:

                    +------------------+
                    |                  |
                    +------------------+

                   <--- overlap --->

    We want the scanner to tell us when this happens.

    When there is no overlap, the scanner should be white.

    When there is an overlap, the scanner should become red.

    There is something important to notice here.

    The scanner is itself a range.

    The particle field is also a range.

    So the question we are asking is:

    Do these two ranges overlap?

    You need to write a function that answers this question.

    It should receive the information needed to describe the two ranges and return whether they overlap.

    Do not make this function specific to the particular values you chose for your particle field.

    It should work for any two ranges.

    For example, it should work if one range is:

    100 to 150

    and another is:

    130 to 180

    But it should also work if you change them to completely different values.

    Both ways#

    There is another important property you should test.

    If range A overlaps range B, then range B also overlaps range A.

    In other words, your overlap test must work both ways.

    Test both of these situations:

    scanner → particle field

    and:

    particle field → scanner

    The answer should be the same.

    Think carefully about the different positions the two ranges can have.

    What happens when:

    • they are completely separate?
    • they just touch?
    • one is partly inside the other?
    • one completely contains the other?
    • they are exactly the same range?

    You do not need to create a complicated test framework for this. Change the values in your program and observe what happens.

    Your task#

    Make the scanner change color:

    • white when the two ranges do not overlap;
    • red when they do overlap.

    Do not hard-code the answer for the particular positions you have chosen.

    Your overlap function should work for arbitrary ranges.

    Then:

    1. Test it with several different positions and widths.
    2. Check the overlap in both directions.
    3. Look at your code and see whether anything can be simplified.
    4. Commit your changes.
    5. Push your commit to Git.

    Step 4 — Another Particle Field#

    Space is rarely so simple.

    Let’s introduce another particle field.

    You should now have two blue ranges.

    For example, you can use approximately:

    First field:
start = 100
width = 50

Second field:
start = 200
width = 5

    The exact values are not important.

    Your program should work with other values too.

    The scanner should behave exactly as it did before.

    It should:

    • move back and forth;
    • turn red when it overlaps either particle field;
    • remain white when it overlaps neither.

    Notice that we now have two possible things for the scanner to detect.

    The scanner is asking:

    Do I overlap the first range or the second range?

    You will need to decide how to organize this in your program.

    Do not simply duplicate large pieces of code.

    Think about the functions you already have.

    Could one function be responsible for determining whether two ranges overlap?

    Could another part of your program use that function to determine whether the scanner has detected something?

    Then:

    1. Test the scanner against both particle fields.
    2. Try different positions and widths.
    3. Refactor anything that has become repetitive.
    4. Commit your changes.
    5. Push your commit to Git.

    Step 5 — Two Particle Detectors#

    Our region of space is getting larger.

    We are now going to use two particle detectors.

    Divide the region into two halves.

    The first detector is responsible for scanning the left half.

    The second detector is responsible for scanning the right half.

    For a 300-pixel-wide region, that means:

                        150
                     |
                     v
+--------------------+--------------------+
|                    |                    |
|     Scanner 1      |      Scanner 2     |
|                    |                    |
|       ← →          |          ← →       |
|                    |                    |
+--------------------+--------------------+
0                   150                  300

    Both scanners should move back and forth.

    The first scanner must remain in the left half.

    The second scanner must remain in the right half.

    Give the two scanners different speeds.

    For example, one might move one pixel per frame while the other moves two pixels per frame.

    Both scanners should otherwise behave in the same way.

    They are both ranges.

    They have the same kind of representation.

    They have the same kind of movement.

    They should also use the same visual language:

    • white when they are not overlapping a particle field;
    • red when they are overlapping a particle field.

    Your task#

    Modify your program so that it contains two scanners.

    Make sure each scanner:

    • has its own position;
    • has its own movement;
    • stays within its own half of the region;
    • moves at a different speed from the other scanner;
    • detects the particle fields using the same overlap logic.

    Try changing the width of the window.

    Try changing the speeds.

    Try changing the particle fields.

    Your program should still behave sensibly.

    There is an important organizational question here:

    Do you need two different functions to move the two scanners?

    The scanners behave in the same way.

    The things that are different are their values.

    Think carefully about what should be shared and what should be different.

    When you have finished:

    1. Test both scanners thoroughly.
    2. Try different speeds.
    3. Try different particle-field positions and widths.
    4. Check that each scanner stays inside its own half.
    5. Refactor your code.
    6. Commit your changes.
    7. Push your commit to Git.

    Code Review#

    You have now built the complete simulation.

    Before you consider the assignment finished, go through your code carefully.

    Do not treat this as optional cleanup.

    Part of programming is being able to look at a program you have just written and improve its organization.

    Use the following checklist.

    Checklist#

    Functions#

    • Do your functions rely on as few global variables as possible?
    • Can any information be passed into a function instead of being taken from a global variable?
    • Can you further extract useful functions out of your code?
    • Does each function have a clear responsibility?
    • Are you updating things in the right function?

    Names#

    • Are your variable names clear?
    • Are your function names clear?
    • If someone read the name without reading the implementation, would they have a reasonable idea what it represents?
    • Are you using the same terminology consistently throughout the program?

    Organization#

    • Where should each variable be?
    • Where should each function be?
    • Are your variable declarations happening in the right place?
    • Are your function declarations happening in the right place?
    • Are things in the right file?
    • Have you accidentally put something in main that belongs somewhere else?
    • Have you accidentally put something in sketch that belongs somewhere else?

    Unnecessary Code#

    • Can you get rid of any unnecessary variables?
    • Can you get rid of any unnecessary functions?
    • Have you accidentally duplicated code?
    • Is there code that was useful while experimenting but is no longer needed?

    Testing#

    • Have you tested your code with a variety of values?
    • Have you changed the positions of the particle fields?
    • Have you changed their widths?
    • Have you changed the scanner widths?
    • Have you changed the scanner speeds?
    • Have you tested ranges that are completely separate?
    • Have you tested ranges that partially overlap?
    • Have you tested one range completely inside another?
    • Have you tested ranges that just touch?

    Refactoring#

    • Can you make the program simpler?
    • Can you make the program easier to understand?
    • Can you further extract functions?
    • Are related things kept together?
    • Have you made updates in the right function?
    • Does your code still make sense if you read it from the beginning?

    Finally, run your program one more time.

    Watch the scanners.

    Watch the particle fields.

    Make sure you understand why the scanner turns red.

    If you can explain why the overlap function gives the answer it does for every situation you have tested, you are done.

    I deliberately left the overlap algorithm completely unspecified. The visual progression should give them enough information to discover the condition themselves, while Step 3 makes the key conceptual point explicit: both things are ranges, and overlap is a relationship between two ranges.
