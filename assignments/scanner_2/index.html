    Extension — Scan in Two Directions#

    Our particle detector has so far been scanning from left to right and back again.

    That means we have been thinking about ranges along the horizontal direction.

    But our region of space has two dimensions.

    Why should we only scan horizontally?

    A particle detector could also scan from top to bottom.

    A New Direction#

    Add another scanner to your simulation.

    This scanner should move vertically.

    It should start at the top of the region, move towards the bottom, and then bounce back towards the top.

    Just like the other scanners, it is a range.

    The difference is that this range now describes a position along the vertical direction rather than the horizontal direction.

    Until now, a range might have looked like this:

           start             end
         |                |
         v                v
         +----------------+
         |                |
         |                |
         |                |
         +----------------+

    The range extends across the entire height of the screen.

    Our new range works the other way around:

             start
           |
           v
         +-------+
         |       |
         |       |
         |       |
         |       |
         +-------+
           ^
           |
          end

    This range extends across the entire width of the screen.

    The important idea has not changed.

    It still has:

    • a start;
    • an end;
    • a width;
    • a position;
    • movement;
    • and the possibility of overlapping another range.

    Only the direction has changed.

    A Horizontal Particle Field#

    We also need something for the new scanner to detect.

    Add a particle field that is represented horizontally.

    The existing particle fields occupy the full height of the screen:

           +-----+
       |     |
       |     |
       |     |
       |     |
       +-----+

    The new particle field should occupy the full width of the screen:

    +-----------------------------+
|                             |
+-----------------------------+

    It therefore represents a range along the vertical axis.

    When the vertical scanner overlaps this particle field, it should turn red.

    When it is not overlapping the field, it should remain white.

    Your Task#

    Extend your program so that you now have:

    • the two scanners that scan horizontally;
    • the horizontal particle fields;
    • a new scanner that scans vertically;
    • a new particle field that is also represented vertically;
    • overlap detection between the new scanner and the new particle field.

    The new scanner should:

    • move from the top towards the bottom;
    • bounce when it reaches the edge;
    • move back towards the top;
    • continue doing this;
    • turn red when it overlaps the particle field;
    • remain white when it does not.

    The existing scanners should continue working exactly as they did before.

    Do not break something that already works while adding something new.

    Think About the Range#

    There is an important question here.

    Your overlap function already knows how to answer a question about two ranges.

    Do you need a completely different idea for vertical ranges?

    Think about what the overlap function actually knows.

    Does it know that a range represents something horizontal?

    Or does it simply receive a start and an end and determine whether two ranges overlap?

    The meaning of the range has changed.

    The underlying idea has not.

    Try to keep that distinction in mind while you work.

    Organize Your Code#

    This extension is also an opportunity to look carefully at the organization of your program.

    You now have different kinds of things:

    • horizontal scanners;
    • a vertical scanner;
    • horizontal particle fields;
    • vertical particle fields;
    • movement;
    • drawing;
    • overlap detection.

    As you add the new behaviour, think about where each piece of code belongs.

    Do not simply keep adding code to update() or draw() because it is convenient.

    Ask yourself:

    What is this piece of code responsible for?

    and:

    Does this belong here, or should it be part of a function?

    You may discover that some of the code you wrote in the earlier steps can now be improved.

    That is expected.

    Good programs often become clearer as you understand the problem better.

    Test It#

    Do not only test the particular values you have been given.

    Change things.

    Try:

    • moving the horizontal particle field;
    • changing its size;
    • changing the vertical scanner’s speed;
    • changing the scanner’s width;
    • making the particle field very small;
    • making the particle field very large;
    • putting the particle field near an edge;
    • putting it in the middle.

    Your program should continue to work.

    The same idea should apply to the existing horizontal scanners too.

    Commit Your Work#

    When the extension is working:

    1. Test it with several different values.
    2. Look through your code carefully.
    3. Refactor anything that needs improving.
    4. Make sure your functions have clear responsibilities.
    5. Check your variable and function names.
    6. Commit your changes.
    7. Push your commit to Git.

    Extension Checklist#

    Before you finish, go through the checklist from the main assignment again.

    • Do your functions rely on as few global variables as possible?
    • Are your variable names clear?
    • Are your function names clear?
    • Where should your variables and functions live?
    • Are your declarations happening in the right place?
    • Are they in the right file?
    • Have you removed unnecessary variables?
    • Have you removed unnecessary functions?
    • Have you tested your code with a variety of values?
    • Can you extract any more useful functions?
    • Have you made updates in the right function?
    • Have you accidentally duplicated code that could be shared?
    • Does the original horizontal scanning behaviour still work?
    • Does the new vertical scanner stay inside the region?
    • Does the vertical scanner correctly detect the horizontal particle field?
    • Does the overlap logic still work for different ranges?
    • Does your code still make sense when you read it from beginning to end?

    Finally, stop and think about what you have built.

    You started with a scanner moving across a screen.

    You then modeled the scanner as a range, modeled objects in space as ranges, and wrote a general rule for determining whether two ranges overlap.

    Now the same idea works in another direction.

    The problem was not really about horizontal strips or vertical strips.

    It was about ranges and relationships between ranges.
