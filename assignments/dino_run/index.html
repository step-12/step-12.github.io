      The Long Run#

      A dinosaur is running through an empty world.

      It cannot stop. Cacti and birds appear in its path. It must jump over one and duck under the other.

      We will build the game a little at a time. Each assignment adds something to the game you made in the previous one.

      Do not jump into the code immediately. Read the assignment first and understand what the game should do.

      For each part, pause before you begin. Think about the behaviour you need, make a plan, discuss your approaches with one of the mentors and then implement it. Run the game, observe the result, and make sure that part works before moving to the next one.

      Commit your code after every working part. Publish those commits regularly as well, a local commit cannot protect your work if the repository is accidentally damaged or deleted.

      Do not try to make the finished game immediately. A rectangle that moves correctly is more useful than a beautiful dinosaur that does not.

      The project#

      You will be given a repository containing this structure:

      dino-run/
├── main.js
├── sketch.js
├── geometry.js
├── dino.js
├── obstacle.js
├── ground.js
└── assets/

      The structure is already in place when you begin.

      1. Before the Run#

      Every game begins with a world.

      Use a wide window with a 4:1 aspect ratio. This means the width is four times the height.

      For example, you may use:

      • 640 × 160 pixels;
      • 800 × 200 pixels; or
      • 1024 × 256 pixels.

      800 × 200 is a good starting size. It provides enough horizontal space for several obstacles while keeping the short, wide appearance of the original game.

      Draw a ground across the bottom of the window. Place a rectangle near the left side of the screen to represent the dinosaur. Place another rectangle farther to the right to represent an obstacle.

      Use dimensions based on a 16-pixel grid. Prefer multiples of 16, such as 16, 32, and 48. For smaller measurements, divide 16 evenly—for example, 16 / 2 = 8 or 16 / 4 = 4. This will make it easier to replace the rectangles with the supplied artwork later.

      For example, the dinosaur could be 32 × 48 pixels, a cactus could be 16 × 32 pixels, and a bird could be 32 × 16 pixels. Using related measurements helps the objects look as though they belong to the same visual scale. These are examples, not required sizes.

      The dinosaur and obstacle should stand on the ground. They should not float above it or disappear inside it.

      The ground position, dino position, and obstacle positions should be configurable.

      Choose dimensions that suit your scene. The starter repository already gives the dinosaur, obstacles, and main sketch their own files. Use that structure from the beginning.

      2. The Road Ahead#

      One obstacle does not make much of a journey.

      Create several obstacles. Give them different horizontal positions and draw all of them.

      Give at least two obstacles different heights or widths. No matter their size, all of them should remain on the ground.

      Try changing the number of obstacles. Does the same drawing logic continue to work?

      3. Jumping Japang#

      The dinosaur has only one way to survive: it must leave the ground.

      When Space is pressed, make the dinosaur rise and then return to the ground.

      Begin with a simple jump. The dinosaur should rise, reach a highest point, and return to the ground.

      Watch the jump carefully. The dinosaur moves upward at a fixed speed, suddenly changes direction, and then moves downward at a fixed speed.

      The jump works, but it does not look natural. We will improve it in the next part.

      4. What Goes Up#

      We can describe the jump differently.

      Replace the basic jump with one that uses vertical velocity and gravity.

      Give the dinosaur a vertical velocity. It should begin by carrying the dinosaur upward. Gravity should gradually slow the rise and then pull the dinosaur back down.

      The dinosaur should jump only when Space is newly pressed and it is already on the ground. Holding Space must not make it fly, and pressing Space in the air must not create a second jump.

      Try different jump velocities and gravity values. Notice how each value changes the height, duration, and shape of the jump.

      5. The Journey Begins#

      Until now, the dinosaur and obstacles have remained in place. Now start the movement.

      Make the scene look as though the dinosaur is continually travelling forward. Obstacles ahead of it should come closer, pass it, and eventually leave the screen.

      Jumping should continue to work while the journey is in progress.

      Points to keep in mind:

      • The gaps between the obstacles should remain consistent as they travel.
      • Do not add new obstacles yet.
      • Use dt for Obstacle movement.
      • Do not add collision check. This part involves movement of obstacles to left.
      • Velocity of obstacles should be configurable.

      6. A Sudden Stop#

      Sooner or later, the dinosaur will fail to clear an obstacle.

      Both the dinosaur and the obstacles are rectangles. Write a function with this contract:

      checkCollisionRecs(rec1, rec2);

      rec1 and rec2 are rectangles. The function should return true when they collide and false when they do not.

      Check the dinosaur against every obstacle. When a collision occurs, stop the game and display GAME OVER.

      The game should remain visible after the collision. Do not immediately close the window.

      Stop updating the dinosaur, obstacles, and other gameplay values after game over. Continue drawing the final state so the player can see what happened.

      Test collisions from the left, right, top, and corners.

      7. The Road Never Ends#

      An endless runner needs an endless supply of obstacles.

      Part A: An Endless Road#

      The dinosaur should keep encountering obstacles no matter how long the game runs. After one group has passed, more obstacles should arrive from the right without leaving the road empty.

      Build this in stages. Complete and test one step before moving to the next:

      For now, keep the obstacle dimensions and the gap between obstacles fixed.

      1. Start with one obstacle and make it move from right to left.
      2. Let the obstacle move until it has completely left the screen.
      3. Obstacle should disappear only after its right edge has passed the left edge of the screen.
      4. New obstacles should start appearing from the right edge of the screen.
      5. Make sure the new obstacle enters naturally and does not suddenly appear in the middle of the screen.
      6. Repeat the process whenever an obstacle leaves so that the dinosaur always has more obstacles ahead.
      7. Run the game for several minutes and confirm that obstacles continue entering and leaving correctly.

      Let the game run for several minutes and check that:

      • New obstacles enter from the right side of the screen
      • Old obstacles leave completely through the left side

      Part B: Break the pattern#

      Regular spacing makes the next obstacle too easy to predict. Vary the gap before each new obstacle. Vary the width and height of the obstacles as well.

      The spacing changes how difficult the next part of the run feels. Obstacles that appear close together create a harder sequence. A larger gap gives the player time to recover.

      Use this to give the game a changing rhythm. The order does not need to follow a predictable pattern.

      Think carefully about the limits:

      • If the minimum gap between obstacles is too small, some combinations may be impossible to jump.
      • If the maximum gap between obstacles is too large, the game may feel empty.
      • If you remove an obstacle too early, the player may see it disappear.

      Let the game run through several complete cycles. There should always be another obstacle ahead, but the journey should not feel the same every time.
