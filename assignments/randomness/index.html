      Randomness#

      We have spent some time telling the computer exactly what to do.

      We give it a number. We give it another number. We ask it to draw a rectangle at a particular position. We calculate something and then draw the result.

      But what happens when we don’t tell the computer exactly what to do?

      What if we give it a little freedom?

      We can ask the computer to make a choice for us.

      That is what randomness gives us.

      In this study, we are going to use randomness to explore a few ideas about numbers, geometry, probability, and simulation.

      This is not a compulsory set of exercises. You don’t have to complete all of them. If you find the ideas interesting, however, there is quite a lot to discover.

      We will use Raylib to make everything visible. It is much easier to reason about randomness when we can see thousands of random points appear on the screen.

      A random number#

      Let’s begin with a very simple question.

      How can we ask the computer for a random number between 0 and 1?

      JavaScript gives us Math.random().

      Try it in the REPL.

      Math.random();

      Run it a few times.

      You should see different numbers each time.

      They will be somewhere between 0 and 1.

      But what does that actually mean?

      Are all numbers between 0 and 1 equally likely?

      Can we ever get exactly 0?

      Can we ever get exactly 1?

      What happens if we generate a thousand of these numbers?

      Let’s make a small Raylib program that generates a random number and uses it as an x coordinate.

      Run the program several times.

      The point moves.

      That’s our first encounter with randomness: we have given up control over the exact value, but we still know something about the value.

      It is somewhere in a particular range.

      Think about it#

      • What does Math.random() actually promise us?
      • Why might a computer-generated random number not be truly random?
      • If we generated 100 points, where would you expect them to appear?
      • Would you expect some part of the range to remain completely empty?

      Don’t worry about answering all of these immediately. Keep them in mind as we continue.

      A random number between 0 and x#

      Suppose we have a number x.

      We want a random number between 0 and x.

      For example, if x is 500, we want something between 0 and 500.

      We already know how to generate a number between 0 and 1.

      Can we use that to solve this problem?

      Try to find the relationship.

      random number between 0 and 1
                ↓
       __________________
       random number between 0 and x

      Test your idea with different values of x.

      Then visualize the result.

      There is a useful idea hiding here.

      We did not learn a completely new way to generate a random number.

      We took something we already had and transformed it.

      Think about it#

      Suppose our random number is 0.25.

      What happens when we use x = 100?

      What happens when we use x = 400?

      What happens when x gets larger?

      What operation are we performing on the random number?

      A random number between x₁ and x₂#

      Now let’s make the question slightly harder.

      We don’t want a number between 0 and x.

      We want a number between two arbitrary numbers:

      x₁                         x₂
|--------------------------|

      For example:

      20                         80
|--------------------------|

      How can we turn our random number between 0 and 1 into a number between 20 and 80?

      Try it.

      Then try:

      -50                       100
|-------------------------|

      And:

      200                       250
|-------------------------|

      Visualize the numbers on a line.

      Notice that we are beginning to build a small collection of techniques.

      We can start with a random number in a known range and transform it into another range.

      Think about it#

      What are the two things that have happened to our original range?

      We started with:

      0 -------------------- 1

      and ended with:

      x₁ ------------------- x₂

      What changed?

      Can you describe the transformation without looking at your code?

      A random point in a rectangle#

      A point on a line is not very exciting.

      Let’s move into two dimensions.

      Suppose we have a rectangle whose top-left corner is (0, 0) and whose width and height are x and y.

      (0,0)
  +-------------------+
  |                   |
  |                   |
  |                   |
  |                   |
  +-------------------+
                      (x,y)

      We want to generate a random point somewhere inside it.

      We already know how to generate a random number between 0 and x.

      And we know how to generate one between 0 and y.

      Can we use those two ideas together?

      Try it.

      Draw a point.

      Then draw 100 points.

      Then 1,000.

      The picture should start to look fairly uniform.

      But notice what we did.

      We generated an x coordinate and a y coordinate separately.

      The two choices don’t depend on one another.

      Think about it#

      If we generated:

      const x = ...
const y = ...

      why is it possible for every combination of x and y to occur?

      What would happen if the value of y depended on x?

      Would the resulting points still fill the rectangle?

      A random point in any rectangle#

      So far our rectangle has been anchored at (0, 0).

      That is convenient, but rectangles don’t have to live there.

      Suppose our rectangle has corners:

      (x₁, y₁) ------------------ (x₂, y₁)
       |                    |
       |                    |
       |                    |
       |                    |
(x₁, y₂) ------------------ (x₂, y₂)

      Can we generate a random point inside it?

      You already have everything you need.

      Think about the problem as two separate problems:

      Generate a random x.

      and:

      Generate a random y.

      Then put the two results together.

      Try different rectangles.

      Try rectangles that are very wide.

      Try rectangles that are very tall.

      Try rectangles whose coordinates are negative.

      Think about it#

      What does moving the rectangle do to the random points?

      What does changing its width do?

      What does changing its height do?

      Are we generating a fundamentally different kind of random point than before, or are we transforming the same idea?

      A random point inside a circle#

      Now things get interesting.

      Suppose we have a circle centered at (0, 0).

                   *
         *       *
       *           *
      *      +      *
       *           *
         *       *
             *

      We want a random point inside the circle.

      We know how to generate random points inside a rectangle.

      So one possibility is to generate a point in the rectangle containing the circle.

      But then we have a problem.

      Some of our points will be outside the circle.

      Could we simply check whether a point is inside the circle?

      Yes.

      But there is another way to think about this.

      Instead of describing a point by its x and y coordinates, can we describe it differently?

      Imagine drawing a line from the centre of the circle to a point.

      There are two useful quantities:

      • How far away is the point?
      • In which direction is it?

      We can describe the point using a distance and an angle.

      This is a different coordinate system.

      It is called polar coordinates.

      Instead of:

      (x, y)

      we can think of a point as:

      (distance, angle)

      Can you use this idea to generate a random point inside the circle?

      There is a subtle question here.

      If we choose the distance and angle randomly, will the points actually be distributed uniformly throughout the circle?

      Try it.

      Don’t assume the answer.

      Generate a lot of points and look at the picture.

      Think about it#

      Why might some distances produce more area than others?

      If you choose a random distance, are you choosing a random point, or are you choosing a random radius?

      What would you have to do to make the points spread evenly across the whole circle?

      This is a good problem to spend some time with.

      A random point inside a translated circle#

      Our circle was centered at (0, 0).

      What if its centre is somewhere else?

      Suppose the centre is (cx, cy).

                          *
                *       *
              *           *
             *      +      *
              *           *
                *       *
                    *
                 (cx, cy)

      Can you use everything you have already learned to generate random points inside this circle?

      Notice that we don’t necessarily need to invent a new technique.

      We can first solve the problem for a circle centred at (0, 0).

      Then we can think about how to move the resulting point.

      Think about it#

      What changes when we move the centre of the circle?

      What stays the same?

      Can you separate the problem into:

      1. generating a point relative to the centre, and
      2. positioning that point in the world?

      This idea will become useful again.

      A random point inside a parallelogram#

      Let’s make the shape a little stranger.

      A rectangle has sides that are horizontal and vertical.

      A parallelogram doesn’t have to be.

      Suppose we know one corner of a parallelogram and the two vectors that describe its sides.

              +----------------+
       /                /
      /                /
     /                /
    +----------------+

      We want a random point inside it.

      We already know how to generate two random numbers between 0 and 1.

      Can those two numbers tell us how far to travel along each of the two sides?

      Try to construct the point.

      Don’t worry about finding the “right formula” immediately.

      Draw it.

      Experiment with it.

      Think about what happens when one random number changes while the other stays fixed.

      Think about it#

      If one random number controls movement along one side, what does the other control?

      What happens when the first number is 0?

      What happens when it is 1?

      What happens when both numbers are 0.5?

      Can you describe every point in the parallelogram using just two numbers between 0 and 1?

      Not all randomness looks the same#

      So far, we have mostly been trying to make points spread evenly.

      But randomness does not necessarily mean that every outcome is equally likely.

      Consider rolling a die.

      Each face has the same probability.

      Now imagine a different experiment where some results are much more likely than others.

      Can we make our computer do that?

      Let’s generate a large number of random values and draw them as points.

      First, use the random numbers we have already been using.

      Now change the way the random values are generated.

      For example, generate two random numbers and add them together.

      What does the resulting distribution look like?

      Try adding three random numbers.

      Try taking their average.

      Try other combinations.

      Don’t worry about naming the distribution yet.

      Just look at what happens.

      Think about it#

      Why do some values occur more frequently than others?

      If every call to Math.random() is uniform, how did we produce something that isn’t uniform?

      Can we create a distribution with a particular shape?

      Can you make a distribution that has a strong peak in the middle?

      Can you make one that is concentrated toward one end?

      A more interesting distribution#

      Let’s go further.

      Suppose we want our points to follow a particular probability distribution.

      Rather than every point being equally likely, we want some regions to be more likely than others.

      The computer doesn’t have to give us that distribution directly.

      We can transform simpler random values into the distribution we want.

      Try to construct one.

      Start with a simple uniform random number.

      Then experiment with mathematical functions.

      For example:

      x
│
│       *
│      * *
│     *   *
│   **     **
│***         ***
└────────────────

      Can you create a distribution that looks roughly like this?

      Once you have one, draw thousands of samples and inspect the result.

      The important thing here isn’t whether your distribution exactly matches some mathematical ideal.

      The important question is:

      How can we transform randomness?

      We began with a simple source of random values.

      By applying operations to those values, we can create very different patterns.

      Think about it#

      What does it mean to say that a value is “more likely” than another?

      Can you tell from one random sample whether a distribution has a particular shape?

      How many samples do you need before you start seeing the shape?

      What happens as you increase the number of samples?

      Estimating with randomness#

      We have been generating random points and observing the resulting patterns.

      Now let’s turn the process around.

      Can randomness help us calculate something?

      Consider a circle inside a square.

      +---------------------+
|                     |
|       *****         |
|     **     **       |
|    *         *      |
|    *         *      |
|     **     **       |
|       *****         |
|                     |
+---------------------+

      We know the area of the square.

      We know the radius of the circle.

      But let’s pretend that we don’t know the formula for the area of a circle.

      Can we estimate it?

      Generate a large number of random points inside the square.

      For every point, ask:

      Is this point inside the circle?

      Keep count of the two groups.

      total points
points inside circle

      What relationship do you notice?

      Try 100 points.

      Then 1,000.

      Then 10,000.

      Then 100,000.

      Use your results to estimate the area of the circle.

      How close did you get?

      Run the experiment again.

      Did you get exactly the same answer?

      Why not?

      Think about it#

      Why does the estimate become better as we use more points?

      Does using twice as many points make the answer twice as accurate?

      What happens if the points are not uniformly distributed?

      Could you use the same idea to estimate the area of some shape for which you don’t know a convenient formula?

      What other quantities could we estimate using random sampling?

      This is the basic idea behind Monte Carlo methods: use repeated random experiments to estimate something that may be difficult to calculate directly.

      The chaos game#

      We will finish with something that looks almost impossible.

      Take a triangle.

      Choose one of its three corners.

      Start with a point somewhere inside the triangle.

      Now repeat this:

      1. Randomly choose one of the three corners.
      2. Move the point halfway toward that corner.
      3. Draw the new point.
      4. Repeat.

      That’s it.

      There is no complicated formula.

      There is no complicated geometry.

      There is just a random choice and a very simple movement.

      Try it with a few points.

      Now let it run.

      Keep going.

      A pattern appears.

      A very precise pattern.

      It is called the Sierpiński triangle.

      And yet, we never explicitly told the computer to draw a Sierpiński triangle.

      We only gave it a few simple rules.

      Think about it#

      Why do some regions of the triangle remain empty?

      Why do the same shapes keep appearing at smaller scales?

      Would you get the same pattern if the corner were chosen in a completely predictable sequence?

      What is the role of randomness here?

      Does randomness always produce noise?

      Or can a simple random process produce structure?

      What did we learn?#

      Each exercise started with a small question and added one more idea.

      4. Random point in a rectangleGenerating independent coordinates
      5. Random point in an arbitrary rectangleTransforming random coordinates into a different region
      6. Random point in a circleDescribing points using distance and angle; discovering polar coordinates
      7. Random point in a translated circleSeparating a shape’s local coordinates from its position
      8. Random point in a parallelogramCombining independent quantities to construct geometry
