    Recur and Tear#

    A small collection of exercises for getting comfortable with recursive functions, base cases, reducing problems to smaller problems, and the occasional mathematical ambush.

    1. Even Steven#

    Write a recursive function that adds all the even numbers between 0 and x.

    If x is even, include x in the result.

    For example:

    f(3) = 2
f(4) = 6
f(5) = 6
f(10) = 30

    Your function should work for any non-negative integer x.

    2. Odd One Out#

    Write a recursive function that adds all the odd numbers between 0 and x.

    For example:

    f(1) = 1
f(2) = 1
f(3) = 4
f(5) = 9
f(7) = 16
f(9) = 25

    As before, the function should work for any non-negative integer x.

    The trick is not to calculate the entire sum from scratch every time.

    3. A String of Events#

    Now let’s leave numbers behind.

    All arguments to f,g,h, and cat are words. A word is a sequence of zero or more letters.

    Consider:

    f(x)
  = "" when x is ""
  = first letter of x

    So:

    f("hello") = "h"
f("ab")    = "a"
f("")      = ""

    We also have:

    g(x)
  = "" when x is ""
  = all but the first letter of x

    So:

    g("hello") = "ello"
g("ab")    = "b"
g("")      = ""

    And finally:

    cat(x,y) = join x and y

    For example:

    cat("he","llo") = "hello"
cat("","a")     = "a"

    Now consider:

    h(x)
  = "" when x is ""
  = cat(h(g(x)),f(x))

    Evaluate:

    h("hello")

    Be careful.

    There is recursion here, but there is also a small change happening to the argument each time.

    4. A Little Left Over#

    Division can be thought of as repeatedly taking away the divisor.

    For example, when calculating:

    10 ÷ 3

    we can take away 3 three times:

    10 → 7 → 4 → 1

    There is nothing more to take away.

    The number left over is 1.

    Write a recursive function that calculates the remainder of a division.

    For example:

    modulo(10,3) = 1
modulo(5,3)  = 2

    Your function should work for positive integers.

    The Recursive Recipe#

    For each of the functions above, you should be able to answer three questions:

    1. What is the base case?
    2. How does the problem get smaller?
    3. How does the answer to the smaller problem help produce the answer to the original problem?

    If you cannot answer all three, your function probably isn’t recursive yet.

    It is merely thinking about being recursive.

    And thinking about recursion is not recursion.

    Shun the loops. Embrace the smaller problem.
