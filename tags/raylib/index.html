      Extension — Scan in Two Directions#

      Our particle detector has so far been scanning from left to right and back again.

      That means we have been thinking about ranges along the horizontal direction.

      But our region of space has two dimensions.

      Why should we only scan horizontally?

      A particle detector could also scan from top to bottom.

      Add another scanner to your simulation.

      This scanner should move vertically.

      Scanning for Particles#

      Imagine that we have sent a particle detector into space.

      The detector is looking at a small region of space around it. It moves from one side of the region to the other, scanning for particles as it goes.

      Our job is to build a simulation of this detector.

      Modules and a Raylib Template#

      So far, each Raylib program you have written has lived in a single file.

      We have already started organizing that file into functions:

      function setup() {}

function update() {}

function draw() {}

function loop() {
  while (!r.WindowShouldClose()) {
    update();
    draw();
  }
}

function main() {
  setup();
  loop();
}

main();

      This gives different parts of the program different responsibilities.

      But there is another kind of organization available to us.

      We can separate our program into different files.

      Skeleton

      September 24, 2026
      Raylib, Organization

      Organizing a Raylib Program#

      You have now written a few small Raylib programs.

      You have probably noticed that even a small program starts to contain several different kinds of code:

      • code that prepares the window
      • code that changes things
      • code that draws things
      • code that keeps the program running

      It is useful to give these different responsibilities a little structure.

      We are going to use the following skeleton:

      function setup() {}

function update() {}

function draw() {}

function loop() {
  update();
  draw();
}

function main() {
  setup();
  loop();
}

main();

      This is not a rule imposed by Raylib.

      First Exercises#

      You now have a working Raylib program.

      You have seen how a Raylib program is structured, and you have used functions such as r.DrawRectangle.

      Now it is time to start solving some small problems.

      For these exercises, create a directory called:

      workspace/raylib_exercises/

      Each exercise should be its own program.

      Use these filenames:

      01_center_rectangle.js
02_center_rectangle_in_rectangle.js
03_scale_and_center.js
04_closer_target.js

      Write the Raylib program yourself for each exercise. You should not need to copy the program from the previous post.

      Raylib anatomy

      September 23, 2026
      Raylib, Graphics

      The anatomy of a Raylib program#

      In the previous post, we saw that Raylib is a library that gives our JavaScript programs a collection of functions for working with graphics.

      We are now going to look at a complete Raylib program.

      Don’t worry if you don’t understand everything in it yet.

      In fact, you shouldn’t.

      Read through it once and see if you can recognize anything.

      const r = require("raylib");

r.InitWindow(800, 400, "Raylib");
r.SetTargetFPS(60);

while (!r.WindowShouldClose()) {
  r.BeginDrawing();
  r.ClearBackground(r.BLACK);

  r.DrawRectangle(100, 50, 600, 300, r.WHITE);

  r.EndDrawing();
}

r.CloseWindow();

      There are quite a few things happening here.

      Raylib#

      So far, most of the programs you have written have produced things like numbers and text.

      You might have written:

      console.log(2 + 3);

      and seen:

      5

      Or perhaps you wrote a function that takes some values, performs a computation, and returns another value.

      What if the result of our program could be something that we could see?

      What if instead of producing:

      5

      our program could produce a rectangle on the screen?

      That is where we are going next.
