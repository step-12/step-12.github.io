    More Functions in Math

    August 28, 2026
    Math, Functions

    Functions — Beyond the Basics#

    From mathematical functions to programming functions#

    1. Where We Are#

    We already know that a function:

    • Takes some input
    • Applies a rule
    • Produces an output
    • Has a domain and a range

    For example:

    f(x) = 2x + 3

    If we give it 5:

    f(5) = 2(5) + 3
     = 13

    So far, we have mostly treated functions as rules for transforming values.

    Now we will ask:

    What else can we do with functions?

    2. Functions Can Be Combined#

    Suppose we have two functions:

    f(x) = 2x
g(x) = x + 3

    We can apply one function after another.

    First g, then f:

    f(g(x))

    Substitute:

    f(g(x)) = f(x + 3)
         = 2(x + 3)
         = 2x + 6

    This is called function composition.

    3. Function Composition#

    Composition can be written as:

    (f ∘ g)(x) = f(g(x))

    Read this as:

    “f composed with g”

    The important idea is the order:

    x → g → f → result

    For example:

    g(x) = x + 3
f(x) = 2x

(f ∘ g)(x) = f(g(x))
            = 2(x + 3)
            = 2x + 6

    4. Composition Is Not Usually Commutative#

    With ordinary multiplication:

    2 × 3 = 3 × 2

    But function composition generally does not work this way.

    Consider:

    f(x) = 2x
g(x) = x + 3

    Then:

    (f ∘ g)(x) = f(g(x))
            = 2x + 6

    But:

    (g ∘ f)(x) = g(f(x))
            = 2x + 3

    Therefore:

    f ∘ g ≠ g ∘ f

    The order in which functions are applied matters.

    5. Composition as a Pipeline#

    We can think of composition as a pipeline.

    x
↓
g
↓
g(x)
↓
f
↓
f(g(x))

    For example:

    x = 5

g(x) = x + 3
f(x) = 2x

    The pipeline is:

    5 → 8 → 16

    This idea becomes extremely important in programming.

    A program can be thought of as a collection of transformations:

    input → transformation → transformation → transformation → output

    6. The Identity Function#

    There is a special function that does nothing to its input.

    I(x) = x

    This is called the identity function.

    For any function f:

    f(I(x)) = f(x)

    and:

    I(f(x)) = f(x)

    Therefore:

    f ∘ I = I ∘ f = f

    The identity function is analogous to the number 0 for addition or 1 for multiplication: it leaves something unchanged.

    7. Inverse Functions#

    What if a function transforms a value and we want to reverse the transformation?

    Consider:

    f(x) = x + 5

    If:

    f(3) = 8

    we can reverse the operation by subtracting 5.

    Define:

    f⁻¹(x) = x - 5

    Then:

    f⁻¹(8) = 3

    So:

    3 → f → 8 → f⁻¹ → 3

    An inverse function undoes what the original function does.

    8. Inverses and Composition#

    If f⁻¹ is truly the inverse of f, composing them should give us the identity function.

    f⁻¹(f(x)) = x

    and:

    f(f⁻¹(x)) = x

    For example:

    f(x) = 2x + 3
f⁻¹(x) = (x - 3) / 2

    Check:

    f⁻¹(f(x))
= f⁻¹(2x + 3)
= ((2x + 3) - 3) / 2
= x

    This connects three ideas:

    function
    ↓
inverse
    ↓
composition
    ↓
identity

    9. Not Every Function Has an Inverse#

    Consider:

    f(x) = x²

    We have:

    f(2) = 4
f(-2) = 4

    Two different inputs produce the same output.

    If we are given 4, we don’t know whether the original input was:

    2

    or:

    -2

    Therefore, there is no unique inverse function over all real numbers.

    This leads us to an important property of functions.

    10. One-to-One Functions#

    A function is one-to-one if different inputs always produce different outputs.

    For example:

    f(x) = 2x + 1

    Some values:

    f(1) = 3
f(2) = 5
f(3) = 7
f(4) = 9

    No two inputs give the same output.

    A one-to-one function is also called injective.

    Informally:

    One input → one unique output and no two inputs share an output.

    11. Injective, Surjective, Bijective#

    Consider a function:

    f : A → B

    There are three useful properties.

    Injective#

    Different inputs have different outputs.

    a₁ ≠ a₂  ⇒  f(a₁) ≠ f(a₂)

    Surjective#

    Every element of B is reached by at least one element of A.

    Bijective#

    A function is both injective and surjective.

    A bijective function gives a perfect one-to-one correspondence between the two sets.

    12. Why Bijections Matter#

    Consider:

    A = {1, 2, 3}
B = {a, b, c}

    A bijection could be:

    1 → a
2 → b
3 → c

    Every element in A maps to exactly one element in B.

    And every element in B is reached.

    Because the mapping is one-to-one and onto, it can be reversed:

    a → 1
b → 2
c → 3

    The inverse exists because there is no ambiguity.

    13. Piecewise Functions#

    A function does not have to use the same rule everywhere.

    For example:

    f(x) =
    x²       if x ≥ 0
    -x       if x < 0

    Different parts of the domain use different rules.

    Evaluate:

    f(3) = 3² = 9

    But:

    f(-3) = -(-3) = 3

    This is a piecewise-defined function.

    14. Piecewise Functions and Absolute Value#

    A familiar example is the absolute value function.

    |x| =
    x       if x ≥ 0
    -x      if x < 0

    So:

    |5| = 5
|-5| = 5

    Piecewise functions are useful because they show that:

    A function is defined by its mapping, not necessarily by one simple formula.

    15. Piecewise Functions in Programming#

    A piecewise function is very close to conditional logic.

    Mathematically:

    f(x) =
    x²       if x ≥ 0
    -x       if x < 0

    Conceptually:

    if x >= 0:
    return x²
else:
    return -x

    The programming language is simply giving us another way to express the same mathematical idea.

    16. Functions Can Be Treated as Objects#

    So far, our functions have taken values as inputs.

    For example:

    f(x) = x²

    But what if the input itself is a function?

    Consider:

    F(f, x) = f(x) + 1

    Now f is itself an input.

    If:

    f(x) = x²

    then:

    F(f, 3)
= f(3) + 1
= 9 + 1
= 10

    The function F has received another function as an argument.

    17. Functions Can Produce Functions#

    A function can also return another function.

    Consider:

    F(a) = a function that adds a

    More formally:

    F(a)(x) = x + a

    For example:

    F(5)(x) = x + 5

    So:

    F(5)(3) = 8

    The first application gives us a new function:

    F(5)

    The second application gives us a value:

    F(5)(3)

    18. Higher-Order Functions#

    A higher-order function is a function that:

    • takes one or more functions as arguments, or
    • returns a function.

    For example:

    H(f, x) = f(x)²

    If:

    f(x) = x + 1

    then:

    H(f, 3)
= f(3)²
= 4²
= 16

    Here, H receives a function as an input.

    19. A Function That Modifies Functions#

    Consider:

    f(x) = x²

    We could define:

    addOne(f)(x) = f(x) + 1

    Then:

    addOne(f)(3)
= f(3) + 1
= 9 + 1
= 10

    But notice what happened.

    We started with:

    f(x) = x²

    and created a new function:

    g(x) = x² + 1

    So a function can transform another function into a new function.

    20. Functions Are Values#

    This gives us a powerful general principle:

    Functions can be treated like values.

    A value can be:

    stored
passed around
given as an argument
returned from another operation

    And so can a function.

    For example:

    number → value
string → value
function → value

    This is one of the conceptual foundations of functional programming.

    21. Anonymous Functions#

    Sometimes we need a function only temporarily.

    Instead of naming it:

    f(x) = x²

    we can simply describe the function itself:

    x ↦ x²

    This is an anonymous function: a function without a permanent name.

    For example, suppose we want to apply:

    x ↦ x²

    to:

    5

    The result is:

    5² = 25

    Programming languages often provide special syntax for these unnamed functions.

    22. Functions Over Different Kinds of Values#

    Mathematical functions don’t have to map numbers to numbers.

    For example:

    length : Strings → Natural Numbers

    A possible mapping is:

    length("hello") = 5
length("cat") = 3
length("functions") = 9

    Or:

    uppercase : Strings → Strings

    For example:

    uppercase("hello") = "HELLO"

    The idea of a function is much more general than:

    number → number

    23. Functions Over Collections#

    We can also have functions that operate on collections.

    For example:

    sum : Lists of Numbers → Numbers

    Then:

    sum([1, 2, 3, 4]) = 10

    Or:

    length([10, 20, 30]) = 3

    Or a function that transforms every element:

    square([1, 2, 3, 4])
= [1, 4, 9, 16]

    This is where mathematical functions begin to look very much like programming functions.

    24. Mapping#

    Suppose:

    f(x) = x²

    We can apply f to every element of a collection:

    [1, 2, 3, 4]

    giving:

    [1², 2², 3², 4²]

    which becomes:

    [1, 4, 9, 16]

    This operation is commonly called map.

    Conceptually:

    map(f, [x₁, x₂, ..., xₙ])
=
[f(x₁), f(x₂), ..., f(xₙ)]

    The important part is that map receives a function as input.

    25. Filtering#

    Another useful operation is filtering.

    Suppose:

    p(x) = "x is even"

    Given:

    [1, 2, 3, 4, 5, 6]

    we can keep only the values for which p is true:

    [2, 4, 6]

    Conceptually:

    filter(p, [1, 2, 3, 4, 5, 6])
=
[2, 4, 6]

    Again, the operation receives a function.

    This is another example of a higher-order function.

    26. Currying#

    Consider a function with two parameters:

    f(x, y) = x + y

    Normally we provide both values at once:

    f(2, 3) = 5

    Currying changes the way we think about this function.

    Instead of:

    f(x, y)

    we can think of it as:

    f(x)(y)

    The first function receives x and returns another function waiting for y.

    27. Currying Step by Step#

    Consider:

    add(x, y) = x + y

    A curried version can be thought of as:

    add(x)(y) = x + y

    Now:

    add(5)

    doesn’t produce a number.

    It produces a new function:

    g(y) = 5 + y

    Then:

    g(3) = 8

    Therefore:

    add(5)(3) = 8

    Currying makes functions that return functions especially explicit.

    28. Partial Application#

    Currying naturally leads to partial application.

    Start with:

    multiply(x, y) = x × y

    Fix the first argument:

    multiplyBy10(y) = 10 × y

    Now we have created a specialized function.

    For example:

    multiplyBy10(3) = 30
multiplyBy10(7) = 70

    We started with a general function:

    multiply(x, y)

    and created a more specific function:

    multiplyBy10(y)

    29. Recursion#

    A function can call itself.

    This is called recursion.

    Consider factorial:

    n! = n × (n - 1)!

    For example:

    5! = 5 × 4!
   = 5 × 4 × 3!
   = 5 × 4 × 3 × 2!
   = 5 × 4 × 3 × 2 × 1!

    Eventually we need a stopping point.

    0! = 1

    This is called the base case.

    30. The Structure of a Recursive Function#

    A recursive definition generally has two parts:

    Base case#

    The condition where recursion stops.

    f(0) = some known value

    Recursive case#

    The function defines itself in terms of a smaller version of the same problem.

    f(n) = some expression involving f(n - 1)

    For factorial:

    factorial(0) = 1

factorial(n) = n × factorial(n - 1)

    Without the base case, the function would never stop.

    31. Tracing Recursion#

    Consider:

    factorial(4)

    The recursive expansion is:

    factorial(4)
= 4 × factorial(3)
= 4 × 3 × factorial(2)
= 4 × 3 × 2 × factorial(1)
= 4 × 3 × 2 × 1 × factorial(0)
= 4 × 3 × 2 × 1 × 1
= 24

    Notice that recursion doesn’t mean:

    “Do something infinitely.”

    It means:

    “Reduce the problem until we reach a case we already know how to solve.”

    32. Recursion on Sequences#

    Functions over integers are particularly useful for recursion.

    Consider:

    a(0) = 1
a(n) = 2a(n - 1)

    Then:

    a(0) = 1
a(1) = 2
a(2) = 4
a(3) = 8
a(4) = 16

    This is a recurrence relation.

    A recurrence defines a value in terms of previous values.

    33. Fibonacci#

    The Fibonacci sequence is another famous recursive definition.

    F(0) = 0
F(1) = 1

F(n) = F(n - 1) + F(n - 2)

    Therefore:

    F(0) = 0
F(1) = 1
F(2) = 1
F(3) = 2
F(4) = 3
F(5) = 5
F(6) = 8

    The mathematical definition is already extremely close to a recursive program.

    34. Functions as Transformations#

    There is another useful way to think about a function.

    Instead of thinking:

    “A function is an equation.”

    Think:

    “A function is a transformation between sets.”

    For example:

    f : A → B

    means:

    f maps elements from set A to elements of set B.

    For example:

    f : Integers → Integers
f(x) = x + 1

    The function transforms:

    ... -2, -1, 0, 1, 2, ...

    into:

    ... -1,  0, 1, 2, 3, ...

    35. Functions Are More General Than Equations#

    Consider:

    f(x) = x²

    This is a convenient way of describing a function.

    But a function can also be represented as:

    A table#

    x    f(x)
1     1
2     4
3     9
4    16

    A graph#

    Each input corresponds to exactly one output.

    A rule#

    Square the input.

    A mapping#

    1 → 1
2 → 4
3 → 9
4 → 16

    The function is the underlying relationship, not the particular representation.

    36. Function Transformations#

    Starting with:

    f(x) = x²

    we can create related functions.

    Vertical shift:

    g(x) = f(x) + 3

    Horizontal shift:

    g(x) = f(x - 3)

    Vertical scaling:

    g(x) = 2f(x)

    Horizontal scaling:

    g(x) = f(2x)

    These expressions show that functions themselves can be transformed.

    37. Operations on Functions#

    Functions can participate in operations just like numbers.

    Suppose:

    f(x) = x²
g(x) = x + 1

    We can define:

    (f + g)(x) = f(x) + g(x)

    Therefore:

    (f + g)(x)
= x² + x + 1

    Similarly:

    (f - g)(x) = f(x) - g(x)

    and:

    (fg)(x) = f(x)g(x)

    and:

    (f / g)(x) = f(x) / g(x)

    where the division is defined.

    38. Composition Is Another Operation on Functions#

    We can now see composition differently.

    If:

    f(x) = 2x
g(x) = x + 3

    then:

    (f ∘ g)(x) = f(g(x))

    So there are operations that combine functions:

    f + g
f - g
fg
f / g
f ∘ g

    The result is often another function.

    39. Properties of Functions#

    Functions can have interesting properties beyond their formulas.

    For example:

    Even#

    f(-x) = f(x)

    Example:

    f(x) = x²

    Odd#

    f(-x) = -f(x)

    Example:

    f(x) = x³

    Periodic#

    There is some positive T such that:

    f(x + T) = f(x)

    Example:

    sin(x + 2π) = sin(x)

    These properties describe behaviour, not merely the formula.

    40. Increasing and Decreasing Functions#

    A function can also describe a trend.

    If increasing x generally increases f(x), the function is increasing.

    For example:

    f(x) = 2x + 1

    As x increases:

    x:     1   2   3   4
f(x):  3   5   7   9

    The outputs increase.

    Other functions may decrease, or may increase in some regions and decrease in others.

    41. Functions Can Have Different Domains#

    The same expression can define different functions depending on its domain.

    Consider:

    f(x) = x²

    Over the real numbers:

    f : ℝ → ℝ

    But we could instead define:

    f : ℤ → ℤ

    Now the function only accepts integers.

    Or:

    f : {1, 2, 3} → ℝ

    Now it accepts only three possible inputs.

    The domain is not an afterthought.

    The domain is part of the function.

    42. Functions in Programming#

    We can now reinterpret a programming function mathematically.

    A function such as:

    double(x)

    might represent:

    double(x) = 2x

    A function such as:

    square(x)

    might represent:

    square(x) = x²

    And a function such as:

    compose(f, g)

    might represent:

    compose(f, g)(x) = f(g(x))

    Programming gives us a way to execute these mathematical transformations.

    43. The Important Shift in Thinking#

    Initially, we think:

    function = formula

    But a more powerful understanding is:

    function = transformation

    Then:

    function
    ↓
can be composed
    ↓
can be inverted
    ↓
can be passed around
    ↓
can be returned
    ↓
can transform other functions
    ↓
can be applied recursively

    This is the bridge from elementary mathematics to programming.

    44. One Big Example#

    Suppose:

    f(x) = x²
g(x) = x + 1

    We can compose them:

    h(x) = f(g(x))
     = (x + 1)²

    We can then transform h:

    k(x) = h(x) + 5

    So:

    k(x) = (x + 1)² + 5

    We could also define a function that takes h itself:

    addFive(h)(x) = h(x) + 5

    Then:

    addFive(h)(3)
= h(3) + 5
= 16 + 5
= 21

    We are no longer just calculating with functions.

    We are calculating with functions themselves.

    45. From Values to Functions#

    There are several levels of abstraction.

    Level 1 — Values#

    x = 5

    Level 2 — Functions producing values#

    f(x) = x²

    Level 3 — Functions taking functions#

    H(f, x) = f(x) + 1

    Level 4 — Functions producing functions#

    F(a)(x) = x + a

    Level 5 — Functions transforming functions#

    transform(f)(x) = f(x) + 1

    This is a major conceptual transition toward functional programming.

    46. A Mental Model for Programming#

    When you encounter a programming function, ask:

    What are its inputs?#

    domain

    What does it produce?#

    range

    What transformation does it perform?#

    mapping

    Can it be composed with another function?#

    f(g(x))

    Can it receive another function?#

    H(f, x)

    Can it return another function?#

    F(x)(y)

    Can it call itself?#

    f(x) → f(smaller problem)

    These questions turn programming functions into something mathematically familiar.

    47. Summary#

    We began with:

    input → function → output

    We can now extend that model:

    input
  ↓
function
  ↓
output

    Functions can also:

    compose with other functions
    be inverted
    take functions as inputs
    return functions as outputs
    be transformed into other functions
    operate on collections
    be defined recursively

    48. The Big Idea#

    A function is not merely:

    f(x) = some formula

    A function is a mapping or transformation.

    And once we accept that functions are things we can manipulate, we can build increasingly powerful ideas:

    Functions
    ↓
Composition
    ↓
Inverse functions
    ↓
Functions as values
    ↓
Higher-order functions
    ↓
Anonymous functions
    ↓
Currying / partial application
    ↓
Recursion
    ↓
Functional programming

    The mathematical concept stays the same.

    What changes is what we are willing to do with functions.
