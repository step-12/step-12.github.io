    Javascript, Objects

    Objects#

    You have now written enough JavaScript to run into an interesting problem.

    You have variables.

    You have functions.

    You have started writing programs that are a little larger than a few lines.

    And now you may have noticed something.

    Sometimes, several values belong together.

    Suppose we want to describe a person.

    We might write:

    const name = "Asha";
const age = 20;
const city = "Mysuru";

    There is nothing wrong with this.

    But look at those three variables.

    They all describe the same thing.

    Wouldn’t it be useful if we could give the whole collection a name?

    JavaScript gives us a way to do exactly that.

    It is called an object.

    Our first object#

    Try this in the REPL:

    const person = {
  name: "Asha",
  age: 20,
  city: "Mysuru",
};

    What do you think person contains?

    Try:

    person;

    You should see something like:

    { name: 'Asha', age: 20, city: 'Mysuru' }

    We have created one value containing several other values.

    The object has three properties:

    name
age
city

    Each property has a value:

    name → "Asha"
age  → 20
city → "Mysuru"

    We can think of the object as a little collection of names and values.

    Getting a property#

    How do we get the name out of the object?

    Try:

    person.name;

    You should get:

    "Asha"

    And:

    person.age;

    gives:

    20

    And:

    person.city;

    gives:

    "Mysuru"

    The . means:

    Get this property from this object.

    So:

    person.age;

    means:

    Look at the object referred to by person and get its age property.

    Try combining this with things you already know:

    person.age + 1;

    What do you get?

    You should get:

    21

    Notice what happened.

    person.age is an expression.

    It produces a value.

    That value can be used anywhere we could use another value.

    For example:

    console.log(person.name);

    or:

    person.age > 18;

    or:

    person.age + 10;

    Changing a property#

    An object is not frozen just because we used const.

    Try:

    person.age = 21;

    Now:

    person.age;

    You should get:

    21

    We changed the value of the age property.

    We can also add a property.

    Try:

    person.country = "India";

    Now:

    person;

    You should see the new property too.

    We started with:

    {
  name: "Asha",
  age: 20,
  city: "Mysuru"
}

    and then added:

    country → "India"

    There is something worth noticing here.

    We did not have to declare country beforehand.

    The assignment:

    person.country = "India";

    created the property.

    If the property already exists, assignment changes it.

    If it does not exist, assignment creates it.

    Try:

    person.city = "Bengaluru";

    What is person.city now?

    const and objects#

    We just did something that might seem strange.

    We declared:

    const person = {
  name: "Asha",
  age: 20,
};

    and then changed the object:

    person.age = 21;

    So what exactly does const mean here?

    Try this:

    person = {};

    You should get an error.

    But this works:

    person.age = 21;

    Why?

    There are two different things happening.

    When we write:

    person.age = 21;

    we are changing the object.

    When we write:

    person = {};

    we are trying to change what person refers to.

    const prevents the second thing.

    It does not make the object itself unchangeable.

    For now, keep this distinction in your head:

    const prevents reassignment of the variable. It does not make the object immutable.

    We will return to this distinction.

    It is important.

    Another way to access a property#

    There is another way to get a property.

    We have already written:

    person.name;

    We can also write:

    person["name"];

    Try it.

    You should get:

    "Asha"

    Try:

    person["age"];

    You should get:

    21

    So these two expressions produce the same value:

    person.name;

    and:

    person["name"];

    Why do we have two ways to do the same thing?

    There is a very good reason.

    When the property name is in a variable#

    Consider our object of capitals:

    const capitals = {
  India: "New Delhi",
  France: "Paris",
  Japan: "Tokyo",
};

    We can write:

    capitals.India;

    and get:

    "New Delhi"

    We can also write:

    capitals["India"];

    and get the same value.

    But now suppose we have:

    const country = "India";

    We want to find the capital of whatever country is stored in country.

    Try:

    capitals[country];

    What do you think happens?

    We get:

    "New Delhi"

    Notice what happened.

    The value of country is:

    "India"

    So:

    capitals[country];

    is effectively asking for:

    capitals["India"];

    This is called computed property access.

    The expression inside [] is evaluated first.

    Try:

    const country = "Japan";

capitals[country];

    You should get:

    "Tokyo"

    Now try:

    const country = "France";

capitals[country];

    You should get:

    "Paris"

    This is one of the reasons [] is useful.

    What would happen if you wrote:

    capitals.country;

    Think before you run it.

    You are asking JavaScript for a property literally named:

    country

    You are not asking it to look at the value stored in the variable country.

    That is the difference.

    capitals.country;

    means:

    Get the property whose name is "country".

    Whereas:

    capitals[country];

    means:

    Evaluate country, then use that value as the property name.

    This distinction will become very useful.

    Objects can be empty#

    We don’t have to create all the properties at once.

    Try:

    const person = {};

    This is an empty object.

    Now:

    person.name = "Asha";
person.age = 20;

    We have gradually built the object.

    Try:

    person;

    You should now see:

    { name: "Asha", age: 20 }

    An empty object is still an object.

    There is another interesting thing about an empty object.

    Try:

    if ({}) {
  console.log("yes");
}

    What happens?

    You should see:

    yes

    An empty object is truthy.

    It does not matter that it has no properties.

    The object itself is a value, and objects are truthy.

    So don’t think:

    “It is empty, therefore it must be false.”

    That is not how JavaScript works.

    What happens when a property doesn’t exist?#

    Try:

    const person = {
  name: "Asha",
};

person.age;

    What happens?

    You should get:

    undefined

    There is no age property.

    JavaScript does not automatically produce an error just because the property doesn’t exist.

    It gives us undefined.

    Now try:

    person.age = 20;

    and then:

    person.age;

    Now the property exists.

    This gives us another useful way to think about objects:

    An object is a collection of properties, and each property has a name and a value.

    Why are objects useful?#

    Let’s return to our original problem.

    Suppose we have a point:

    x = 10
y = 20

    We could write:

    const x = 10;
const y = 20;

    But perhaps these two values belong together.

    We can instead write:

    const point = {
  x: 10,
  y: 20,
};

    Now we can pass the point around as one value.

    We can say:

    point.x;

    and:

    point.y;

    We have given the collection a name:

    point

    This becomes especially useful when we have functions.

    Too many parameters#

    Imagine a function that needs to describe a person.

    We might write:

    function describePerson(name, age, city, country) {
  // ...
}

    That works.

    But look at the function call:

    describePerson("Asha", 20, "Mysuru", "India");

    What does each value mean?

    You have to remember the order.

    The first value is the name.

    The second is the age.

    The third is the city.

    The fourth is the country.

    What if we had ten pieces of information?

    The function call would become difficult to read.

    Instead, we can group the related values:

    const person = {
  name: "Asha",
  age: 20,
  city: "Mysuru",
  country: "India",
};

    Then:

    function describePerson(person) {
  console.log(person.name);
  console.log(person.age);
  console.log(person.city);
  console.log(person.country);
}

    And:

    describePerson(person);

    We have passed one value.

    That value happens to contain several related values.

    This is one of the most common uses of objects.

    Objects and functions#

    You have already learned that functions can receive values.

    For example:

    function double(number) {
  return number * 2;
}

    We can give it:

    double(10);

    and the parameter number receives the value 10.

    The same thing happens when we pass an object.

    Try:

    const point = {
  x: 10,
  y: 20,
};

function showPoint(p) {
  console.log(p.x);
  console.log(p.y);
}

showPoint(point);

    Inside the function, p refers to the object we passed.

    So:

    p.x;

    gets the x property of that object.

    And:

    p.y;

    gets the y property.

    There is something important happening here.

    The function did not receive four separate values.

    It received one object.

    That object gives the function access to all the related information it needs.

    Functions can return objects#

    You have also learned that a function can return a value.

    For example:

    function double(number) {
  return number * 2;
}

    The returned value is a number.

    But a function can return an object too.

    Try:

    function makePoint() {
  return {
    x: 10,
    y: 20,
  };
}

    Now:

    const point = makePoint();

    What is point?

    Try:

    point;

    You should see:

    { x: 10, y: 20 }

    And:

    point.x;

    gives:

    10

    A function can return any kind of value that JavaScript allows us to use as a value.

    An object is one such value.

    This is useful when a function needs to produce several related pieces of information.

    Instead of trying to return several separate values, we can put them into an object.

    For example:

    function getPerson() {
  return {
    name: "Asha",
    age: 20,
  };
}

    Then:

    const person = getPerson();

    and:

    person.name;

    or:

    person.age;

    But what exactly happens when we pass an object?#

    This is where things get interesting.

    Consider:

    const person = {
  name: "Asha",
  age: 20,
};

    Now:

    const otherPerson = person;

    What do you think happened?

    Did JavaScript make a second object?

    Let’s test it.

    Try:

    otherPerson.age = 21;

    Now:

    person.age;

    What do you expect?

    You might expect:

    20

    because we changed otherPerson.

    But try it.

    You should get:

    21

    Why?

    Because person and otherPerson refer to the same object.

    We did not make a copy of the object.

    We made another reference to it.

    You can imagine it like this:

    person ───────────┐
                  │
                  ▼
             ┌──────────────┐
             │ name: "Asha" │
             │ age: 21      │
             └──────────────┘
                  ▲
                  │
otherPerson ──────┘

    There is one object.

    There are two names referring to it.

    So when we write:

    otherPerson.age = 21;

    we change the object.

    When we later ask:

    person.age;

    we are looking at that same object.

    So we see 21.

    Try it yourself#

    Before reading further, try these:

    const a = {
  x: 10,
};

const b = a;

b.x = 20;

a.x;

    Predict the result.

    Then try it.

    Now change the last expression to:

    b.x;

    Are the answers different?

    They should not be.

    Both names refer to the same object.
