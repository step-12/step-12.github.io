      Javascript, Loops

      Loops#

      We have been asking the computer to do more and more interesting things.

      We can give names to values. We can make decisions with if. We can organize data with objects. We can even draw things on the screen.

      But there is one thing we haven’t really asked the computer to do yet:

      Do something again.

      You have already seen a loop, though.

      Think back to the Raylib program we wrote.

      There was a piece of code that kept running:

      while (!r.WindowShouldClose()) {
  update();
  draw();
}

      We didn’t spend much time thinking about the while at the time. We were interested in understanding the drawing loop.

      Now let’s slow down and ask:

      What exactly is a loop?

      Doing something again#

      Suppose you want to print hello three times.

      You could write:

      console.log("hello");
console.log("hello");
console.log("hello");

      That works.

      But what if you wanted to print it 100 times?

      Would you write 100 console.log calls?

      What if you wanted to print it 10,000 times?

      There must be a better way of saying:

      Do this thing again.

      This is what loops give us.

      Before looking at the syntax, let’s think about what any loop must do.

      Suppose I tell you:

      Keep walking forward until you reach the wall.

      What information do you need?

      You need to know:

      1. Where do you start?
      2. What do you do?
      3. When do you stop?
      4. What changes between one attempt and the next?

      These questions are going to appear again and again when we write loops.

      While#

      Let’s start with the loop you have already seen.

      while (condition) {
  // something
}

      What do you think this means?

      Try this:

      let n = 0;

while (n < 5) {
  console.log(n);
  n = n + 1;
}

      Before running it, predict what it prints.

      Now trace it carefully.

      We start with:

      n = 0

      Is n < 5 true?

      Yes.

      So the body runs.

      0

      Then n changes:

      n = 1

      We reach the while condition again.

      Is 1 < 5 true?

      And so on.

      Eventually:

      n = 5

      Is 5 < 5 true?

      No.

      So the loop stops.

      This gives us a useful way to think about a while loop:

      check the condition
        |
        v
    Is it true?
     /       \
   yes        no
    |           |
    v           v
 run body      stop
    |
    v
change something
    |
    +-----------> check the condition again

      The condition is checked before every iteration.

      An iteration is one trip through the body of the loop.

      So how many iterations did our example have?

      What makes a loop a loop?#

      Look at this:

      let n = 0;

while (n < 5) {
  console.log(n);
  n = n + 1;
}

      There are three important pieces hiding here.

      Where do we start?#

      let n = 0;

      When do we continue?#

      n < 5;

      What changes?#

      n = n + 1;

      These three questions are useful whenever you write a loop:

      Where do I start?

      When should I continue?

      What changes each time?

      Consider this loop:

      let n = 10;

while (n > 0) {
  console.log(n);
  n = n - 1;
}

      What are the answers to those three questions?

      Now change it so that it prints:

      10
8
6
4
2

      What needs to change?

      What happens if nothing changes?#

      Consider:

      let n = 0;

while (n < 5) {
  console.log(n);
}

      What happens here?

      The condition is true.

      So the body runs.

      The condition is true again.

      The body runs again.

      The condition is true again.

      Does anything ever make n reach 5?

      No.

      We have accidentally created an infinite loop.

      A loop does not automatically make progress. We have to make sure that something changes in a way that can eventually make the condition false.

      This is one of the first things to check when a loop doesn’t behave as expected:

      Can this loop ever stop?

      For#

      Now consider our first example again:

      let n = 0;

while (n < 5) {
  console.log(n);
  n = n + 1;
}

      There is something slightly repetitive about it.

      The setup is here:

      let n = 0;

      The condition is here:

      n < 5;

      And the update is here:

      n = n + 1;

      JavaScript gives us another way to write this:

      for (let n = 0; n < 5; n = n + 1) {
  console.log(n);
}

      At first, this looks quite different.

      But look closely.

      There are three things inside the parentheses:

      for (initialization; condition; update) {
  // body
}

      Can you identify the three pieces from our while loop?

      initialization → let n = 0
condition      → n < 5
update         → n = n + 1
body           → console.log(n)

      So perhaps a for loop isn’t as mysterious as it first appears.

      The order matters#

      There is one important question.

      In this:

      for (let n = 0; n < 5; n = n + 1) {
  console.log(n);
}

      What happens first?

      Does n = n + 1 happen before console.log?

      Does the condition get checked before n is initialized?

      Let’s trace it.

      let n = 0

check n < 5
run the body
update n

check n < 5
run the body
update n

...

      More precisely:

      initialization
      |
      v
  condition <------------------+
      |                        |
     true                      |
      |                        |
      v                        |
     body                      |
      |                        |
      v                        |
    update --------------------+
      |
      v
  condition

      And when the condition becomes false, we leave the loop.

      Notice something important:

      The update happens after the body.

      That is why this:

      for (let n = 0; n < 5; n = n + 1) {
  console.log(n);
}

      prints:

      0
1
2
3
4

      and not:

      1
2
3
4
5

      Every for can be a while#

      We can take our for loop:

      for (let n = 0; n < 5; n = n + 1) {
  console.log(n);
}

      and expand it into:

      let n = 0;

while (n < 5) {
  console.log(n);
  n = n + 1;
}

      The two loops have the same structure.

      The for syntax simply puts the initialization, condition, and update together.

      This is an important idea:

      A for loop isn’t a completely different kind of repetition. It is another way of organizing a loop.

      If you understand while, you already understand the essential idea behind for.

      Try converting these yourself.

      Exercise#

      Rewrite each for loop as a while loop.

      for (let n = 0; n < 10; n = n + 1) {
  console.log(n);
}
      for (let n = 10; n > 0; n = n - 1) {
  console.log(n);
}
      for (let n = 0; n < 20; n = n + 2) {
  console.log(n);
}

      Pay attention to the last one.

      The update isn’t necessarily:

      n = n + 1;

      Which brings us to something worth correcting.

      It doesn’t have to be i++#

      If you have programmed in C or another language, you may have seen hundreds of loops that look like this:

      for (let i = 0; i < 10; i++) {
  // ...
}

      It is easy to start thinking that a for loop means:

      Start i at zero, increase i by one, and stop at ten.

      But that is only one particular use of a for loop.

      Remember what the third part means:

      for (initialization; condition; update)

      It is the update.

      There is nothing special about i++.

      For example:

      for (let n = 0; n < 10; n = n + 2) {
  console.log(n);
}

      What does this print?

      How about:

      for (let n = 10; n > 0; n = n - 1) {
  console.log(n);
}

      And:

      for (let n = 1; n < 100; n = n * 2) {
  console.log(n);
}

      What does this one print?

      The computer doesn’t know that n is a counter.

      We decided to use it as one.

      The third part of the for loop is simply something that gets evaluated after every iteration.

      A for loop written strangely#

      Consider this:

      for (let n = 100; n > 1; n = n / 2) {
  console.log(n);
}

      There is no ++.

      There isn’t even an addition.

      The value is being divided by two every time.

      Trace it.

      What values are printed?

      How many iterations are there?

      Now try changing the update to:

      n = n - 3;

      What changes?

      The syntax of the loop hasn’t changed.

      Only the rule for what happens next has changed.

      for and while are not rules about counting#

      You may now be tempted to make a rule:

      Use for when counting. Use while when not counting.

      That’s a useful starting point, but it isn’t a law.

      Remember:

      for (let n = 0; n < 100; n = n + 1) {
  // ...
}

      and:

      let n = 0;

while (n < 100) {
  // ...
  n = n + 1;
}

      can do exactly the same thing.

      So how do we choose?

      One useful question is:

      Do I naturally know the structure of the repetition?

      If you want to do something a known number of times, a for loop often describes the problem nicely.

      For example:

      Print "hello" 10 times.

      We know there are 10 iterations.

      A for loop makes that structure visible.

      But consider:

      Keep looking at numbers until you find the 100th prime.

      Do we know how many numbers we will have to examine?

      No.

      We don’t know where the 100th prime is.

      We know the condition that ends the process, but not the number of iterations.

      A while loop often describes this kind of problem naturally.

      Again, this is a useful way of thinking, not a rule enforced by JavaScript.

      An exercise in choosing#

      For each problem, decide whether you would naturally start with a for loop or a while loop.

      Don’t write the code yet. Just think about the problem.

      1. Print "hello" 20 times.
      2. Print the numbers from 1 to 100.
      3. Find the 100th prime number.
      4. Keep generating numbers until you get one greater than 1,000.
      5. Print a countdown from 10 to 1.
      6. Keep trying until a number is divisible by both 7 and 13.
      7. Print the powers of 2 smaller than 1,000.
      8. Find the first prime number greater than 1,000.

      For each one, ask:

      Do I know how many times I need to repeat?

      Or:

      Do I know a condition that tells me when I’m done?

      A problem that naturally wants while#

      Let’s think about primes.

      Suppose we want to find the 10th prime number.

      We could start at 2 and examine numbers one by one.

      When we find a prime, we increase our count of primes.

      When we have found 10 primes, we’re done.

      Before writing any JavaScript, describe the process in English.

      Perhaps something like:

      Start with a number.
Start with zero primes found.

While we haven't found 10 primes:
    check whether the number is prime
    if it is prime, increase our count
    move to the next number

      Notice what happened.

      We didn’t choose while because someone told us:

      “Prime numbers require a while loop.”

      We chose it because the problem itself naturally says:

      Keep going until something becomes true.

      Now implement it.

      You will need to decide how you want to determine whether a number is prime. That’s a problem of its own.

      do...while#

      There is one small variation of while that is worth knowing.

      Consider:

      while (condition) {
  // body
}

      What happens first?

      The condition is checked.

      Only if it is true does the body run.

      Now consider:

      do {
  // body
} while (condition);

      What’s different?

      The body comes first.

      Try:

      let n = 10;

while (n < 10) {
  console.log(n);
}

      What happens?

      Now try:

      let n = 10;

do {
  console.log(n);
} while (n < 10);

      This prints:

      10

      Why?

      Because the body is executed before the first condition check.

      So we can think of them this way:

      while:

    check
      |
      v
    do it
      |
      +---- check again

      versus:

      do...while:

    do it
      |
      v
    check
      |
      +---- do it again

      This means a do...while loop always executes its body at least once.

      You probably won’t need it very often.

      But when the problem says:

      Do this at least once, and then keep doing it while…

      do...while can describe the problem nicely.

      Nested loops#

      What happens if a loop contains another loop?

      Consider:

      for (let i = 0; i < 3; i = i + 1) {
  for (let j = 0; j < 4; j = j + 1) {
    console.log(i, j);
  }
}

      Before running it, predict the output.

      How many times does the console.log execute?

      A useful way to think about it is:

      i = 0
    j = 0
    j = 1
    j = 2
    j = 3

i = 1
    j = 0
    j = 1
    j = 2
    j = 3

i = 2
    j = 0
    j = 1
    j = 2
    j = 3

      For every iteration of the outer loop, the inner loop runs completely.

      The outer loop runs 3 times.

      The inner loop runs 4 times for each outer iteration.

      So the body runs:

      3 × 4

      times.

      Try writing the same program with two while loops.

      Then try changing the outer loop to run 5 times and the inner loop to run 2 times.

      How many times does the body execute now?

      Nested loops don’t have to be for loops#

      There is nothing special about nesting for loops.

      This is also perfectly valid:

      let i = 0;

while (i < 3) {
  let j = 0;

  while (j < 4) {
    console.log(i, j);
    j = j + 1;
  }

  i = i + 1;
}

      And we can mix them:

      let i = 0;

while (i < 3) {
  for (let j = 0; j < 4; j = j + 1) {
    console.log(i, j);
  }

  i = i + 1;
}

      The important thing isn’t the syntax.

      The important thing is understanding what happens when one repetition happens inside another repetition.

      break#

      Sometimes we want to stop a loop before its normal condition becomes false.

      JavaScript gives us break:

      for (let n = 0; n < 10; n = n + 1) {
  if (n === 5) {
    break;
  }

  console.log(n);
}

      What does this print?

      At n === 5, break immediately leaves the loop.

      So:

      0
1
2
3
4

      A break is useful when we discover that we are done before reaching the normal end of the loop.

      But there is a reason to use it carefully.

      Compare:

      for (let n = 0; n < 5; n = n + 1) {
  console.log(n);
}

      with a loop whose termination is hidden somewhere inside its body.

      The first one tells you immediately:

      This loop runs while n < 5.

      The second requires you to search the body to understand when it might stop.

      So although break is useful, a good general preference is:

      Prefer a loop whose normal condition clearly describes when it ends.

      Use break when it genuinely makes the code clearer.

      continue#

      There is another control-flow statement:

      continue;

      It means:

      Stop this iteration here and move on to the next iteration.

      For example:

      for (let n = 0; n < 10; n = n + 1) {
  if (n % 2 === 0) {
    continue;
  }

  console.log(n);
}

      What does it print?

      When n is even, we skip the rest of the body.

      So the output is:

      1
3
5
7
9

      Again, continue is useful, but use it judiciously.

      A loop with several continues can force the reader to keep jumping around the code to understand what happens.

      Often, the same logic can be written more clearly using an if:

      for (let n = 0; n < 10; n = n + 1) {
  if (n % 2 !== 0) {
    console.log(n);
  }
}

      Neither break nor continue is bad.

      But as a general preference:

      Prefer straightforward loops where the normal flow tells the story.

      Use these tools when they make that story clearer, not simply because they are available.

      One last question#

      We started with a simple question:

      How do we tell the computer to do something again?

      We now have several ways of expressing the answer.

      A while loop says:

      Keep doing this while this condition is true.

      A for loop gives us a convenient place to put:

      Where do I start? When do I continue? What changes?

      A do...while says:

      Do this once, then keep doing it while this condition is true.

      And nested loops let one repetition happen inside another.

      But underneath all of these is the same idea:

      Do something repeatedly, and have some way of knowing when to stop.

      As you write more loops, don’t start by asking:

      “Should I use for or while?”

      Instead, ask:

      What am I repeating?

      What changes each time?

      What tells me that I’m done?

      Those questions will usually lead you to the loop you need.
