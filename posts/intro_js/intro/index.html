    Intro to JS

    September 16, 2026

    Your first language#

    Until now, you’ve been talking to your computer through the shell.

    You’ve typed commands. The shell has interpreted those commands, started processes, connected them together, and shown you their output.

    Now we’re going to learn a programming language.

    We’re going to start with JavaScript.

    And we’re going to do something slightly different from what you might expect from a programming class.

    For now, we’re not going to write a program.

    We’re going to have a conversation.

    Open Ghostty.

    JavaScript#

    JavaScript was created in the 1990s, originally as a language for making web pages interactive. Since then, it has grown far beyond the browser.

    Today, JavaScript can be used for servers, command-line programs, desktop applications, tooling, and much more.

    But JavaScript itself isn’t a program sitting on your computer waiting for you to type things into it.

    A programming language needs something that can understand the language and execute it.

    That something is an implementation of the language.

    There are several implementations of JavaScript. The browser you’re using has one. Node.js has another. Other environments have their own implementations.

    For this course, we’ll use Node.js.

    You don’t need to worry too much about the distinction yet. Just remember:

    JavaScript is the language. Node.js is one implementation of that language.

    And Node gives us something particularly useful for learning:

    a REPL.

    Your first REPL#

    In Ghostty, type:

    node

    You should see something like:

    Welcome to Node.js ...
Type ".help" for more information.
>

    That > is Node waiting for you.

    Type:

    5;

    Press Enter.

    You should get:

    5

    And then another prompt:

    >

    You just had your first conversation with JavaScript.

    But what exactly happened?

    REPL#

    REPL stands for:

    Read – Evaluate – Print – Loop

    Node reads what you type.

    It evaluates it as JavaScript.

    It prints the result.

    And then it waits for you to do it again.

    Let’s try something more interesting.

    5 + 3;

    You should get:

    8

    Now try:

    5 * 3;

    And:

    20 / 4;

    And:

    20 - 7;

    The REPL is a little bit like your shell.

    You type something, press Enter, and something happens.

    But there is an important difference.

    When you were using the shell, you were giving the shell commands.

    Here, you’re giving Node JavaScript.

    Try this:

    ls;

    What happens?

    Try:

    pwd;

    What happens?

    Now press Ctrl-D to leave Node and return to your shell.

    Try:

    ls

    What happened this time?

    This is an important distinction to get comfortable with:

    The shell and the JavaScript REPL may both live inside your terminal, but they are different environments that understand different languages.

    Start Node again:

    node

    We’ll stay here for a while.

    Values#

    Let’s start with something very simple.

    Type:

    5;

    JavaScript gives you:

    5

    Now try:

    42;

    Then:

    -10;

    Then:

    3.14159;

    These are all numbers.

    But there’s something more fundamental going on.

    5 is a value.

    A value is, roughly speaking, a thing that JavaScript can work with.

    And an expression is something JavaScript can evaluate to produce a value.

    For example:

    5;

    is an expression.

    Its value is:

    5

    And:

    5 + 3;

    is also an expression.

    Its value is:

    8

    Keep that idea in your head.

    An expression produces a value.

    We’ll keep coming back to it.

    Numbers#

    Let’s explore numbers a little.

    Try these one at a time:

    0;
1;
100 - 100;
5.25;

    Now try:

    1e6;

    What did you get?

    What about:

    1e-3;

    You don’t need to remember every way of writing a number right now. The interesting thing is that JavaScript gives you several ways to describe the same general kind of value.

    Now let’s do some arithmetic.

    5 + 3;
    5 - 3;
    5 * 3;
    5 / 3;
    5 % 3;

    What do you think % means?

    Don’t look it up yet.

    Try different numbers.

    10 % 2;
    10 % 3;
    10 % 4;

    Can you figure out what it is doing?

    You may not be able to explain it yet.

    That’s fine.

    One of the most useful skills you can develop as a programmer is learning to ask the computer questions.

    You don’t always need to know the answer before you start investigating.

    Try:

    2 ** 8;

    What happened?

    What do you think ** means?

    Try a few more.

    2 ** 3;
3 ** 2;
10 ** 2;

    Can an expression contain another expression?#

    Consider:

    2 + 3 * 5;

    Before you press Enter, predict the answer.

    Is it:

    25

    or:

    17

    Try it.

    Now try:

    (2 + 3) * 5;

    Why did the answer change?

    Try:

    2 + 3 * 5;

    What happens?

    Now try:

    10 - 2 * 3;

    and:

    (10 - 2) * 3;

    There is a rule here.

    JavaScript has rules about which parts of an expression get evaluated first.

    You don’t need to memorize all of those rules right now.

    Instead, experiment.

    Try to find out what happens with:

    2 + 3 * 4;
    (2 + 3) * 4;
    2 * 3 + 4 * 5;
    20 / (2 + 3);

    Can you predict the answer before running each one?

    This is the beginning of learning to read code.

    Eventually, when you see an expression, you shouldn’t have to run it to know what it means.

    But for now, run it.

    What else can be a value?#

    Numbers aren’t the only things JavaScript can work with.

    Try:

    true;

    and:

    false;

    These are boolean values.

    A boolean can have one of two values:

    true
false

    Now ask JavaScript a question.

    Try:

    5 > 3;

    What did you get?

    Try:

    5 < 3;

    And:

    5 === 5;

    And:

    5 === 10;

    Something interesting is happening.

    The expression:

    5 > 3;

    produces a value.

    That value is:

    true;

    So comparisons are expressions too.

    They take values and produce another value.

    Try:

    10 >= 10;
    10 > 10;
    10 <= 10;
    10 != 20;

    Now investigate this:

    5 === "5";

    What happened?

    And now:

    5 == "5";

    Something strange?

    Don’t worry if you don’t yet understand why.

    In fact, this is a good moment to develop a habit:

    When JavaScript does something surprising, don’t immediately memorize the rule. Investigate it.

    We’ll return to this later.

    For now, prefer === when you mean “are these exactly equal?”

    Combining questions#

    We can also combine boolean expressions.

    Try:

    true && true;

    Then:

    true && false;

    Then:

    false && false;

    What does && appear to mean?

    Now try:

    true || false;
    false || false;
    true || true;

    What about !?

    !true;
    !false;

    You can now put these ideas together.

    Try:

    5 > 3 && 10 < 20;

    And:

    5 < 3 || 10 < 20;

    And:

    !(5 === 5);

    Notice the structure.

    We have expressions inside expressions.

    5 > 3

    produces a boolean.

    That boolean can become part of:

    5 > 3 && 10 < 20;

    which itself produces another boolean.

    This is a pattern you’ll see constantly in programming:

    Small expressions can be combined to make larger expressions.

    Strings#

    Let’s meet another kind of value.

    Try:

    "Hello";

    You can also write:

    "Hello";

    And:

    `Hello`;

    All three describe strings.

    Try:

    "Hello" + " World";

    What did you get?

    The + operator can do arithmetic with numbers:

    5 + 3;

    But with strings, it can mean something different:

    "Hello" + " World";

    It joins them together.

    Now try:

    "Score: " + 10;

    What happened?

    JavaScript is willing to convert the number so that it can combine it with the string.

    Now try:

    `Score: ${10}`;

    This is a template string.

    The ${...} part lets us put an expression inside the string.

    Try changing it:

    `The answer is ${5 + 3}`;

    And:

    `2 multiplied by 10 is ${2 * 10}`;

    Pause here.

    What do you think ${...} is doing?

    Can you put a comparison inside it?

    Try:

    `Is 10 greater than 5? ${10 > 5}`;

    The important thing isn’t memorizing template strings.

    It’s noticing that expressions can appear inside other expressions.
