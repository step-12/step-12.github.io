      October 21, 2026
      Javascript, Arrays

      More Array APIs#

      We have learned how arrays work.

      We know how to access an element using its index:

      const numbers = [10, 20, 30];

numbers[1]; // 20

      We know how to move through an array using a loop. We also know how to add and remove elements using APIs such as push, pop, shift, and unshift.

      JavaScript gives us several more useful array APIs. They give names to common operations and save us from writing the same loops repeatedly.

      In this post, we will learn about:

      • concat
      • includes
      • indexOf
      • reverse
      • slice
      • splice

      As we explore them, keep asking three questions:

      1. What problem does the API solve?
      2. What does the API return?
      3. Does it change the original array?

      These three questions will help us avoid many surprises.

      Joining arrays with concat#

      Suppose we have two arrays:

      const first = [10, 20];
const second = [30, 40];

      We want one array containing the elements of both.

      JavaScript gives us concat:

      const combined = first.concat(second);

      Now:

      combined; // [10, 20, 30, 40]

      The elements from first come first. The elements from second follow them.

      Something important happened here: concat created a new array.

      first;  // [10, 20]
second; // [30, 40]

      Neither original array changed.

      We can join more than two arrays:

      const morning = ["wake up", "brush teeth"];
const afternoon = ["eat lunch", "study"];
const evening = ["exercise", "sleep"];

const day = morning.concat(afternoon, evening);

      The result is:

      ["wake up", "brush teeth", "eat lunch", "study", "exercise", "sleep"]

      Try it#

      Create these two arrays:

      const odd = [1, 3, 5];
const even = [2, 4, 6];

      Use concat to create:

      [1, 3, 5, 2, 4, 6]

      Then reverse the order in which you concatenate them. What changes?

      Asking whether an array contains a value with includes#

      Sometimes we do not need to know where an element is. We only need to know whether it is present.

      const heroes = ["Storm", "Cyclops", "Wolverine"];

heroes.includes("Wolverine");

      The result is:

      true

      If the value is not present:

      heroes.includes("Spider-Man");

      the result is:

      false

      includes answers a yes-or-no question, so it always returns a boolean.

      It does not change the array.

      Capitalisation matters:

      heroes.includes("wolverine"); // false

      The array contains "Wolverine", not "wolverine".

      Try it#

      Given:

      const numbers = [10, 20, 30, 40];

      Use includes to ask whether the array contains 30.

      Then ask whether it contains 35.

      What type of value do you get each time?

      Finding a position with indexOf#

      includes tells us whether a value exists. Sometimes we also need to know its position.

      For that, we can use indexOf:

      const heroes = ["Storm", "Cyclops", "Wolverine"];

heroes.indexOf("Cyclops");

      The result is:

      1

      Remember that array indices begin at 0.

             0          1            2
[ "Storm", "Cyclops", "Wolverine" ]

      What happens when the value is not in the array?

      heroes.indexOf("Spider-Man");

      The result is:

      -1

      -1 means that no matching index was found.

      This gives us another way to ask whether an array contains a value:

      if (heroes.indexOf("Wolverine") !== -1) {
  console.log("Wolverine is here");
}

      If a value appears more than once, indexOf gives us the index of its first appearance:

      const numbers = [10, 20, 10, 30];

numbers.indexOf(10); // 0

      Like includes, indexOf does not change the array.

      Try it#

      Given:

      const colours = ["red", "green", "blue", "green"];

      What does colours.indexOf("green") return?

      What does colours.indexOf("yellow") return?

      Explain why the two results are different.

      Reversing an array with reverse and toReversed#

      We previously wrote loops that visited an array from its end to its beginning. JavaScript can also reverse the order of the elements for us:

      const numbers = [10, 20, 30, 40];

numbers.reverse();

      Now numbers is:

      [40, 30, 20, 10]

      There is an important difference between reverse and the APIs we have just seen.

      reverse changes the original array.

      It does not make a separate reversed array for us.

      This can be a problem when we still need the original order.

      How could we create a reversed array without changing the original one?

      We can use toReversed:

      const numbers = [10, 20, 30, 40];
const reversed = numbers.toReversed();

      Now:

      numbers;  // [10, 20, 30, 40]
reversed; // [40, 30, 20, 10]

      Unlike reverse, toReversed returns a new array and leaves the original array unchanged.

      Try it#

      Start with:

      const names = ["Anu", "Rahul", "Meera"];

      Create a reversed version without changing names.

      Check both arrays afterwards.

      Which of the two APIs should you use: reverse or toReversed?

      Copying part of an array with slice#

      Suppose we want only part of an array.

      const numbers = [10, 20, 30, 40, 50];

      We can use slice:

      const middle = numbers.slice(1, 4);

      The result is:

      [20, 30, 40]

      The first argument is the index where the slice begins.

      The second argument is the index where it stops. The value at the stopping index is not included.

       index       0     1     2     3     4
           [10]  [20]  [30]  [40]  [50]
                  └─────────────┘
                    slice(1, 4)

      We can remember it like this:

      Start at 1. Stop before 4.

      What happens if we provide only one argument?

      numbers.slice(2);

      Where might the slice stop when no stopping index is provided?

      What happens if we provide no arguments at all?

      const copy = numbers.slice();

      What values do you expect copy to contain? Is copy the same array as numbers, or is it a new array?

      slice returns a new array. It does not change the original.

      Try it#

      Given:

      const letters = ["a", "b", "c", "d", "e"];

      Use slice to create:

      ["b", "c", "d"]

      Then create:

      ["c", "d", "e"]

      Check that letters has not changed.

      Removing and inserting elements with splice#

      The names slice and splice look similar, but the APIs behave very differently.

      slice copies part of an array.

      splice changes an array by removing or inserting elements.

      Let us begin by removing an element:

      const numbers = [10, 20, 30, 40];

numbers.splice(1, 1);

      The first argument tells us where to begin.

      The second argument tells us how many elements to remove.

      We begin at index 1 and remove one element, so numbers becomes:

      [10, 30, 40]

      We can remove more than one element:

      const numbers = [10, 20, 30, 40, 50];

numbers.splice(1, 3);

      Now numbers is:

      [10, 50]

      The removed elements are also returned to us:

      const numbers = [10, 20, 30, 40];
const removed = numbers.splice(1, 2);

removed; // [20, 30]
numbers; // [10, 40]

      We can insert elements by adding more arguments:

      const numbers = [10, 20, 40];

numbers.splice(2, 0, 30);

      This says:

      1. Begin at index 2.
      2. Remove 0 elements.
      3. Insert 30.

      The result is:

      [10, 20, 30, 40]

      We can remove and insert in the same operation:

      const names = ["Anu", "Rahul", "Meera"];

names.splice(1, 1, "Vikram");

      Now names is:

      ["Anu", "Vikram", "Meera"]

      splice changes the original array.

      Before using it, make sure that changing the array is what you intend.

      Try it#

      Start with:

      const numbers = [10, 20, 40, 50];

      Use splice to insert 30 in the correct position.

      Then remove 20 and 30 in a single operation.

      What does splice return when it removes them?

      Which APIs change the original array?#

      Let us put everything together:

      Answer every ? in the table below. For each API, decide whether it changes the original array and identify the value it returns.

      APIWhat it doesChanges the original array?What does it return?
      concatJoins arrays??
      includesChecks whether a value is present??
      indexOfFinds the first index of a value??
      reverseReverses the order of the elements??
      toReversedCreates a new array with the elements in reverse order??
      sliceCopies part or all of an array??
      spliceRemoves or inserts elements??

      The distinction matters whenever we need to keep the original data unchanged and if we sometimes want to use the value returned by the API.
