      Javascript, Arrays

      Arrays#

      So far, we have learned how to describe a thing using an object.

      const student = {
  name: "Anu",
  age: 20,
  city: "Chennai",
};

      This works very well when we have one thing.

      But what happens when we have many things?

      Suppose we have three students:

      const student1 = {
  name: "Anu",
  age: 20,
};

const student2 = {
  name: "Rahul",
  age: 19,
};

const student3 = {
  name: "Meera",
  age: 20,
};

      What if we have thirty students?

      What if we have three hundred?

      We could keep giving every student a different variable name. But something feels wrong about that.

      We don’t really want thirty different variables.

      We want to say:

      Here is a collection of students.

      JavaScript gives us a data structure for exactly this purpose.

      It is called an array.

      A collection of values#

      An array lets us put several values together.

      const numbers = [10, 20, 30, 40];

      We can think of this as a sequence of four values:

             0     1     2     3
     ┌─────┬─────┬─────┬─────┐
     │ 10  │ 20  │ 30  │ 40  │
     └─────┴─────┴─────┴─────┘

      The values are the elements of the array.

      The positions have names too.

      Those positions are called indices.

      Notice something interesting.

      The first position is 0, not 1.

      The second position is 1.

      The third position is 2.

      And so on.

      We call this zero-based indexing.

      Why might the first position be called zero?

      Think about an index as the number of steps we have moved from the beginning.

      The first element is zero steps from the beginning.

      The second element is one step from the beginning.

      The third element is two steps from the beginning.

      We don’t need to spend too much time worrying about why JavaScript chose this convention. What matters is that we understand it and use it consistently.

      Creating an array#

      We create an array using square brackets:

      const numbers = [10, 20, 30, 40];

      We can put strings in an array:

      const fruits = ["apple", "banana", "orange"];

      We can put booleans in one:

      const answers = [true, false, false, true];

      And, as we will see later, we can even put objects and other arrays inside an array.

      An empty array is simply:

      const numbers = [];

      There is nothing special about an empty array. It is simply an array containing zero elements.

      Try it#

      Create an array containing five numbers.

      Then create an array containing three names.

      How would you create an array containing no elements?

      Accessing an element#

      We use the index to access an element.

      const fruits = ["apple", "banana", "orange"];

fruits[0];

      The result is:

      "apple"

      What about:

      fruits[1];

      It is:

      "banana"

      And:

      fruits[2];

      is:

      "orange"

      So we can think of:

      fruits[1];

      as saying:

      Give me the element at index 1.

      The index is not part of the value. It is a way of locating the value.

      This is different from an object.

      With an object, we use a property name:

      student.name;

      With an array, we use an index:

      students[0];

      We will return to this difference later.

      Try it#

      Given:

      const numbers = [10, 20, 30, 40, 50];

      What is the value of:

      numbers[0];
numbers[2];
numbers[4];

      What about:

      numbers[5];

      Before running the code, make a prediction.

      Going out of bounds#

      Our array has five elements:

      const numbers = [10, 20, 30, 40, 50];

      The valid indices are:

      0  1  2  3  4

      There is no index 5.

      So what happens if we ask for it?

      numbers[5];

      We get:

      undefined

      We can think of this as asking:

      Is there an element at index 5?

      There isn’t.

      JavaScript does not throw an error simply because we tried to read an element that isn’t there. It gives us undefined.

      The same applies if we go in the other direction:

      numbers[-1];

      This does not mean “the last element”.

      It gives us undefined.

      We’ll see a more convenient way to ask for elements from the end shortly.

      For now, remember:

      An ordinary array index is a non-negative integer identifying a position in the array.

      How many elements?#

      How do we find out how many elements an array contains?

      We have already seen this idea with strings.

      const name = "Alice";

name.length;

      An array also has a length.

      const numbers = [10, 20, 30, 40, 50];

numbers.length;

      The result is:

      5

      This gives us an important relationship:

      length = 5

indices:
0  1  2  3  4

      The last valid index is therefore:

      numbers.length - 1;

      So:

      numbers[numbers.length - 1];

      gives us the last element.

      There is another useful way to write this.

      numbers.at(-1);

      at lets us use a negative index to count from the end.

      numbers.at(-1); // 50
numbers.at(-2); // 40
numbers.at(-3); // 30

      Notice the difference:

      numbers[-1]; // undefined
numbers.at(-1); // 50

      The two expressions are not the same thing.

      Try it#

      Given:

      const numbers = [10, 20, 30, 40, 50];

      Without running the program, predict the result of:

      numbers.length;
numbers[numbers.length - 1];
numbers.at(-1);
numbers.at(-2);
numbers.at(numbers.length);

      Changing an element#

      An array is not just something we can read from.

      We can also change an element.

      const numbers = [10, 20, 30];

numbers[1] = 200;

      Now the array is:

      [10, 200, 30]

      We used the index to say:

      Change the element at position 1.

      This is one of the ways an array differs from a string.

      Strings cannot be changed one character at a time in this way. Arrays can.

      There is an important question here.

      What happens if we have:

      const numbers = [10, 20, 30];

      and then do:

      numbers = [40, 50, 60];

      That is an error.

      numbers was declared with const, so we cannot make the variable refer to a different array.

      But this is perfectly fine:

      numbers[0] = 100;

      Why?

      Because we aren’t changing what numbers refers to.

      We are changing the array that numbers refers to.

      This is the same distinction we saw when we learned that objects are references.

      Arrays are references#

      Consider:

      const numbers = [10, 20, 30];

const otherNumbers = numbers;

      What does this mean?

      We haven’t created a second array.

      We now have two variables referring to the same array.

      We can picture it like this:

      numbers ────────┐
                │
                ▼
          ┌─────┬─────┬─────┐
          │ 10  │ 20  │ 30  │
          └─────┴─────┴─────┘
                ▲
                │
otherNumbers ───┘

      So:

      otherNumbers[0] = 100;

      changes the same array.

      Therefore:

      numbers[0];

      is also:

      100

      This should look familiar.

      We learned exactly the same idea with objects.

      An array is also an object in this sense: it is a value that we can have multiple references to.

      This is why we need to think carefully about changing arrays.

      Should we change an array?#

      Sometimes we should.

      Sometimes we shouldn’t.

      For example, suppose we have:

      const numbers = [10, 20, 30];

      We could change it:

      numbers[0] = 100;

      But we could also write a function that creates a new array instead of changing the old one.

      There are good reasons to prefer the second approach in many situations.

      If several variables refer to the same array, changing it means that all of those variables now observe the change.

      That can make a program harder to reason about.

      So, as a general habit, we will often prefer not to modify an array that was given to us.

      Instead, we can create and return a new array.

      This is a preference, not a law.

      There are many situations where modifying an existing array is useful or even necessary. When we deliberately use an array as changing state, mutation can be exactly what we want.

      For our exercises, when we say:

      Do not modify the input array

      we are asking you to leave the original array alone and produce a new result.

      Arrays and loops#

      Now we have a problem we can solve with something we already know.

      Suppose we have:

      const numbers = [10, 20, 30, 40, 50];

      We want to print every element.

      We could write:

      console.log(numbers[0]);
console.log(numbers[1]);
console.log(numbers[2]);
console.log(numbers[3]);
console.log(numbers[4]);

      But we already know how to avoid repeating ourselves.

      We know how to write loops.

      What changes as we move through the array?

      The index.

      So we can use a loop:

      for (let i = 0; i < numbers.length; i++) {
  console.log(numbers[i]);
}

      Look carefully at the condition:

      i < numbers.length;

      Suppose numbers.length is 5.

      Then i takes the values:

      0
1
2
3
4

      When i becomes 5, the condition is false.

      This is exactly what we want because 5 is not a valid index.

      This is one of the most important patterns when working with arrays:

      for (let i = 0; i < array.length; i++) {
  // array[i]
}

      We will use it repeatedly.

      Try it#

      Write a loop that prints:

      10
20
30
40
50

      Then change it so that it prints the elements in reverse order.

      What should the initial value of i be?

      What should the condition be?

      What should happen to i after every iteration?

      Changing the size of an array#

      So far, we have created arrays with a fixed set of elements.

      But an array can grow and shrink.

      We can add an element to the end using push:

      const numbers = [10, 20, 30];

numbers.push(40);

      Now:

      numbers;

      is:

      [10, 20, 30, 40]

      push changes the array.

      It adds an element at the end.

      We can remove the last element using pop:

      numbers.pop();

      Now we are back to:

      [10, 20, 30]

      There are corresponding operations at the beginning of the array.

      unshift adds an element at the beginning:

      numbers.unshift(5);

      giving:

      [5, 10, 20, 30]

      And shift removes the first element:

      numbers.shift();

      giving:

      [10, 20, 30]

      We can think about these four operations in terms of the ends of a sequence:

      unshift                         push
   ↓                             ↓
[ 10 ][ 20 ][ 30 ]
   ↑                             ↑
 shift                          pop

      There is also splice, which allows us to remove or insert elements at a particular position.

      For example:

      const numbers = [10, 20, 30, 40];

numbers.splice(1, 1);

      The first argument tells us where to start.

      The second tells us how many elements to remove.

      So the result is:

      [10, 30, 40]

      We can also insert elements.

      const numbers = [10, 20, 40];

numbers.splice(2, 0, 30);

      The result is:

      [10, 20, 30, 40]

      We won’t spend too much time on splice right now. The important thing is to understand that arrays represent a sequence and give us operations for changing that sequence.

      Try it#

      Start with:

      const numbers = [10, 20, 30];

      Using array operations, make it:

      [5, 10, 20, 30, 40]

      Then start with:

      const numbers = [10, 20, 30, 40, 50];

      Remove 30 from the array.

      Are two arrays equal?#

      Here is something that might surprise you.

      What do you think this produces?

      [1, 2, 3] === [1, 2, 3];

      It produces:

      false

      Why?

      Because we have created two different arrays.

      Remember that arrays are references.

      These two expressions create two separate objects:

      [1, 2, 3][(1, 2, 3)];

      They contain the same values, but they are not the same array.

      Compare that with:

      const a = [1, 2, 3];
const b = a;

a === b;

      This produces:

      true

      because a and b refer to the same array.

      This distinction is important.

      There are two different questions we might ask:

      Are these the same array?

      and:

      Do these two arrays contain the same elements?

      JavaScript’s === answers the first question.

      If we want to answer the second question, we need to write the logic ourselves.

      That is one of the things you will do in the exercises.

      Homogeneous and heterogeneous arrays#

      JavaScript does not require every element of an array to have the same type.

      This is completely legal:

      const things = [10, "hello", true, null];

      This is a heterogeneous array: its elements have different types.

      We can also have:

      const numbers = [10, 20, 30, 40];

      This is a homogeneous array: its elements all have the same type.

      Both are valid JavaScript.

      But ask yourself which is easier to work with.

      Suppose we have:

      const numbers = [10, 20, 30, 40];

      If we loop over the array, we know that every element is a number.

      We can confidently do things like:

      numbers[i] * 2;

      With:

      const things = [10, "hello", true, null];

      we have to think about what each element means and what operations are appropriate.

      So, in practice, we will often prefer homogeneous arrays.

      This is not a rule enforced by JavaScript.

      It is a design choice made by the programmer.

      A heterogeneous array can be useful when the different types have a deliberate meaning. But when a collection represents many things of the same kind, a homogeneous array is usually easier to understand.

      Arrays and objects#

      We now have two useful data structures.

      Objects and arrays.

      When should we use which?

      Consider this object:

      const student = {
  name: "Anu",
  age: 20,
  city: "Chennai",
};

      We are describing one student.

      The properties tell us different things about that student.

      student
 ├── name
 ├── age
 └── city

      Now consider:

      const students = ["Anu", "Rahul", "Meera"];

      We aren’t describing one student.

      We are describing a collection of students.

      students
 ├── 0 → "Anu"
 ├── 1 → "Rahul"
 └── 2 → "Meera"

      This gives us a useful rule of thumb:

      Objects describe the properties of a thing. Arrays describe a collection of things.

      The distinction becomes even clearer when we combine them.

      Arrays of objects#

      Suppose we want a collection of students, but we also want to store information about each student.

      We can put objects inside an array:

      const students = [
  {
    name: "Anu",
    age: 20,
  },
  {
    name: "Rahul",
    age: 19,
  },
  {
    name: "Meera",
    age: 20,
  },
];

      Now we can use an index to select a student:

      students[0];

      and then a property to select something about that student:

      students[0].name;

      So we can combine the two ways of organizing information:

      students
   │
   ├── [0] ──→ student object
   │             ├── name
   │             └── age
   │
   ├── [1] ──→ student object
   │             ├── name
   │             └── age
   │
   └── [2] ──→ student object
                 ├── name
                 └── age

      This is an extremely common pattern.

      We use an array when we have many things.

      We use an object when we need to describe one of those things.

      Try it#

      Given:

      const students = [
  { name: "Anu", marks: 80 },
  { name: "Rahul", marks: 65 },
  { name: "Meera", marks: 91 },
];

      Write a loop that prints the name of every student.

      Then write a loop that prints the names of students who scored more than 70.

      Notice how the array and the objects have different jobs.

      Nested arrays#

      An array can also contain other arrays.

      For example:

      const points = [
  [10, 20],
  [30, 40],
  [50, 60],
];

      Each element of points is itself an array.

      So:

      points[0];

      is:

      [10, 20]

      And:

      points[0][1];

      is:

      20

      We can read this as:

      Get element 0 from points, and then get element 1 from that array.

      We can use this to represent a two-dimensional structure.

      For example:

      const matrix = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];

      We can picture it as:

      ┌───┬───┬───┐
│ 1 │ 2 │ 3 │
├───┼───┼───┤
│ 4 │ 5 │ 6 │
├───┼───┼───┤
│ 7 │ 8 │ 9 │
└───┴───┴───┘

      To visit every number, we need one loop for the rows and another loop for the elements inside each row.

      for (let row = 0; row < matrix.length; row++) {
  for (let column = 0; column < matrix[row].length; column++) {
    console.log(matrix[row][column]);
  }
}

      Notice how naturally the loops correspond to the structure of the data.

      The outer loop moves through the arrays.

      The inner loop moves through the elements of each array.

      Try it#

      Given:

      const matrix = [
  [1, 2, 3],
  [4, 5, 6],
  [7, 8, 9],
];

      Write a program that calculates the sum of every number in the matrix.

      Then write one that prints the matrix row by row.

      Arrays are about collections#

      We have now seen several different ways of using arrays.

      We can have:

      const numbers = [10, 20, 30];

      An array of numbers.

      We can have:

      const names = ["Anu", "Rahul", "Meera"];

      An array of strings.

      We can have:

      const students = [
  { name: "Anu", age: 20 },
  { name: "Rahul", age: 19 },
];

      An array of objects.

      And we can have:

      const matrix = [
  [1, 2, 3],
  [4, 5, 6],
];

      An array of arrays.

      The common idea is not the type of the elements.

      The common idea is that we have a collection of values arranged in a sequence.

      Once we understand that idea, the JavaScript syntax becomes much easier to understand.

      One last thing#

      We have deliberately not learned many Array APIs yet.

      You may have seen code such as:

      numbers.map(...)
numbers.filter(...)
numbers.find(...)

      Don’t worry about those yet.

      For now, we want you to understand what is happening underneath.

      When you write:

      for (let i = 0; i < numbers.length; i++) {
  // ...
}

      you are working directly with the structure.

      You know where the elements are.

      You know how to access them.

      You know how to change them.

      You know how to add and remove them.

      You know how to move through them.

      That understanding is more important than knowing a collection of convenient functions.

      The APIs will come later.

      For now, we have learned how to work with collections.
