      Functions as Values

      November 18, 2026
      Javascript, Functions, Expressions

      Functions Are Values#

      So far, we have been writing functions like this:

      function add(x, y) {
  return x + y;
}

      And when we want to use the function, we write:

      const result = add(10, 20);

      This works perfectly well.

      But there is another way to write a function in JavaScript. Before we look at it, let’s revisit something we have already learned.

      Expressions produce values#

      We have spent quite some time working with expressions.

      Consider:

      const a = 10 + 20;

      JavaScript evaluates the expression 10 + 20. It produces the value 30, which is then associated with the name a.

      We can do the same thing with other expressions:

      const b = Math.sqrt(25);
const c = 10 > 5;
const d = "Hello";

      In each case, the expression on the right produces a value.

      We have also seen that we can give these values names using const.

      Now consider this:

      const add = function (x, y) {
  return x + y;
};

      This might look a little strange.

      But look carefully.

      The expression on the right is:

      function(x, y) {
    return x + y;
}

      This is a function expression.

      Just like 10 + 20 produces the value 30, this expression produces a function.

      We have given that function a name by associating it with the variable add.

      So now we can write:

      const result = add(10, 20);

      And we get:

      30

      Nothing about how the function works has changed.

      We have simply written it differently.

      Why const?#

      You might wonder why we are using const here.

      Why not let?

      Remember the difference:

      • const creates a variable that cannot be reassigned.
      • let creates a variable that can be reassigned.

      Consider:

      let score = 10;
score = 20;

      This is perfectly fine. We expect the score to change.

      But do we expect add to suddenly refer to a different function?

      Probably not.

      Once we have created our add function, we want add to continue referring to that same function.

      We have no intention of reassigning it.

      Therefore:

      const add = function (x, y) {
  return x + y;
};

      is the appropriate choice.

      This is the same principle we have been following throughout our JavaScript programs:

      Prefer const unless you have a reason to reassign a variable.

      One small distinction is worth remembering.

      const prevents us from reassigning the variable add. It does not mean that the function itself is somehow frozen or cannot execute.

      Does the order matter?#

      There is another interesting difference between the two ways of writing functions.

      Consider this program:

      console.log(add(10, 20));

function add(x, y) {
  return x + y;
}

      Run it.

      You will get:

      30

      Notice something?

      We are calling add before we have written its definition!

      JavaScript allows this when we use a function declaration.

      Now try the same thing using our new syntax:

      console.log(add(10, 20));

const add = function (x, y) {
  return x + y;
};

      Run it.

      You will get an error.

      Why?

      When JavaScript reaches:

      console.log(add(10, 20));

      it tries to use add.

      But we haven’t reached the statement that creates add yet.

      The variable has not been initialized.

      This is an important difference.

      With function declarations, JavaScript allows us to use the function before its definition appears in the program.

      With a function expression assigned to const, we must initialize the variable before we use it.

      So this works:

      const add = function (x, y) {
  return x + y;
};

console.log(add(10, 20));

      And this does not:

      console.log(add(10, 20));

const add = function (x, y) {
  return x + y;
};

      This gives us a useful habit.

      Write things before you use them.

      When a function depends on another function, put the definition of the dependency first.

      Your programs will become easier to read because the order in which things are introduced will follow the order in which they are needed.

      Two ways of writing the same function#

      Let’s put the two forms side by side.

      Function declaration:

      function multiply(x, y) {
  return x * y;
}

      Function expression:

      const multiply = function (x, y) {
  return x * y;
};

      Both create a function that multiplies two numbers.

      Both can be called like this:

      multiply(5, 6);

      The difference is in how the function is introduced into the program.

      In the first case, we declare a function.

      In the second case, we evaluate a function expression and associate the resulting value with a variable.

      From now on, we will use the second form when writing our functions.

      Try this#

      Create a file called functions.js.

      Write the following program:

      const add = function (x, y) {
  return x + y;
};

const subtract = function (x, y) {
  return x - y;
};

const multiply = function (x, y) {
  return x * y;
};

const a = add(10, 20);
const b = subtract(50, 10);
const c = multiply(5, 6);

console.log(a);
console.log(b);
console.log(c);

      Run it.

      Now try moving the const multiply declaration below the line that calls it.

      What happens?

      Move it back.

      Try moving the const subtract declaration below the line that calls it.

      What happens?

      Pay attention to the order in which things are written.

      What have we added to our mental model?#

      We have already learned that expressions produce values.

      We have learned that variables give names to values.

      And now we have seen that a function can also be a value.

      There is nothing particularly mysterious about this.

      A function is something JavaScript can create, and a variable can refer to that function.

      We will build on this idea as we continue learning JavaScript.

      For now, get comfortable writing your functions this way:

      const myFunction = function () {
  // ...
};

      This is going to become an important part of how we write JavaScript.
