      Destructuring

      November 18, 2026
      Javascript, Destructuring, Arrays, Objects

      Taking Things Apart#

      We have spent a lot of time putting values together.

      We have built arrays:

      const scores = [90, 75, 60];

      And we have built objects:

      const person = { name: "Asha", age: 24, city: "Pune" };

      Very often, we then want to take those values back out.

      const first = scores[0];
const second = scores[1];
const third = scores[2];
      const name = person.name;
const age = person.age;
const city = person.city;

      This works perfectly well.

      But look at it carefully. We are repeating ourselves.

      scores appears three times. person appears three times. The words name, age and city each appear twice on the same line.

      JavaScript gives us a shorter way to write this. It is called destructuring.

      To destructure something is to take its structure apart and give names to the pieces.

      Destructuring Arrays#

      Consider:

      const scores = [90, 75, 60];

const [first, second, third] = scores;

console.log(first);
console.log(second);
console.log(third);

      Run it.

      You will get:

      90
75
60

      Look at the left-hand side of the =:

      const [first, second, third]

      This looks like an array, but it isn’t creating one.

      It is a pattern. It describes the shape we expect on the right-hand side, and tells JavaScript which names to give to each position.

      • first is given the element at index 0
      • second is given the element at index 1
      • third is given the element at index 2

      So this:

      const [first, second, third] = scores;

      means exactly the same as this:

      const first = scores[0];
const second = scores[1];
const third = scores[2];

      For arrays, position is what matters. The names can be anything we like.

      const [gold, silver, bronze] = scores;

      gold is 90, silver is 75 and bronze is 60.

      Fewer names than elements#

      What if we only care about the first two?

      const scores = [90, 75, 60];

const [first, second] = scores;

console.log(first);
console.log(second);
      90
75

      The remaining elements are simply ignored. The array is not changed.

      More names than elements#

      What if we ask for more than the array has?

      const scores = [90, 75];

const [first, second, third] = scores;

console.log(third);
      undefined

      Remember what happens when we go out of bounds:

      scores[2]; // undefined

      Destructuring behaves in exactly the same way. There is no element at index 2, so third is undefined.

      Skipping elements#

      What if we want the first and the third, but not the second?

      We leave a gap:

      const scores = [90, 75, 60];

const [first, , third] = scores;

console.log(first);
console.log(third);
      90
60

      The empty space between the two commas means “there is an element here, but I don’t need a name for it”.

      Use this sparingly. One gap is easy to read. Three gaps in a row is not.

      Destructuring Objects#

      Now let’s take apart an object.

      const person = { name: "Asha", age: 24, city: "Pune" };

const { name, age } = person;

console.log(name);
console.log(age);

      Run it.

      Asha
24

      This time the pattern uses curly braces: { name, age }.

      And this time, position does not matter. Names do.

      JavaScript looks for a property called name in person and creates a variable called name with that value. Then it does the same for age.

      So this:

      const { name, age } = person;

      means exactly the same as this:

      const name = person.name;
const age = person.age;

      Because it uses names and not positions, the order inside the braces does not matter:

      const { age, name } = person;

      This gives exactly the same result.

      Missing properties#

      What if we ask for a property that does not exist?

      const person = { name: "Asha", age: 24 };

const { email } = person;

console.log(email);
      undefined

      Again, nothing new. We already know:

      person.email; // undefined

      Destructuring follows the same rule.

      Arrays use positions, objects use names#

      This is the most important thing to remember about destructuring, so let’s put it side by side.

      const scores = [90, 75, 60];
const [a, b] = scores; // a is 90, b is 75 — chosen by position

      const person = { name: "Asha", age: 24 };
const { age, name } = person; // chosen by name, order doesn't matter

      What do you think happens here?

      const person = { name: "Asha", age: 24 };
const { a, b } = person;

      Try it and see. Can you explain the output?

      Renaming#

      Sometimes the property name is not the name we want for our variable.

      Perhaps the name is already taken:

      const name = "Library";

const book = { name: "The Hobbit", author: "Tolkien" };

const { name } = book; // Error!

      Run it.

      You will get an error saying that name has already been declared.

      We cannot have two variables called name in the same scope. So we tell JavaScript to give the property a different name:

      const name = "Library";

const book = { name: "The Hobbit", author: "Tolkien" };

const { name: bookName } = book;

console.log(name);
console.log(bookName);
      Library
The Hobbit

      Read name: bookName as:

      Take the property name, and call it bookName.

      The left side of the colon is the property we are looking for. The right side is the new variable we are creating.

      This catches many people out, so let’s be clear about it. After this line:

      const { name: bookName } = book;

      there is a variable called bookName.

      There is no new variable called name. name was only used to find the property.

      Default Values#

      A missing property gives us undefined. We can provide a value to use instead:

      const settings = { theme: "dark" };

const { theme, fontSize = 14 } = settings;

console.log(fontSize);
      14

      If settings had a fontSize, that value would be used instead. Defaults work for arrays too: const [first, second = 0] = [5];

      The default is used only when the value is undefined. Even 0 or null is kept as it is.

      Nested Destructuring#

      Objects can contain objects. Arrays can contain arrays.

      Patterns can be nested in the same way.

      const person = {
  name: "Asha",
  address: {
    city: "Pune",
    pin: "411001",
  },
};

const {
  name,
  address: { city },
} = person;

console.log(name);
console.log(city);
      Asha
Pune

      Read the pattern from the outside in.

      • name — take the property name from person
      • address: { city } — go into the property address, and from that object take city

      Notice the colon again. Just as with renaming, the left side of the colon is the property we are looking for. This time, the right side is not a new name. It is another pattern.

      So, in this example, address is not a variable:

      console.log(address); // Error!

      address was only used to find our way to city.

      If you want both, ask for both:

      const { address, address: { city } } = person;

      Arrays nest in the same way:

      const grid = [
  [1, 2],
  [3, 4],
];

const [[a, b], [c, d]] = grid;

console.log(a, b, c, d);
      1 2 3 4

      And we can mix them:

      const team = {
  name: "Falcons",
  players: ["Ravi", "Meera", "Imran"],
};

const {
  players: [captain],
} = team;

console.log(captain);
      Ravi

      A word of caution#

      Nested destructuring is powerful, but it can quickly become hard to read.

      const {
  a: {
    b: [, { c }],
  },
} = data;

      Can you tell what this does at a glance? Neither can most people.

      If a pattern is more than one level deep, consider splitting it into two steps:

      const { address } = person;
const { city, pin } = address;

      Clear code is better than short code.

      Also, if the outer property is missing, nested destructuring will fail:

      const person = { name: "Asha" };

const {
  address: { city },
} = person; // Error!

      person.address is undefined, and JavaScript cannot look for city inside undefined.

      This is the same error you would get from writing person.address.city.

      Destructuring in Function Parameters#

      Do you remember that a function’s parameters are just variables that are given values when the function is called?

      const describe = function (person) {
  return person.name + " is " + person.age + " years old";
};

      When we call describe(asha), it is as if JavaScript wrote:

      const person = asha;

      So anywhere we can write const person = ..., we can use a pattern instead.

      const describe = function ({ name, age }) {
  return name + " is " + age + " years old";
};

const asha = { name: "Asha", age: 24, city: "Pune" };

console.log(describe(asha));
      Asha is 24 years old

      When describe(asha) is called, it is as if JavaScript wrote:

      const { name, age } = asha;

      This has a nice side effect. Just by reading the first line of the function, we can see which properties it uses.

      Defaults work here too:

      const greet = function ({ name, greeting = "Hello" }) {
  return greeting + ", " + name + "!";
};

greet({ name: "Asha" }); // "Hello, Asha!"

      Array patterns work too:

      const distance = function ([x1, y1], [x2, y2]) {
  return Math.sqrt((x2 - x1) ** 2 + (y2 - y1) ** 2);
};

console.log(distance([0, 0], [3, 4]));
      5

      Destructuring what a function returns#

      Functions can only return one value. But that value can be an array or an object.

      const minAndMax = function (numbers) {
  let min = numbers[0];
  let max = numbers[0];

  for (const number of numbers) {
    if (number < min) {
      min = number;
    }
    if (number > max) {
      max = number;
    }
  }

  return { min, max };
};

const { min, max } = minAndMax([4, 9, 1, 7]);

console.log(min);
console.log(max);
      1
9

      Notice return { min, max };. This is a shorthand for:

      return { min: min, max: max };

      When a property has the same name as the variable holding its value, we can write it once.

      It is the mirror image of destructuring. const { min, max } = ... takes an object apart; { min, max } puts one together.

      Destructuring in loops#

      Each element that Object.entries gives us is a [key, value] array, so we can take it apart right in the loop:

      const prices = { tea: 20, coffee: 35 };

for (const [item, price] of Object.entries(prices)) {
  console.log(item + " costs " + price);
}
      tea costs 20
coffee costs 35

      item and price say far more than entry[0] and entry[1].

      What have we added to our mental model?#

      We already knew how to put values into arrays and objects.

      Now we have a tidy way to take them out again.

      • Arrays are destructured by position.
      • Objects are destructured by name.
      • We can rename (name: newName), provide defaults (size = 14), and reach into nested structures.
      • Anywhere we create a variable, including parameters and for...of loops, we can use a pattern.

      None of this lets us do anything we couldn’t do before. Everything here could be written with indexes and dots.

      What it gives us is code that says what it means.

      Use destructuring when it makes your code clearer. Don’t use it just because you can.

      Exercises#

      For each “predict the output” exercise, write down your answer before running the code.

      1. Predict the output#

      const [a, b, c] = [10, 20];
console.log(a, b, c);

      2. Predict the output#

      const [, second, , fourth] = ["w", "x", "y", "z"];
console.log(second, fourth);

      3. Predict the output#

      const { b, a } = { a: 1, b: 2 };
console.log(a, b);

      4. Why doesn’t this work?#

      const point = { x: 3, y: 4 };
const [x, y] = point;
console.log(x, y);

      Run it. Read the error. Fix it.

      5. Renaming#

      const { title: heading } = { title: "Welcome" };
console.log(heading);
console.log(title);

      What happens on each line? Why?

      6. Defaults#

      Predict the output:

      const { a = 1, b = 2, c = 3, d = 4 } = { a: 10, b: undefined, c: null, d: 0 };
console.log(a, b, c, d);

      7. Nested#

      const company = {
  name: "Acme",
  ceo: { name: "Meera", joined: 2015 },
  offices: ["Pune", "Bengaluru", "Delhi"],
};

      Using a single destructuring statement, create three variables:

      • companyName with the value "Acme"
      • ceoName with the value "Meera"
      • headOffice with the value "Pune"

      Then do it again using three separate statements. Which version do you prefer?

      8. Destructuring parameters#

      Rewrite this function so that it uses destructuring in its parameter list:

      const formatAddress = function (address) {
  return address.street + ", " + address.city + " - " + address.pin;
};

      9. Default parameters#

      Write a function createUser that takes an object with name, role and active properties and returns a sentence describing the user.

      If role is missing, use "intern". If active is missing, use true.

      // createUser({ name: "Asha" })
//   => "Asha is an active intern"
// createUser({ name: "Ravi", role: "mentor", active: false })
//   => "Ravi is an inactive mentor"

      10. Return multiple values#

      Write a function divide that takes two numbers and returns an object with quotient and remainder.

      Use destructuring to call it:

      const { quotient, remainder } = divide(17, 5);
// quotient => 3, remainder => 2

      11. Entries#

      const stock = { pens: 40, pencils: 0, erasers: 12, notebooks: 0 };

      Using Object.entries, for...of and destructuring, print the name of every item that is out of stock.
