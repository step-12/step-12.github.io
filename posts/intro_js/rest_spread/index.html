      Rest and Spread

      November 18, 2026
      Javascript, Rest, Spread, Arrays, Objects, Functions

      Three Dots#

      In Destructuring, we learned how to take values out of arrays and objects and give them names.

      In this post we will learn two related ideas:

      • Rest — collecting the “remaining” values together
      • Spread — expanding the values of an array or object into another place

      Both use the same three dots: .... We will see why that is less confusing than it sounds.

      Rest: Collecting What’s Left#

      Let’s start with arrays.

      const runners = ["Asha", "Ravi", "Meera", "Imran", "Kiran"];

      We want the winner in one variable, and everyone else in another.

      const [winner, ...others] = runners;

console.log(winner);
console.log(others);
      Asha
[ 'Ravi', 'Meera', 'Imran', 'Kiran' ]

      ...others means:

      Collect all the remaining elements into a new array called others.

      This is called a rest element. It gathers “the rest”.

      others is always an array, even if there is only one element left, or none:

      const [a, ...remaining] = [1];

console.log(remaining);
      []

      The rest element must come last. It collects everything that is left over, so nothing can come after it.

      const [...everyoneElse, last] = runners; // SyntaxError

      Rest with objects#

      Rest works with objects too.

      const user = { id: 7, name: "Asha", email: "asha@example.com", city: "Pune" };

const { id, ...details } = user;

console.log(id);
console.log(details);
      7
{ name: 'Asha', email: 'asha@example.com', city: 'Pune' }

      details is a new object containing every property we didn’t ask for by name.

      This is a handy way of saying “everything except id”.

      The original user object is not changed:

      console.log(user);
      { id: 7, name: 'Asha', email: 'asha@example.com', city: 'Pune' }

      Rest parameters#

      Since parameters are just patterns, rest works in parameter lists too.

      Suppose we want a sum function that works with any number of arguments:

      sum(1, 2);
sum(1, 2, 3);
sum(5, 10, 15, 20);

      We don’t know how many parameters to write.

      So we collect them all:

      const sum = function (...numbers) {
  let total = 0;

  for (const number of numbers) {
    total = total + number;
  }

  return total;
};

console.log(sum(1, 2));
console.log(sum(1, 2, 3));
console.log(sum(5, 10, 15, 20));
console.log(sum());
      3
6
50
0

      Inside the function, numbers is an ordinary array. Every argument we passed ends up in it.

      When we call sum() with no arguments, numbers is an empty array, the loop doesn’t run, and we return 0.

      We can mix ordinary parameters with a rest parameter. The rest parameter must come last:

      const introduce = function (host, ...guests) {
  return host + " welcomes " + guests.length + " guests";
};

console.log(introduce("Asha", "Ravi", "Meera", "Imran"));
      Asha welcomes 3 guests

      host gets the first argument. guests collects everything after it.

      You have already used a function that works like this.

      Math.max(2, 5);
Math.max(10, 3, 7);

      Math.max accepts any number of arguments. Now you know how you could write a function like that yourself.

      Try it#

      1. Destructure [10, 20, 30, 40] into first and rest. Print both.
      2. From { a: 1, b: 2, c: 3 }, take out a and collect everything else into others.
      3. Write a function average that accepts any number of arguments and returns their average. What should average() return?

      Spread: Expanding Values#

      Rest collects many values into one array.

      Spread does the opposite. It takes an array and expands it into individual values.

      It uses exactly the same three dots.

      Spreading into a function call#

      We know that Math.max takes separate arguments:

      Math.max(4, 9, 1, 7); // 9

      But what if our numbers are in an array?

      const numbers = [4, 9, 1, 7];

Math.max(numbers); // NaN

      Math.max does not want an array. It wants separate numbers.

      So we spread the array:

      const numbers = [4, 9, 1, 7];

console.log(Math.max(...numbers));
      9

      Math.max(...numbers) means exactly the same as:

      Math.max(numbers[0], numbers[1], numbers[2], numbers[3]);

      The array is expanded, and each element becomes a separate argument.

      This works with any function, including our own:

      const add = function (x, y) {
  return x + y;
};

const pair = [10, 20];

console.log(add(...pair));
      30

      Spreading into an array#

      We can also spread an array inside another array literal.

      const fruits = ["apple", "banana"];
const vegetables = ["carrot", "pea"];

const food = [...fruits, ...vegetables];

console.log(food);
      [ 'apple', 'banana', 'carrot', 'pea' ]

      In More Array APIs, we did this with concat:

      const food = fruits.concat(vegetables);

      Spread lets us do the same thing, but we can also put other values wherever we like:

      const food = ["bread", ...fruits, "rice", ...vegetables, "milk"];
      [ 'bread', 'apple', 'banana', 'rice', 'carrot', 'pea', 'milk' ]

      Copying an array#

      In Arrays, we learned that arrays are references:

      const original = [1, 2, 3];
const same = original;

same.push(4);

console.log(original);
      [ 1, 2, 3, 4 ]

      same and original refer to the same array.

      We also saw that slice() gives us a new array. Spread does too:

      const original = [1, 2, 3];
const copy = [...original];

copy.push(4);

console.log(original);
console.log(copy);
console.log(original === copy);
      [ 1, 2, 3 ]
[ 1, 2, 3, 4 ]
false

      [...original] builds a brand new array and fills it with the elements of original.

      Adding to an array without changing it#

      Our style guide says that a function should not modify its arguments.

      Suppose we want a function that adds an item to a list:

      const addItem = function (list, item) {
  list.push(item);
  return list;
};

      This changes the array we were given. Whoever called addItem might be surprised.

      With spread, we can return a new array instead:

      const addItem = function (list, item) {
  return [...list, item];
};

const groceries = ["milk", "eggs"];
const updated = addItem(groceries, "bread");

console.log(groceries);
console.log(updated);
      [ 'milk', 'eggs' ]
[ 'milk', 'eggs', 'bread' ]

      groceries is untouched.

      Spreading a string#

      We saw in Iterating over Objects that for...of can visit each character of a string.

      Spread works on anything that for...of works on. So:

      const letters = [..."hello"];

console.log(letters);
      [ 'h', 'e', 'l', 'l', 'o' ]

      Try it#

      1. Given const a = [1, 2] and const b = [3, 4], create [0, 1, 2, 3, 4, 5] using spread.
      2. Find the smallest number in [8, 3, 12, 5] using Math.min and spread.
      3. Make a copy of an array. Change the copy. Check that the original did not change.
      4. What does Math.max(...[]) return? Why do you think that is?

      Spreading Objects#

      Spread also works inside object literals.

      const person = { name: "Asha", age: 24 };

const copy = { ...person };

console.log(copy);
console.log(copy === person);
      { name: 'Asha', age: 24 }
false

      { ...person } creates a new object and copies every property of person into it.

      Combining objects#

      const basics = { name: "Asha", age: 24 };
const contact = { email: "asha@example.com", city: "Pune" };

const profile = { ...basics, ...contact };

console.log(profile);
      { name: 'Asha', age: 24, email: 'asha@example.com', city: 'Pune' }

      When properties clash#

      What if both objects have the same property?

      const defaults = { theme: "light", fontSize: 14, language: "en" };
const choices = { theme: "dark" };

const settings = { ...defaults, ...choices };

console.log(settings);
      { theme: 'dark', fontSize: 14, language: 'en' }

      JavaScript builds the new object from left to right.

      First it copies everything from defaults. Then it copies everything from choices. When it reaches theme the second time, it simply replaces the earlier value.

      The last one wins.

      So the order matters. What happens if we swap them?

      const settings = { ...choices, ...defaults };

      Try it. Can you explain the result?

      Updating an object without changing it#

      Just as with arrays, we can use spread to return a changed copy instead of modifying an object.

      In Objects part 2, we saw functions that changed the object they were given:

      const birthday = function (person) {
  person.age = person.age + 1;
  return person;
};

      Here is a version that leaves the original alone:

      const birthday = function (person) {
  return { ...person, age: person.age + 1 };
};

const asha = { name: "Asha", age: 24 };
const older = birthday(asha);

console.log(asha);
console.log(older);
      { name: 'Asha', age: 24 }
{ name: 'Asha', age: 25 }

      Read { ...person, age: person.age + 1 } as:

      A new object with everything from person, but with a different age.

      Because age comes after ...person, our new value wins.

      What happens if we write it the other way round?

      return { age: person.age + 1, ...person };

      Try it#

      1. Copy { x: 1, y: 2 } using spread. Change x in the copy. Check the original.
      2. Combine { a: 1 }, { b: 2 } and { c: 3 } into one object.
      3. Write a function rename that takes a person object and a new name, and returns a new object with the name changed. The original must not change.

      Rest or Spread?#

      Both use .... How do we tell them apart?

      Look at where the dots appear.

      Rest collects. It appears where we are receiving values: on the left of = in a destructuring pattern, or in a function’s parameter list.

      const [first, ...others] = runners; // collects into others
const { id, ...details } = user; // collects into details
const sum = function (...numbers) {}; // collects arguments into numbers

      Spread expands. It appears where we are producing values: inside an array literal, an object literal, or a function call.

      const all = [...fruits, ...vegetables]; // expands into a new array
const copy = { ...person }; // expands into a new object
Math.max(...numbers); // expands into arguments

      One way to remember it:

      Rest gathers many values into one. Spread scatters one into many.

      They are two sides of the same idea:

      const sum = function (...numbers) {
  // rest: many arguments → one array
  let total = 0;
  for (const number of numbers) {
    total = total + number;
  }
  return total;
};

const values = [1, 2, 3, 4];

console.log(sum(...values)); // spread: one array → many arguments

      What have we added to our mental model?#

      • Rest (...) collects the remaining values into a new array or object. It appears where values are received: in a destructuring pattern or a parameter list.
      • Spread (...) expands an array or object into individual values. It appears where values are produced: in an array literal, an object literal or a function call.
      • Spread is a convenient way to copy, combine and update arrays and objects without changing the original.

      Use these tools when they make your code clearer. Don’t use them just because you can.

      Exercises#

      For each “predict the output” exercise, write down your answer before running the code.

      1. Head and tail#

      Write a function headAndTail that takes an array and returns an object with head (the first element) and tail (an array of everything else).

      // headAndTail([1, 2, 3, 4]) => { head: 1, tail: [2, 3, 4] }
// headAndTail([1]) => { head: 1, tail: [] }

      Use rest destructuring.

      2. Without a property#

      Write a function withoutPassword that takes a user object and returns a new object with every property except password.

      // withoutPassword({ name: "Asha", password: "secret", city: "Pune" })
//   => { name: 'Asha', city: 'Pune' }

      The original object must not change.

      3. Any number of arguments#

      Write a function longest that accepts any number of strings and returns the longest one.

      // longest("tea", "coffee", "juice") => "coffee"
// longest("a") => "a"

      Then, given:

      const words = ["apple", "fig", "banana", "kiwi"];

      call longest with the words in this array.

      4. Rest or spread?#

      For each ... below, say whether it is rest or spread:

      const [first, ...others] = list;
const merged = [...a, ...b];
const log = function (label, ...values) {};
log("total", ...numbers);
const { id, ...data } = record;
const updated = { ...record, status: "done" };

      5. Don’t change the original#

      Each of these functions modifies its argument. Rewrite each one so that it returns a new value and leaves the argument unchanged.

      const addToFront = function (list, item) {
  list.unshift(item);
  return list;
};

const markDone = function (task) {
  task.done = true;
  return task;
};

      6. Merge order#

      Predict the output:

      const a = { x: 1, y: 2 };
const b = { y: 20, z: 30 };

console.log({ ...a, ...b });
console.log({ ...b, ...a });
console.log({ ...a, y: 100, ...b });
console.log({ ...a, ...b, y: 100 });

      One last question#

      Look back at the functions you wrote for Arrays and More Array APIs.

      Find two functions that modify their arguments. Rewrite them using spread so that they return a new value instead.
