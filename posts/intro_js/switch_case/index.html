      Switch Case

      October 9, 2026
      Javascript, Switch/Case, Conditions

      Switch / Case#

      So far, we have used if and else to make decisions in our programs.

      For example:

      const day = 3;

if (day === 1) {
  console.log("Monday");
} else if (day === 2) {
  console.log("Tuesday");
} else if (day === 3) {
  console.log("Wednesday");
} else if (day === 4) {
  console.log("Thursday");
} else if (day === 5) {
  console.log("Friday");
}

      There is nothing wrong with this program.

      But look at what we are doing.

      We keep asking the same kind of question:

      Is day equal to this particular value?

      First:

      day === 1

      Then:

      day === 2

      Then:

      day === 3

      And so on.

      What if JavaScript gave us a construct specifically for this situation?

      switch#

      JavaScript does.

      It is called switch.

      Here is the same program written using switch:

      const day = 3;

switch (day) {
  case 1:
    console.log("Monday");
    break;

  case 2:
    console.log("Tuesday");
    break;

  case 3:
    console.log("Wednesday");
    break;

  case 4:
    console.log("Thursday");
    break;

  case 5:
    console.log("Friday");
    break;
}

      There are some new words here:

      • switch
      • case
      • break

      Let’s figure out what they mean.

      How does switch choose?#

      Look at this program:

      const x = 2;

switch (x) {
  case 1:
    console.log("one");
    break;

  case 2:
    console.log("two");
    break;

  case 3:
    console.log("three");
    break;
}

      What will it print?

      The expression inside switch is:

      x

      The value of x is 2.

      JavaScript then looks at the cases:

      case 1:

      Does x match 1?

      No.

      Then:

      case 2:

      Does x match 2?

      Yes.

      So JavaScript executes the statements belonging to that case:

      console.log("two");

      The basic mental model is:

      Evaluate the expression in switch, then find the matching case.

      Consider another example:

      const x = 3;

switch (x) {
  case 1:
    console.log("one");
    break;

  case 2:
    console.log("two");
    break;

  case 3:
    console.log("three");
    break;
}

      Which console.log runs?

      Try to predict the answer before running it.

      What is break?#

      You may have noticed something strange.

      Why do we keep writing this?

      break;

      Consider this program:

      const x = 2;

switch (x) {
  case 1:
    console.log("one");

  case 2:
    console.log("two");

  case 3:
    console.log("three");
}

      What do you think this prints?

      Run it.

      You might have expected only:

      two

      But that isn’t what happens.

      Once JavaScript finds a matching case, it starts executing from there.

      It doesn’t automatically stop at the end of that case.

      So the program prints:

      two
three

      This behavior is called fall-through.

      break tells JavaScript:

      Stop executing this switch.

      So:

      const x = 2;

switch (x) {
  case 1:
    console.log("one");
    break;

  case 2:
    console.log("two");
    break;

  case 3:
    console.log("three");
    break;
}

      prints only:

      two

      because after printing "two", the break exits the switch.

      Falling through on purpose#

      Fall-through is not always a mistake.

      Sometimes we actually want several cases to do the same thing.

      Suppose we want to print whether a day is a weekday or a weekend.

      We could write:

      const day = 6;

switch (day) {
  case 1:
    console.log("weekday");
    break;

  case 2:
    console.log("weekday");
    break;

  case 3:
    console.log("weekday");
    break;

  case 4:
    console.log("weekday");
    break;

  case 5:
    console.log("weekday");
    break;

  case 6:
    console.log("weekend");
    break;

  case 7:
    console.log("weekend");
    break;
}

      But notice that cases 6 and 7 want to do exactly the same thing.

      We can make use of fall-through:

      const day = 6;

switch (day) {
  case 1:
  case 2:
  case 3:
  case 4:
  case 5:
    console.log("weekday");
    break;

  case 6:
  case 7:
    console.log("weekend");
    break;
}

      There is no code after case 1, case 2, and so on.

      JavaScript simply continues until it reaches the code for the group.

      This is one of the useful things about switch.

      What if nothing matches?#

      Consider:

      const day = 9;

switch (day) {
  case 1:
    console.log("Monday");
    break;

  case 2:
    console.log("Tuesday");
    break;

  case 3:
    console.log("Wednesday");
    break;
}

      What happens?

      There is no matching case.

      So none of the statements inside the cases are executed.

      But sometimes we want to handle this situation.

      For example:

      const day = 9;

switch (day) {
  case 1:
    console.log("Monday");
    break;

  case 2:
    console.log("Tuesday");
    break;

  case 3:
    console.log("Wednesday");
    break;

  default:
    console.log("Unknown day");
}

      default is used when no case matches.

      It is similar to the final else in an if/else if chain.

      For example:

      if (day === 1) {
  console.log("Monday");
} else if (day === 2) {
  console.log("Tuesday");
} else if (day === 3) {
  console.log("Wednesday");
} else {
  console.log("Unknown day");
}

      and:

      switch (day) {
  case 1:
    console.log("Monday");
    break;

  case 2:
    console.log("Tuesday");
    break;

  case 3:
    console.log("Wednesday");
    break;

  default:
    console.log("Unknown day");
}

      express similar ideas.

      switch or if?#

      Does this mean we should always use switch instead of if?

      No.

      Consider this:

      if (age < 18) {
  console.log("child");
} else {
  console.log("adult");
}

      Could we replace this with:

      switch (age) {
  ...
}

      Not naturally.

      The condition here isn’t asking:

      Is age one of these particular values?

      It is asking:

      Is age less than 18?

      if is much better suited to this.

      switch is particularly useful when we have one value and several specific possibilities.

      For example:

      switch (command) {
  case "start":
    ...
    break;

  case "stop":
    ...
    break;

  case "pause":
    ...
    break;
}

      We are asking:

      Which of these values is command?

      On the other hand, if is useful when our questions are more general:

      if (score >= 90) {
  ...
} else if (score >= 70) {
  ...
} else {
  ...
}

      There is no need to force one construct into the job of the other.

      A mental model#

      Keep the following picture in your head:

      switch (value) {
  case possibleValue1:
    // do something
    break;

  case possibleValue2:
    // do something else
    break;

  default:
    // nothing matched
}

      The process is:

      1. Evaluate value.
      2. Look for a matching case.
      3. Start executing from that case.
      4. Continue until a break or the end of the switch.
      5. If no case matches, execute default, if there is one.

      The important thing to remember is that break is what stops execution from falling into the next case.

      Exercises#

      1. Day of the week#

      Write a program called day.js.

      Create a day variable containing a number from 1 to 7.

      Use switch to print the corresponding day:

      1 → Monday
2 → Tuesday
3 → Wednesday
...
7 → Sunday

      If the number isn’t between 1 and 7, print:

      Invalid day

      Do not use if or else.

      2. Weekday or weekend#

      Write a program called weekday.js.

      Given a number from 1 to 7, print either:

      weekday

      or:

      weekend

      Use switch.

      Try to avoid repeating the console.log statement for every day.

      3. Predict the output#

      Without running the following program, write down exactly what it will print:

      const x = 2;

switch (x) {
  case 1:
    console.log("A");

  case 2:
    console.log("B");

  case 3:
    console.log("C");
    break;

  case 4:
    console.log("D");
}

      Then run it.

      Explain why it prints what it prints.

      4. What does break change?#

      Take your solution from exercise 3.

      Add break statements in different places.

      For each version, predict the output before running it.

      Try to construct a version that prints:

      B
C

      and another that prints only:

      B

      5. A simple calculator#

      Write a program called calculator.js.

      Create three variables:

      const a = 10;
const b = 5;
const operation = "+";

      Use switch on operation.

      Support:

      +  → addition
-  → subtraction
*  → multiplication
/  → division

      For the example above, the program should print:

      15

      If the operation is anything else, print:

      Unknown operation

      Do not use if or else.

      6. One more question#

      Look at this:

      const x = 2;

switch (x) {
  case 1:
    console.log("one");
    break;

  case 2:
    console.log("two");

  case 3:
    console.log("three");
    break;

  default:
    console.log("default");
}

      What will this print?

      In particular:

      Will default execute? Why or why not?

      Write down your answer before running the program.
