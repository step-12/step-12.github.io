    Intro to JS part 2

    September 16, 2026

    Strings can have properties#

    Try:

    "Hello".length;

    You should get:

    5

    What do you think happened?

    "Hello" is a string.

    .length asks about something associated with that string.

    Try:

    "".length;
    "Hello World".length;
    "JavaScript".length;

    Now try:

    "Hello\nWorld";

    What did you see?

    The \n represents a newline.

    You can experiment with other strings too.

    Try making a string containing:

    • a quotation mark;
    • several lines;
    • a tab;
    • an empty string.

    Don’t worry about remembering every escape sequence.

    The REPL is available.

    A couple of mysterious values#

    There are two values you’ll encounter often:

    undefined;

    and:

    null;

    Try them.

    What does the REPL print?

    They both represent some notion of “nothing”, but they aren’t the same thing.

    For now, don’t try to force them into a perfect definition.

    Instead, try:

    typeof 5;
    typeof true;
    typeof "Hello";
    typeof undefined;

    What does typeof seem to do?

    Try:

    typeof null;

    Wait.

    What?

    If you got:

    "object"

    you have just encountered one of JavaScript’s famous historical oddities.

    You don’t need to fix it.

    You don’t need to memorize an elaborate explanation.

    Just remember that programming languages, like everything else humans build, sometimes carry strange historical decisions forward.

    Try:

    typeof NaN;

    What do you think you’ll get?

    Truthiness#

    We have seen values such as:

    true;
false;

    But JavaScript can also ask whether other values behave like true or false.

    Let’s investigate.

    Try:

    Boolean(true);
    Boolean(false);

    Now:

    Boolean(1);
    Boolean(0);

    What about:

    Boolean("Hello");

    and:

    Boolean("");

    Try:

    Boolean(null);
    Boolean(undefined);
    Boolean(NaN);

    There is a pattern here.

    Some values are truthy.

    Some values are falsy.

    You don’t need to memorize the entire list yet.

    Instead, explore.

    What about:

    Boolean(-1);
    Boolean(100);
    Boolean("0");
    Boolean("false");

    That last pair is worth thinking about.

    The string "0" contains the character 0.

    The string "false" contains the word false.

    But they are still strings.

    So what do you think JavaScript will consider them?

    Run them.

    Choosing between values#

    We’ve now got enough pieces to do something interesting.

    Try:

    true ? "yes" : "no";

    You should get:

    "yes"

    Now:

    false ? "yes" : "no";

    What happened?

    The general form is:

    condition ? valueIfTrue : valueIfFalse;

    Try:

    5 > 3 ? "yes" : "no";

    And:

    5 < 3 ? "yes" : "no";

    Now make your own.

    For example:

    10 % 2 === 0 ? "even" : "odd";

    Try changing the number.

    Can you make an expression that tells you whether another number is positive or negative?

    What about whether a number is greater than 100?

    You now have enough pieces to make surprisingly complicated expressions without having created a single variable.

    That’s intentional.

    What about the bits?#

    There is another family of operators we should briefly encounter.

    Try:

    5 & 3;

    Then:

    5 | 3;

    Then:

    5 ^ 3;

    These are bitwise operators.

    They’re operating on the bits that make up the number.

    You don’t need to become an expert in binary arithmetic right now.

    But try:

    5 << 1;

    and:

    5 >> 1;

    Can you find a relationship between the result and the original number?

    Try several values.

    1 << 1;
2 << 1;
4 << 1;
8 << 1;

    What is happening?

    Now try:

    8 >> 1;
16 >> 1;
32 >> 1;

    Can you discover the pattern?

    This is another useful way of learning programming:

    notice a pattern before someone gives you the rule.

    You may not fully understand what’s happening yet.

    That’s okay.

    You have somewhere to experiment.

    A small challenge#

    At this point, don’t read the answer to this section immediately.

    Use the REPL.

    See if you can work these out.

    1. What does this produce?#

    2 + 3 * 4;

    2. How could you make it produce 20?#

    3. What does this produce?#

    10 % 3;

    4. Can you write an expression that produces true when 10 is greater than 5?#

    5. Can you combine two comparisons using &&?#

    6. Can you write an expression that produces "even" or "odd" depending on whether a number is even?#

    7. What is the length of:#

    "Hello, JavaScript!";

    Don’t calculate it yourself.

    Ask JavaScript.

    8. What happens here?#

    "5" + 5;

    And here?

    5 + 5;

    Why are the results different?

    9. What happens here?#

    5 === "5";

    Why?

    10. Can you construct one expression containing:#

    • arithmetic;
    • a comparison;
    • && or ||;
    • and a conditional expression?

    It doesn’t have to be useful.

    It just has to work.

    One last thing#

    You may have noticed something.

    We have spent this entire session evaluating expressions.

    We haven’t written a program.

    We haven’t created a variable.

    We haven’t used let.

    We haven’t used const.

    That is deliberate.

    It is tempting to jump immediately into:

    let score = 10;

    and start building things.

    But there’s something more fundamental that we want to understand first.

    When you type:

    5 + 3;

    JavaScript evaluates an expression.

    The expression produces a value.

    That value can be used as part of another expression.

    And that expression can produce another value.

    So far, we’ve seen:

    values
   ↓
expressions
   ↓
evaluation
   ↓
new values
   ↓
larger expressions
   ↓
new values

    This is the basic game.

    We’ve been playing it directly in the REPL.

    Soon we’ll want to give values names.

    We’ll want to keep them around.

    We’ll want to make decisions, repeat things, and eventually build programs.

    But before we do that, get comfortable with this:

    Look at an expression. Predict its value. Ask JavaScript to evaluate it. If you’re surprised, investigate why.

    That’s programming.
