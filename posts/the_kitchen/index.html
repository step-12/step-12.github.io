    The Kitchen

    September 18, 2026

    The Kitchen#

    Imagine that you are running a busy kitchen.

    Not a small kitchen at home where one person makes breakfast.

    A very busy kitchen.

    There are many people who want to use it at the same time.

    One person wants to make tea. Another wants to cook rice. Someone is baking bread. Someone else is making soup. Another person is washing dishes.

    They all need things from the same kitchen:

    • the stove
    • the oven
    • water
    • electricity
    • knives
    • pots and pans
    • ingredients
    • counter space
    • the sink

    There is a problem.

    There is only one kitchen.

    There is only one oven.

    There may only be four burners.

    There is only one sink.

    So what happens when five people want the oven?

    Or when two people want the same burner?

    Or when someone wants to use the sink while somebody else is already washing dishes?

    Someone needs to manage all of this.

    The Kitchen Manager#

    Imagine that your kitchen has a kitchen manager.

    The manager doesn’t make the tea.

    The manager doesn’t bake the bread.

    The manager doesn’t cook the rice.

    Instead, the manager is responsible for running the kitchen.

    Someone says:

    “I need the stove.”

    The manager decides whether the stove is available.

    Someone says:

    “I need the oven for 30 minutes.”

    The manager decides when they can use it.

    Someone asks:

    “Can I have some water?”

    The manager makes sure they can get water.

    Someone tries to take a knife that someone else is using.

    The manager intervenes.

    Someone finishes cooking and leaves their things all over the counter.

    The manager makes sure that the space and resources can eventually be used again.

    The kitchen manager is not the person doing the work.

    The manager controls access to the resources that everyone needs to do their work.

    Keep that person in your head.

    We are going to come back to them many times.

    The People in the Kitchen#

    Now imagine that each person in the kitchen has a job.

    Alice is making tea.

    Bob is baking bread.

    Charlie is making soup.

    David is washing dishes.

    These people are doing different things, but they are all sharing the same kitchen.

    Think about the difference between these two statements:

    Alice is a person.

    and:

    Alice is a person who is currently making tea.

    The second statement tells us what Alice is doing.

    This is a useful way to think about a process.

    A process is a program that is currently running.

    A program is like a recipe sitting in a cookbook.

    It contains instructions, but it isn’t doing anything.

    A process is what happens when someone actually takes that recipe into the kitchen and starts following it.

    So if you write a program:

    make tea

    the program is the recipe.

    When the computer starts executing that program, we can think of the running program as a process.

    One Kitchen, Many Processes#

    Let’s go back to our kitchen.

    Alice wants to make tea.

    Bob wants to make bread.

    Charlie wants to make soup.

    All three are working at the same time.

    But they are sharing the kitchen.

    Alice needs the stove.

    Charlie also needs the stove.

    Bob needs the oven.

    What happens?

    Alice might say:

    “I need the stove.”

    The kitchen manager checks.

    The stove is available.

    So Alice gets it.

    Then Charlie says:

    “I need the stove.”

    The manager looks at the stove.

    Alice is using it.

    So the manager says:

    “Wait.”

    Charlie has to wait until the stove becomes available.

    This is one of the most important things to understand about an operating system:

    There are many processes, but there are a limited number of resources.

    The kernel is responsible for coordinating them.

    The Oven Problem#

    Let’s make the problem harder.

    Five people arrive at the kitchen.

    All five want the oven.

    But there is only one oven.

    The manager could arrange things like this:

    Bread      → Oven
Cake       → Wait
Pizza      → Wait
Roast      → Wait
Cookies    → Wait

    The bread goes into the oven.

    The other four people wait.

    When the bread is finished:

    Bread      → Done
Cake       → Oven
Pizza      → Wait
Roast      → Wait
Cookies    → Wait

    The manager has scheduled access to the oven.

    This is very similar to what happens with a CPU.

    There may be many processes that want to run, but a CPU core can only execute one instruction stream at a time.

    The kernel has to decide:

    Which process gets to use the CPU now?

    And then:

    Which process gets to use it next?

    Everyone Gets a Turn#

    Suppose Alice gets the stove.

    She starts making tea.

    But Alice doesn’t want to give the stove back.

    She says:

    “I’m going to keep using this stove forever.”

    That would be a terrible kitchen.

    The manager needs to make sure that Charlie gets a chance too.

    So after some amount of time, the manager says:

    “Alice, you’ve had your turn. Charlie gets the stove now.”

    Charlie cooks.

    Then perhaps Alice gets another turn.

    The sequence might look like:

    Alice → Charlie → Bob → Alice → Charlie → Bob

    On a computer, the kernel can similarly give processes small amounts of CPU time.

    The computer switches between processes so quickly that it can look as though many things are happening at once.

    This is part of CPU scheduling.

    But How Does Alice Know Where She Was?#

    There is an interesting problem here.

    Suppose Alice is making tea.

    She has:

    • a kettle on the stove
    • tea leaves on the counter
    • milk beside her
    • a cup in her hand

    She has just started boiling the water.

    The manager says:

    “Charlie needs the stove. You have to wait.”

    Alice leaves.

    A little later, the manager says:

    “Alice, your turn.”

    Alice needs to continue her work.

    She needs to know where she was.

    She needs to remember something like:

    Alice

Task:       Making tea
Step:       Waiting for water to boil
Tea leaves: 2 spoons
Milk:       100 ml

    A process also has state.

    The computer needs to keep track of things about a process so that it can stop running it and later continue from where it left off.

    This is part of what happens during a context switch.

    The kernel pauses one process, preserves its state, and gives the CPU to another process.

    Later, it can restore the first process’s state and allow it to continue.

    Running, Ready and Waiting#

    Now look carefully at what is happening in our kitchen.

    Alice is currently using the stove.

    She is running.

    Charlie wants to use the stove, but Alice has it.

    Charlie is ready, but he is waiting for his turn.

    Bob has put his bread into the oven.

    There is nothing he can do until the bread finishes baking.

    Bob is waiting for an event.

    These are different situations.

    A process might be:

    Running

    It is currently using the CPU.

    Ready

    It is able to run, but it is waiting for CPU time.

    Blocked

    It cannot continue because it is waiting for something else.

    Terminated

    It has finished.

    You can imagine the processes moving between these states:

                 +---------+
             |  READY  |
             +----+----+
                  |
                  | gets CPU
                  ↓
             +---------+
             | RUNNING |
             +----+----+
              /       \
             /         \
      needs resource   finishes
           /             \
          ↓               ↓
    +-----------+    +------------+
    |  BLOCKED  |    | TERMINATED |
    +-----+-----+    +------------+
          |
          | resource becomes available
          ↓
        READY

    The kernel is constantly managing these transitions.

    What If Bob Needs the Oven?#

    Suppose Bob’s bread is ready to go into the oven.

    He asks:

    “Can I use the oven?”

    The manager looks.

    Someone else is already using it.

    Bob cannot continue with that part of his recipe.

    So Bob waits.

    But Bob doesn’t necessarily need to stand there doing nothing.

    He might chop some vegetables.

    Or prepare the next part of the recipe.

    Similarly, a computer process might ask for something that takes time.

    For example, it might ask the disk:

    “Give me this file.”

    The disk takes some time to respond.

    There is no reason for the CPU to sit around doing nothing while it waits.

    The kernel can allow another process to use the CPU.

    So we might have:

    Process A
    |
    | asks disk for data
    ↓
  BLOCKED

Meanwhile...

Process B → CPU
Process B → CPU
Process B → CPU

Then...

Disk data arrives
    |
    ↓
Process A → READY

    This is one reason your computer can continue doing other things while a program is waiting for something.

    Asking the Kitchen Manager#

    There are some things the people in the kitchen cannot simply do themselves.

    Suppose Alice wants water.

    She cannot rip open the wall and manipulate the plumbing.

    She asks the kitchen manager:

    “I need water.”

    The manager handles the request.

    Programs work in a similar way.

    A program might need to:

    • open a file
    • read from a file
    • write to a file
    • create a process
    • communicate over a network
    • ask for memory
    • interact with a device

    The program asks the kernel to perform the operation.

    These requests are called system calls.

    You can think of them as the official way for a process to ask the manager for something.

    Process
   |
   | "I need this."
   ↓
Kernel
   |
   | checks and performs operation
   ↓
Process
   |
   | receives result

    The important thing here is the boundary.

    A process does not simply have unrestricted access to the whole computer.

    It has to go through the kernel for operations that require the kernel’s authority.

    The Manager Makes Sure People Don’t Interfere With Each Other#

    Imagine Alice is working on a complicated cake.

    Charlie walks over and says:

    “I’m going to change your recipe.”

    That shouldn’t be allowed.

    Alice’s work needs to be protected from Charlie.

    The same idea exists in a computer.

    A process generally has its own memory.

    One process should not simply reach into another process’s memory and change whatever it wants.

    The kernel provides protection and isolation between processes.

    This is important because there may be many completely unrelated programs running on your computer at the same time.

    You don’t want your music player accidentally changing the memory belonging to your web browser.

    And you definitely don’t want an ordinary program to be able to freely manipulate the operating system itself.

    The Kitchen Has a Door#

    Let’s imagine the kitchen has a locked door.

    People outside the kitchen cannot simply walk in and start operating the stove.

    There is a controlled entrance.

    The kitchen manager controls what happens inside.

    The computer has a similar boundary.

    Programs run with limited privileges.

    The kernel runs with special privileges that allow it to manage the machine.

    Conceptually:

                 PROGRAMS
                 |
                 | requests
                 ↓
              KERNEL
                 |
                 | controls
                 ↓
              HARDWARE

    This is one of the fundamental ideas behind an operating system.

    The kernel sits between your programs and the hardware and provides a controlled way for programs to use the machine.

    What Is the Hardware in Our Kitchen?#

    Our kitchen has:

    • burners
    • an oven
    • a sink
    • a refrigerator
    • knives
    • counters
    • electricity
    • water

    A computer has:

    • CPU
    • memory
    • disk
    • network hardware
    • keyboard
    • display
    • speakers
    • other devices

    The kernel has to manage access to these resources.

    The CPU is especially important because it is where instructions are actually executed.

    So you can think of the CPU as one of the most important pieces of equipment in the kitchen.

    If you have four CPU cores, imagine having four burners.

    Four things can genuinely be happening at the same time.

    But if you have 100 processes and only four CPU cores, the kernel still has to schedule all of those processes.

    What If You Need Another Cook?#

    Now let’s make our kitchen even more interesting.

    Alice is making dinner.

    Her recipe says:

    “Prepare the salad.”

    Alice could stop everything and make the salad herself.

    Or she could ask the manager:

    “I need another person to make the salad.”

    The manager brings another person into the kitchen.

    Now we have:

                 Alice
               |
        creates another worker
               |
               ↓
             Salad

    This is similar to process creation.

    A process can create another process.

    The original process is called the parent process.

    The newly created process is the child process.

    So we can have a process tree:

                 Parent
             /    \
            /      \
        Child A   Child B
                    |
                  Child C

    On Unix-like operating systems, processes form this kind of hierarchy.

    And you have already seen an example of this without necessarily realizing it.

    When you open your terminal and run a command, your shell can create a new process to run that command.

    The shell is itself a process.

    The command you run becomes another process.

    What Happens When the Child Finishes?#

    Suppose Alice asked someone to make the salad.

    Eventually the person comes back:

    “The salad is finished.”

    The work is done.

    The worker can leave.

    The manager needs to clean up the resources that worker was using.

    The process is now terminated.

    But something interesting can happen.

    Suppose the child finishes, but Alice hasn’t yet come back to find out what happened.

    The manager may temporarily keep information about the finished worker:

    Worker
Status: finished
Result: completed
Parent: Alice

    The worker isn’t actually running anymore.

    It has finished.

    But the manager still has a small amount of information about its termination.

    When Alice eventually asks:

    “What happened to the worker?”

    the manager can give her the result and clean up the remaining record.

    This is roughly the idea behind a zombie process on Unix.

    A zombie is not a process that is secretly still cooking.

    It has already finished.

    Some information about its termination is simply still being retained until its parent collects it.

    What If Someone Needs to Be Stopped?#

    Now imagine that someone in the kitchen is causing trouble.

    The manager might shout:

    “Stop!”

    Or:

    “Leave the kitchen!”

    The manager needs some way to communicate with the people working.

    Unix has a mechanism called signals.

    A signal is a notification sent to a process.

    For example, a process might receive a signal asking it to terminate.

    Or it might receive a signal telling it to stop temporarily.

    The exact signals are something you can learn later.

    For now, the important idea is:

    The kernel can send notifications to processes.

    This gives the kernel another way to control and communicate with the things running on the machine.

    The Kitchen Is Always Changing#

    Imagine looking into our kitchen at one particular moment.

    You might see:

    Alice       → RUNNING
Bob         → BLOCKED
Charlie     → READY
David       → BLOCKED
Emma        → TERMINATED
Frank       → READY

    A few seconds later, everything might be different.

    Bob’s bread finishes.

    Bob becomes ready.

    The CPU becomes available.

    Charlie gets a turn.

    Alice needs some water.

    Alice becomes blocked.

    David’s water arrives.

    David becomes ready.

    A new process is created.

    Another process finishes.

    The kernel is constantly responding to these changes.

    This is what makes operating systems interesting.

    A computer isn’t simply:

    “Run program A, then run program B, then run program C.”

    Instead, there are many independent pieces of work appearing, disappearing, waiting, competing for resources and communicating with one another.

    The kernel coordinates this activity.

    The Kitchen Is a Computer#

    Now step back from the kitchen.

    We have been talking about:

    • cooks
    • recipes
    • ovens
    • stoves
    • sinks
    • resources
    • waiting
    • scheduling
    • managers
    • workers
    • messages
    • finishing work

    But our kitchen is really a model of a computer.

    The recipe is like a program.

    The person following the recipe is like a process.

    The kitchen manager is like the kernel.

    The stove, oven, sink and other equipment are resources.

    The manager decides:

    • who gets to use resources
    • when they get to use them
    • what happens when resources are unavailable
    • how processes are created
    • how processes are stopped
    • how processes are isolated
    • what happens when processes finish
    • how processes communicate with the system

    And the most important thing to remember is this:

    The kernel is not doing the work of the processes.

    The kernel doesn’t make your tea.

    It doesn’t bake your bread.

    It doesn’t run your application for you.

    It manages the environment in which the applications run.

    One Last Question#

    There is one more thing worth thinking about.

    We have said that the kitchen manager is responsible for everything.

    The manager controls the kitchen.

    The manager decides who gets the stove.

    The manager decides who gets the oven.

    The manager decides who gets to use the sink.

    But ask yourself:

    Who manages the kitchen manager?

    If the kernel is software, and software needs a CPU to run…

    how does the kernel get started?

    Who gives the kernel control of the computer?

    Who starts the first process?

    And if the kernel is responsible for managing processes, is the kernel itself a process?

    Don’t worry if you don’t know the answers yet.

    Those questions lead us to the next layer of the story: how a computer starts, how the kernel gets control of the hardware, and how the first process comes into existence.
