    Shell, Commands

    Commands#

    We’ve seen that the shell reads what we type and either handles it itself or starts another process.

    But what exactly are we typing?

    ls -l ~/Downloads

    This is a command.

    Let’s take it apart.

    The Anatomy of a Command#

    A command generally starts with a command name.

    ls

    Here, ls is the name of the program we want to run.

    We can provide additional information to the command using arguments and options.

    ls -l ~/Downloads

    Here:

    ls          command
-l          option
~/Downloads argument

    An option is sometimes called a flag or a switch. Options change how a command behaves.

    Arguments provide information to the command about what we want it to operate on.

    For example:

    ls ~/Downloads

    means “list the contents of ~/Downloads.”

    And:

    ls -l ~/Downloads

    asks ls to give us a more detailed listing.

    The exact meaning of options and arguments depends on the command. Fortunately, we don’t have to memorise everything.

    We’ll see how to find out what a command does shortly.

    Spaces Matter#

    There is one small but important detail about commands.

    The shell uses spaces to separate the different parts of a command.

    For example:

    ls ~/Downloads

    contains two pieces:

    ls
~/Downloads

    What if a filename contains a space?

    Suppose we have a directory called:

    My Notes

    If we type:

    ls My Notes

    the shell sees three pieces:

    ls
My
Notes

    It does not know that My Notes is supposed to be one argument.

    We can tell the shell that the space is part of the argument by putting the argument in quotes:

    ls "My Notes"

    Now the shell treats My Notes as one argument.

    This distinction is important because the shell processes the command line before the program receives it.

    The ls program doesn’t receive the original string:

    ls "My Notes"

    It receives the command and its arguments after the shell has interpreted them.

    We’ll encounter more examples of the shell doing this kind of work later.

    A Few Commands#

    Let’s learn a small collection of commands.

    You don’t need to memorise these. We’ll use them to explore the computer.

    pwd#

    pwd tells us where we currently are.

    pwd

    Think of it as:

    Where am I?

    ls#

    ls lists the contents of the current directory.

    ls

    You can also give it a directory to list:

    ls ~/Downloads

    cd#

    cd changes the directory we’re currently in.

    cd ~/Downloads

    Think of it as:

    Take me there.

    Remember that cd is handled directly by the shell. It needs to change the shell’s own current directory.

    mkdir#

    mkdir creates a directory.

    mkdir playground

    touch#

    touch can be used to create an empty file.

    touch hello.txt

    Now:

    ls

    should show hello.txt.

    echo#

    echo prints something.

    echo hello

    Try:

    echo "Hello, world."

    You’ll see the text printed back to you.

    clear#

    clear clears the terminal screen.

    clear

    There are also keyboard shortcuts for controlling the terminal. On our systems, Ctrl-L is a convenient way of clearing/redrawing the screen.

    You may see keyboard shortcuts such as ^L or ^K written down. The ^ notation means Ctrl: ^L means Ctrl-L.

    man#

    Finally, one of the most useful commands of all:

    man ls

    This displays the manual for ls.

    Try:

    man mkdir

    and:

    man cd

    You don’t need to understand everything in these pages. They’re reference material. When you encounter a command you don’t know, the manual is often the first place to look.

    Many commands also provide a shorter help message using:

    pstree -h

    The command line is not something you are expected to memorise. Learning how to find out what a command does is much more useful.

    Let’s Make a Sandbox#

    We’re now going to use these commands to explore one of the most important ideas in the command line: paths.

    Rather than explain paths with a diagram, let’s make a little filesystem of our own.

    Start in your home directory:

    cd ~

    You can check where you are with:

    pwd

    Now create a directory called sandbox and enter it:

    mkdir sandbox
cd sandbox

    Check again:

    pwd

    You should now be inside your new sandbox.

    Let’s make some directories:

    mkdir books music
mkdir books/fiction books/non-fiction
mkdir music/rock music/jazz

    And some files:

    touch books/fiction/dune.txt
touch books/non-fiction/unix.txt
touch music/rock/beatles.txt
touch music/jazz/miles.txt

    We have now created something like this:

    sandbox
├── books
│   ├── fiction
│   │   └── dune.txt
│   └── non-fiction
│       └── unix.txt
└── music
    ├── rock
    │   └── beatles.txt
    └── jazz
        └── miles.txt

    Don’t worry if the diagram looks a little complicated. We’re going to walk around it.

    Relative Paths#

    We are currently in:

    sandbox

    Let’s move into books:

    cd books

    Now:

    pwd

    We’re in books.

    Move into fiction:

    cd fiction
pwd

    Now let’s go back:

    cd ..
pwd

    We are back in books.

    .. means the directory above the one we’re currently in.

    So from books/fiction:

    cd ..

    takes us to:

    books

    We can go up more than one level:

    cd ..
pwd

    We’re back in sandbox.

    We can also describe a route in one go.

    From sandbox, try:

    cd music/jazz
pwd

    We’ve moved into jazz.

    The important thing about this path is that it is relative to where we currently are.

    From sandbox:

    music/jazz

    means:

    Starting here, go into music, then go into jazz.

    Try this:

    cd ..
cd ../books/fiction
pwd

    The path ../books/fiction means:

    Go up one directory from where I am, then go into books, then fiction.

    A relative path describes a route from where you are now.

    Absolute Paths#

    There is another way to describe a location.

    An absolute path describes a location starting from the root of the filesystem.

    The root directory is written as:

    /

    On a Mac, your home directory will be somewhere underneath /Users.

    You can see your complete current path with:

    pwd

    It might look something like:

    /Users/your-name/sandbox/books/fiction

    That is an absolute path.

    Unlike a relative path, it doesn’t matter where you currently are. The path starts at / and describes the complete route to the destination.

    For example, from anywhere, you could use an absolute path to reach your sandbox:

    cd /Users/your-name/sandbox

    Of course, you would have to replace your-name with your actual username.

    An absolute path is like giving someone a complete address.

    A relative path is like saying:

    Go upstairs, then turn left.

    The second instruction only makes sense if we know where you are starting from.

    What Is ~?#

    Typing your entire home directory is inconvenient.

    Fortunately, the shell gives us a shortcut:

    ~

    The tilde means your home directory.

    So:

    ~/sandbox

    means:

    The sandbox directory inside my home directory.

    We can use it from anywhere.

    Try:

    cd ~

    Then:

    pwd

    Now go directly back to the sandbox:

    cd ~/sandbox

    From there, we can reach our music directory:

    cd ~/sandbox/music

    Notice that this doesn’t depend on where we started.

    Let’s Wander Around#

    Now try navigating around the sandbox without following instructions one at a time.

    Start here:

    cd ~/sandbox

    Can you get to the Beatles file using a relative path?

    cd music/rock

    Check:

    pwd
ls

    You should see:

    beatles.txt

    Now get back to sandbox using ..:

    cd ../..
pwd

    You should be back in sandbox.

    Can you get to the Miles Davis file using a single relative path?

    cd music/jazz
ls

    And now, from there, get to the Unix file:

    cd ../../books/non-fiction
ls

    Finally, use an absolute-ish path beginning with ~ to return to the fiction directory:

    cd ~/sandbox/books/fiction
ls

    The more you do this, the less mysterious paths become.

    There are two basic ways of telling the shell where something is:

    absolute path
    "Start at the root and follow this complete route."

relative path
    "Start where I am and follow this route."

    And ~ gives us a convenient name for our home directory.

    You now have most of the vocabulary you need to start moving around the filesystem from the command line.

    The important thing is that you don’t need to memorise a collection of commands. You need to understand what the pieces of a command mean, and know how to ask the computer when you don’t know something.
