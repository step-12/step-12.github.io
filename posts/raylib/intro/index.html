    Intro to Graphics/Raylib

    September 23, 2026
    Raylib, Graphics

    Raylib#

    So far, most of the programs you have written have produced things like numbers and text.

    You might have written:

    console.log(2 + 3);

    and seen:

    5

    Or perhaps you wrote a function that takes some values, performs a computation, and returns another value.

    What if the result of our program could be something that we could see?

    What if instead of producing:

    5

    our program could produce a rectangle on the screen?

    That is where we are going next.

    A different kind of output#

    Imagine that your computer has a large sheet of graph paper in front of it.

    The sheet is made up of many tiny points called pixels. We can describe a position on this sheet using two numbers.

    We usually call them x and y.

    (0, 0)
  ┌──────────────────────────────→ x
  │
  │
  │
  │
  ↓
  y

    The top-left corner is (0, 0).

    Move to the right and x increases.

    Move down and y increases.

    So where would (100, 50) be?

    And where would (500, 200) be?

    You don’t have to draw these points. Just try to imagine them.

    Now suppose we wanted to draw a rectangle.

    A rectangle needs more information than just a position.

    We need to know:

    • where it starts;
    • how wide it is;
    • how tall it is;
    • what colour it should be.

    So perhaps we could describe a rectangle like this:

    x = 100
y = 50
width = 200
height = 100

    We have turned something visual into data.

    This is an important idea.

    Graphics are something that a program can describe.

    A rectangle is not mysterious to the computer. It can be described using numbers.

    A line can be described using positions.

    A circle can be described using a position, a radius, and a colour.

    A picture can be described using many such things together.

    So how do we get our JavaScript program to actually draw them?

    Somebody has already written the code#

    Think back to functions.

    Suppose you need to calculate whether a number is even. You could write the function yourself:

    function isEven(number) {
  return number % 2 === 0;
}

    But what if somebody else had already written a useful function?

    You could simply use it.

    This happens all the time in programming.

    You do not have to write every piece of code yourself.

    Other programmers write collections of useful code that we can use in our own programs.

    These collections are called libraries.

    A library is, broadly speaking, code written by somebody else that we can use in our own programs.

    You have already used libraries without necessarily thinking about them as libraries.

    Now we are going to use one deliberately.

    Raylib#

    We are going to use a library called Raylib.

    Raylib contains functions for doing things with graphics.

    For example, it has functions for:

    • creating a window;
    • drawing rectangles;
    • drawing lines;
    • drawing circles;
    • displaying text;
    • working with the keyboard;
    • working with the mouse;
    • and many other things.

    Imagine that somebody has spent a great deal of time writing all the difficult code necessary to make a rectangle appear on a screen.

    We don’t need to write all of that code ourselves.

    Instead, we can call a function they have provided.

    The idea should feel familiar.

    We know how to call functions:

    someFunction(10, 20);

    Raylib gives us functions that do useful things with graphics.

    For example, there is a function called DrawRectangle.

    We will eventually be able to write something like:

    r.DrawRectangle(100, 50, 200, 100, r.WHITE);

    What do you think those five values might mean?

    Look back at our description of a rectangle.

    There is a position.

    There is a width and a height.

    And there is a colour.

    You can probably make a good guess.

    That’s enough for now.

    We will discover the rest by using it.

    Using Raylib from JavaScript#

    Raylib itself is not a JavaScript library.

    We are writing JavaScript programs using Node.js, so we need a way for our JavaScript programs to use Raylib.

    We will use node-raylib for this.

    Before we can use it, we need to add it to our project.

    Open your terminal and move into your JavaScript workspace.

    Then install Raylib:

    npm install raylib

    You may have seen npm before. It is a tool that helps us work with packages of JavaScript code.

    When you install a package, you will also see a file called:

    package.json

    This file describes our Node.js project and, among other things, keeps track of the packages that our project uses.

    Don’t worry about learning npm or package.json in detail right now.

    We have a much more interesting question to answer:

    What can we make with Raylib?

    A toolbox#

    For now, think of Raylib as a toolbox.

    Our JavaScript program is still our program.

    We still have:

    const
let
if
while
function
return

    and everything else that we have learned.

    Raylib simply gives us some additional tools.

    Instead of writing all the code necessary to draw a rectangle ourselves, we can use the tool that Raylib gives us.

    Instead of writing all the code necessary to create a window, we can use the tool that Raylib gives us.

    Instead of writing all the code necessary to read a keyboard key, we can eventually use the tool that Raylib gives us.

    The programming language has not changed.

    We have simply acquired a new collection of things that our program can do.

    There is a lot here#

    If you look at the Raylib documentation, you will find a lot of functions.

    There are functions for things we have not talked about yet.

    There are concepts we have not learned yet.

    There are probably things that will make very little sense to you right now.

    That is completely fine.

    In fact, you should expect this.

    We are going to learn Raylib gradually.

    At first, we will only use a handful of functions.

    Later, we will discover more.

    Some things will remain mysterious until we have learned the programming concepts necessary to understand them.

    You do not need to understand everything you see.

    You need to understand enough to start experimenting.

    A new kind of programming#

    Up to now, when you wrote a program, you were mostly asking:

    What value should this expression produce?

    Or:

    What should this function return?

    We are going to start asking some different questions.

    Where should this rectangle be?

    What happens if I move it?

    What happens if two rectangles overlap?

    How could I make a circle move?

    How could I make something respond to the keyboard?

    How could I make a game?

    These are still programming questions.

    We will still use variables.

    We will still use conditions.

    We will still use functions.

    We will still use the same JavaScript.

    But now our programs will have a world in which those ideas can operate.

    That is what makes this interesting.

    One last question#

    There is one thing you should notice.

    If a program draws a rectangle, does it draw the rectangle once and then finish?

    What would happen if you wanted the rectangle to move?

    Would the program have to draw the rectangle again?

    And again?

    And again?

    We will answer that next.

    For now, don’t worry about how.

    Just keep the question in your head:

    How does a program keep drawing things on the screen?
