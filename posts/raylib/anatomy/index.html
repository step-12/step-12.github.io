    Raylib anatomy

    September 23, 2026
    Raylib, Graphics

    The anatomy of a Raylib program#

    In the previous post, we saw that Raylib is a library that gives our JavaScript programs a collection of functions for working with graphics.

    We are now going to look at a complete Raylib program.

    Don’t worry if you don’t understand everything in it yet.

    In fact, you shouldn’t.

    Read through it once and see if you can recognize anything.

    const r = require("raylib");

r.InitWindow(800, 400, "Raylib");
r.SetTargetFPS(60);

while (!r.WindowShouldClose()) {
  r.BeginDrawing();
  r.ClearBackground(r.BLACK);

  r.DrawRectangle(100, 50, 600, 300, r.WHITE);

  r.EndDrawing();
}

r.CloseWindow();

    There are quite a few things happening here.

    Let’s take the program apart.

    Getting Raylib#

    The first line is:

    const r = require("raylib");

    We saw this in the previous post.

    We are asking Node.js to give us the Raylib library.

    We store what we get in a variable called r.

    Why r?

    There is nothing particularly special about that name. We could have called it something else.

    const raylib = require("raylib");

    would also work.

    For now, think of r as our way of accessing the Raylib toolbox.

    So when we write:

    r.DrawRectangle(...)

    we are asking Raylib to perform an operation for us.

    We will come back to exactly what require is doing later.

    For now, there is something more interesting to understand.

    Creating a window#

    The next line is:

    r.InitWindow(800, 400, "Raylib");

    We are calling a Raylib function called InitWindow.

    It creates the window in which our graphics will appear.

    Look at the arguments.

    800
400
"Raylib"

    Can you guess what they mean?

    The first two are the width and height of the window.

    So we are asking for a window that is:

    800 pixels wide
400 pixels high

    The third argument is the title of the window.

    Try changing it.

    What happens if you write:

    r.InitWindow(800, 400, "My first graphics program");

    You have already encountered function arguments.

    This is no different.

    Raylib has simply given us a function that does something useful.

    A coordinate system#

    Remember the coordinate system we saw in the previous post.

    The top-left corner of the window is:

    (0, 0)

    The x coordinate increases as we move to the right.

    The y coordinate increases as we move down.

    So where would this point be?

    (100, 50)

    And this one?

    (600, 300)

    Keep those coordinates in mind.

    We are going to use them shortly.

    How quickly should we draw?#

    The next line is:

    r.SetTargetFPS(60);

    FPS means frames per second.

    A graphical program produces a sequence of images called frames.

    If we produce 60 frames every second, we are producing roughly:

    60 frames
---------
  1 second

    So this line tells Raylib that we would like the program to run at 60 frames per second.

    Why would we want to produce the same image 60 times every second?

    That’s a good question.

    We will get to the answer.

    For now, just remember that our graphical program is going to keep producing frames.

    The part that keeps the program running#

    Now we come to something new.

    You can see this:

    while (!r.WindowShouldClose()) {

    You don’t need to understand this line yet.

    There are some JavaScript ideas in here that we haven’t properly introduced.

    We will learn about while loops later.

    For now, all you need to know is this:

    This is the part of the program that keeps the drawing process going.

    Everything inside the { and } belongs to this repeating part of the program.

    So this:

    while (...) {
  // things here
}

    is telling the program that the things inside it should happen repeatedly.

    There is also a Raylib function here:

    r.WindowShouldClose();

    You can probably guess what it is asking.

    It asks Raylib whether the window should close.

    For now, don’t worry about exactly how the while works or how the answer from WindowShouldClose() is used.

    We will come back to that when we properly learn loops.

    What matters today is that the program needs some way of saying:

    Keep producing frames until the window is closed.

    Beginning a frame#

    Inside that repeating part of the program, we have:

    r.BeginDrawing();

    We are beginning to construct one frame.

    Think of everything between:

    r.BeginDrawing();

    and:

    r.EndDrawing();

    as the work involved in producing one image.

    What should that image look like?

    That’s what we are about to describe.

    Clearing the screen#

    The first thing we do is:

    r.ClearBackground(r.BLACK);

    This clears the background and makes it black.

    Why do this every frame?

    Think about a normal piece of paper.

    If you draw a rectangle on paper, it stays there.

    If you draw another rectangle, the first rectangle doesn’t disappear.

    A screen is different.

    We are going to keep describing what the screen should look like right now.

    So at the beginning of each frame, we clear what was there before.

    Then we draw what we want to see.

    You might find it interesting to remove this line and see what happens.

    Don’t worry if you don’t yet understand exactly why it happens.

    Just observe it.

    Drawing the rectangle#

    Now we get to something familiar:

    r.DrawRectangle(100, 50, 600, 300, r.WHITE);

    This is a function call.

    Raylib has provided a function called DrawRectangle.

    We give it five arguments.

    Can you guess what they are?

    Look at the rectangle we are drawing.

    x      → 100
y      → 50
width  → 600
height → 300
color  → WHITE

    So the rectangle begins at:

    (100, 50)

    and has a width of 600 and a height of 300.

    Its colour is white.

    We have already encountered everything necessary to understand the idea of this function call.

    We know how to call functions.

    We know how arguments work.

    We know about numbers.

    We know about values.

    Raylib is simply providing us with a function that has a visible effect.

    Ending the frame#

    After drawing the rectangle, we have:

    r.EndDrawing();

    We have finished describing this frame.

    Raylib can now finish the frame and present it on the screen.

    And then something interesting happens.

    The program goes back to the repeating part.

    It begins another frame.

    The whole thing happens again#

    Let’s look at the important part again:

    while (!r.WindowShouldClose()) {
  r.BeginDrawing();

  r.ClearBackground(r.BLACK);

  r.DrawRectangle(100, 50, 600, 300, r.WHITE);

  r.EndDrawing();
}

    The first time around, we produce something like:

    FRAME 1

black background
white rectangle

    Then another frame is produced:

    FRAME 2

black background
white rectangle

    Then another:

    FRAME 3

black background
white rectangle

    And another.

    And another.

    At 60 frames per second, this happens many times every second.

    But the rectangle doesn’t appear to move.

    Why?

    Because we are drawing it in exactly the same place every time.

    We keep telling Raylib:

    Draw a white rectangle at (100, 50).

    So that’s what we see.

    Now imagine that the position of the rectangle changed between one frame and the next.

    What might happen?

    We will explore that later.

    Closing the window#

    There is one line left:

    r.CloseWindow();

    Notice where it is.

    It is outside the repeating part of the program.

    That means it happens after we are finished producing frames.

    When you close the window, Raylib knows that it is time for the repeating part of the program to finish.

    The program then reaches:

    r.CloseWindow();

    and Raylib can clean up the window before our program finishes.

    You don’t need to understand the exact mechanics of how this works yet.

    We will learn about the JavaScript mechanisms involved when we study loops.

    The shape of a Raylib program#

    We can now look at the whole program in a different way.

    Get Raylib
    ↓
Create a window
    ↓
Set the frame rate
    ↓
┌───────────────────────────┐
│                           │
│   Begin a frame            │
│       ↓                   │
│   Clear the screen         │
│       ↓                   │
│   Draw things              │
│       ↓                   │
│   End the frame            │
│       ↓                   │
│   Repeat                   │
│                           │
└───────────────────────────┘
    ↓
Close the window

    This is the basic shape of the Raylib programs we will be writing.

    There is a part that happens once at the beginning.

    There is a part that happens repeatedly.

    And there is a part that happens when we are finished.

    The repeating part is particularly important.

    It is what allows our program to produce a sequence of frames rather than just one picture.

    There is still a lot we don’t know#

    There are things in this program that we have deliberately not explained.

    For example:

    • What exactly does require do?
    • What is r really?
    • What exactly does while mean?
    • How does the program know when to repeat?
    • How does Raylib know when the window has been closed?
    • How does Raylib create a window?
    • How does DrawRectangle turn five values into pixels?
    • What happens inside BeginDrawing() and EndDrawing()?
    • How does Raylib keep track of 60 frames per second?

    Those are all interesting questions.

    We will answer some of them later.

    For now, you have something more useful.

    You have a working program.

    And you have a mental model of its shape.

    You don’t need to understand every line yet.

    Now change something#

    Before moving on, run the program yourself.

    Then start changing things.

    What happens if you change:

    r.InitWindow(800, 400, "Raylib");

    to:

    r.InitWindow(400, 400, "Raylib");

    What happens if you change:

    r.DrawRectangle(100, 50, 600, 300, r.WHITE);

    to:

    r.DrawRectangle(200, 100, 100, 100, r.WHITE);

    What happens if you change the colour?

    What happens if you draw a second rectangle?

    What happens if you remove ClearBackground()?

    Don’t worry about making a useful program yet.

    For now, change something, run the program, and look carefully at what happened.

    Soon, we’ll start turning these experiments into small programming problems.
