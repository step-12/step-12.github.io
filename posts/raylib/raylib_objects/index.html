      Objects in Raylib

      September 30, 2026
      Objects, Javascript, Raylib

      Objects in Raylib#

      We have learned about objects in JavaScript.

      So far, we have mostly looked at objects as a way of putting related information together:

      const student = {
  name: "Ravi",
  age: 20,
};

      The useful thing about this is not the curly braces. The useful thing is that we can give a shape to something we are thinking about.

      Raylib has many things that naturally have more than one piece of information.

      A colour has several components.

      A point has an x and a y.

      A rectangle has a position, a width and a height.

      It turns out that JavaScript objects are a very natural way to represent these things.

      And Raylib already has APIs designed to work with these objects.

      Colors#

      Let’s begin with something familiar.

      We have already used colors in Raylib:

      r.DrawRectangle(50, 50, 100, 100, r.RED);

      Raylib provides many colors for us:

      r.RED;
r.BLUE;
r.GREEN;
r.WHITE;
r.BLACK;

      But what exactly is a color?

      A color is made up of four numbers:

      red
green
blue
alpha

      We can represent one ourselves:

      const skyBlue = {
  r: 135,
  g: 206,
  b: 235,
  a: 255,
};

      We can then give this object to Raylib:

      r.DrawRectangle(50, 50, 200, 100, skyBlue);

      We have just used an ordinary JavaScript object to represent a color.

      Red, green and blue#

      The first three numbers are called RGB:

      • r — red
      • g — green
      • b — blue

      Each one goes from 0 to 255.

      For example:

      const red = {
  r: 255,
  g: 0,
  b: 0,
  a: 255,
};

      There is no red in this color:

      const noRed = {
  r: 0,
  g: 100,
  b: 200,
  a: 255,
};

      And here is yellow:

      const yellow = {
  r: 255,
  g: 255,
  b: 0,
  a: 255,
};

      You can think of the three values as three separate lights. By changing how much red, green and blue we have, we can produce a very large number of different colors.

      Try changing the numbers and see what happens.

      Why 255?#

      Why does each value stop at 255?

      Because each component is stored as a byte.

      A byte contains 8 bits.

      With 8 bits, we can represent:

      0 through 255

      That gives us 256 possible values.

      We don’t need to worry about the binary details yet. The important thing to remember for now is:

      A color component is represented by one byte, so its value goes from 0 to 255.

      There is a little more going on inside a computer when colors are represented, but this is enough for us to work with colors for now.

      Alpha#

      There is one more value in our color:

      a;

      This is alpha.

      Alpha controls how opaque the color is.

      For example:

      const solidRed = {
  r: 255,
  g: 0,
  b: 0,
  a: 255,
};

      is completely opaque.

      We can make the same red partly transparent:

      const transparentRed = {
  r: 255,
  g: 0,
  b: 0,
  a: 100,
};

      Let’s see this in action.

      Draw one rectangle first:

      const blue = {
  r: 50,
  g: 100,
  b: 220,
  a: 255,
};

r.DrawRectangle(50, 50, 200, 100, blue);

      Then draw another rectangle over it:

      const glass = {
  r: 255,
  g: 50,
  b: 50,
  a: 120,
};

r.DrawRectangle(100, 80, 200, 100, glass);

      The second rectangle is partly transparent, so we can see the rectangle underneath it.

      There is mathematics behind this. The computer has to calculate what color a pixel should become when one partly transparent color is drawn over another.

      We don’t need that mathematics yet.

      For now, it is enough to know that alpha lets us control how much of the color is opaque.

      Rectangles#

      We have used rectangles before:

      r.DrawRectangle(50, 50, 100, 80, r.RED);

      Notice something about this function.

      We give it four numbers:

      x
y
width
height

      Those four numbers belong together.

      They describe one thing: a rectangle.

      We can put those four values into an object:

      const windowRect = {
  x: 50,
  y: 50,
  width: 100,
  height: 80,
};

      Raylib has a function specifically for this:

      r.DrawRectangleRec(windowRect, r.RED);

      Rec stands for rectangle.

      Instead of giving Raylib four separate numbers, we give it one object containing the information it needs.

      This is a useful pattern.

      We have something in our world that has several properties.

      We represent those properties with an object.

      We then give that object to a function that knows how to use it.

      Drawing the outline#

      A rectangle doesn’t always have to be filled.

      We can draw its outline:

      r.DrawRectangleLines(
  windowRect.x,
  windowRect.y,
  windowRect.width,
  windowRect.height,
  r.WHITE,
);

      Now we can draw both:

      r.DrawRectangleRec(windowRect, r.BLUE);
r.DrawRectangleLines(
  windowRect.x,
  windowRect.y,
  windowRect.width,
  windowRect.height,
  r.WHITE,
);

      Notice that both functions use the same rectangle object.

      The rectangle hasn’t changed.

      We have simply chosen a different way to represent it on the screen.

      Objects can contain objects#

      Objects don’t have to contain only numbers and strings.

      They can contain other objects too.

      Suppose we are describing a button.

      A button has a position and a size:

      const button = {
  position: {
    x: 100,
    y: 100,
  },
  size: {
    x: 200,
    y: 50,
  },
};

      Here, position is an object.

      And size is another object.

      This gives us a good reason to talk about something new.

      Vector2#

      Raylib has a type called Vector2.

      For now, we are going to use a very simple definition:

      A Vector2 is a pair of numbers that we use to represent a point in two-dimensional Cartesian space.

      For example:

      const buttonPosition = {
  x: 100,
  y: 100,
};

      This tells us where the button is.

      And:

      const buttonSize = {
  x: 200,
  y: 50,
};

      tells us how wide and tall it is.

      We can use these objects with Raylib.

      For example, DrawRectangleV takes a position, a size and a color:

      r.DrawRectangleV(buttonPosition, buttonSize, r.BLUE);

      Here we have two Vector2-like objects:

      buttonPosition → { x, y }
buttonSize     → { x, y }

      The first represents a position.

      The second represents a size.

      The two objects happen to have exactly the same shape.

      That is an important observation.

      The meaning comes from how we use the object.

      A pair of numbers such as:

      { x: 100, y: 50 }

      could describe a position.

      It could also describe a size.

      It could describe some other pair of values entirely.

      The object gives us the two numbers. The context tells us what those numbers mean.

      A point#

      Let’s make this even simpler.

      Imagine a target somewhere on the screen:

      const targetPosition = {
  x: 200,
  y: 120,
};

      We can draw a circle at that position:

      r.DrawCircleV(targetPosition, 20, r.RED);

      The object tells Raylib where the centre of the circle should be.

      We are using a pair of numbers to represent a location.

      That is our first useful way of thinking about a Vector2.

      Vectors are much more powerful than this. They can be used to represent things such as displacement, direction and velocity, and there is a lot of mathematics behind them.

      We are deliberately not going there yet.

      For now, think:

      Two numbers that travel together and describe something in our two-dimensional space.

      Drawing lines between points#

      Once we have points, we can do interesting things with them.

      Suppose we have two points:

      const start = {
  x: 50,
  y: 50,
};

const end = {
  x: 250,
  y: 150,
};

      Raylib gives us DrawLineV:

      r.DrawLineV(start, end, r.WHITE);

      The V tells us that this version of the function works with Vector2 values.

      Compare this with a function that takes individual coordinates:

      r.DrawLine(50, 50, 250, 150, r.WHITE);

      Both draw the same line.

      But in the second version, the four numbers are separate arguments.

      In the first version, we have two meaningful things:

      start
end

      and each one contains an x and a y.

      This becomes increasingly useful as our programs become larger.

      We can also use DrawLineEx:

      r.DrawLineEx(start, end, 5, r.YELLOW);

      This lets us specify the thickness of the line.

      Rectangle variations#

      We have only looked at two rectangle functions so far:

      r.DrawRectangleRec(rect, color);
r.DrawRectangleLines(rect.x, rect.y, rect.width, rect.height, color);

      Raylib gives us several other ways of drawing rectangles.

      For example, we can draw a rounded rectangle:

      r.DrawRectangleRounded(rect, 0.2, 8, r.BLUE);

      The 0.2 controls the roundness and 8 controls how many segments are used to approximate the rounded corners.

      We can also draw only its outline:

      r.DrawRectangleRoundedLines(rect, 0.2, 8, 2, r.WHITE);

      And there is an extended version:

      r.DrawRectangleRoundedLinesEx(rect, 0.2, 8, 4, r.WHITE);

      Don’t worry about memorising these functions.

      Instead, notice the pattern.

      We have the same rectangle:

      const panel = {
  x: 50,
  y: 50,
  width: 300,
  height: 150,
};

      We can choose different ways to draw it.

      r.DrawRectangleRec(panel, r.BLUE);

      or:

      r.DrawRectangleRounded(panel, 0.2, 8, r.BLUE);

      or:

      r.DrawRectangleRoundedLines(panel, 0.2, 8, 2, r.WHITE);

      The data describing the rectangle has not changed.

      Only what we do with it has changed.

      Gradients#

      Raylib can also draw gradients.

      For example:

      r.DrawRectangleGradientH(
  panel.x,
  panel.y,
  panel.width,
  panel.height,
  r.BLUE,
  r.WHITE,
);

      This draws a horizontal gradient.

      There is also:

      r.DrawRectangleGradientV(
  panel.x,
  panel.y,
  panel.width,
  panel.height,
  r.BLUE,
  r.WHITE,
);

      which draws a vertical gradient.

      Notice that these functions are slightly different.

      They don’t take a Rectangle object.

      They take the rectangle’s four individual values.

      That is okay.

      Different APIs can choose different representations.

      Our job is to understand what information the API needs.

      Circles#

      The same idea applies to circles.

      We can draw a circle using a position object:

      const target = {
  x: 200,
  y: 100,
};

r.DrawCircleV(target, 30, r.RED);

      Or we can draw just its outline:

      r.DrawCircleLines(target.x, target.y, 30, r.WHITE);

      We can also draw only part of a circle.

      For example:

      r.DrawCircleSector(target, 40, 0, 90, 20, r.BLUE);

      and:

      r.DrawCircleSectorLines(target, 40, 0, 90, 20, r.WHITE);

      These APIs let us represent more interesting shapes.

      We don’t need to memorise all their arguments.

      Instead, use VS Code to help you.

      If you type:

      r.DrawCircleSector(

      and hover over the function, VS Code will show you its type definition.

      Read it.

      Look at the arguments.

      Try small experiments.

      Explore#

      Here are some Raylib APIs we have not demonstrated yet:

      DrawRectangleGradientH
DrawRectangleGradientV
DrawCircleLines
DrawCircleSector
DrawCircleSectorLines
DrawLineEx

      We have shown you enough examples to understand the pattern.

      Now use VS Code to explore the APIs yourself.

      For each one, ask:

      1. What arguments does it need?
      2. What do those arguments represent?
      3. Are any of those arguments objects?
      4. What happens if you change one of the values?
      5. Can you use an object you already have?

      You don’t need to memorise the Raylib API.

      Learn to read the API.

      Your editor is part of your programming environment. The type definitions are there to help you.

      Objects describing things#

      Let’s put some of this together.

      Imagine we want to draw a small spaceship.

      We don’t need to build a complicated spaceship.

      Let’s say our spaceship has:

      • a position
      • a size
      • a color

      We could describe it like this:

      const spaceship = {
  position: {
    x: 100,
    y: 120,
  },

  size: {
    x: 60,
    y: 30,
  },

  color: r.WHITE,
};

      We now have one object describing something in our world.

      We can use its parts to draw it:

      r.DrawRectangleV(spaceship.position, spaceship.size, spaceship.color);

      We could change how it looks without changing what the spaceship is:

      r.DrawRectangleRounded(
  {
    x: spaceship.position.x,
    y: spaceship.position.y,
    width: spaceship.size.x,
    height: spaceship.size.y,
  },
  0.3,
  8,
  spaceship.color,
);

      There is an interesting distinction here.

      The spaceship is something we invented for our program.

      The position, size and color are ways of describing it.

      And the rectangle is one way of drawing it.

      We don’t need special JavaScript machinery to do this.

      No classes.

      No constructors.

      No complicated object-oriented programming.

      Just objects containing information.

      Try it#

      Here are some small exercises.

      Each one should be short. Don’t spend twenty minutes trying to make it beautiful.

      The point is to practise using objects with Raylib.

      1. A colored window#

      Create an object representing a window.

      Give it:

      • a position
      • a width
      • a height
      • a color

      Draw it using DrawRectangleRec.

      Then draw its outline using DrawRectangleLines.

      Try changing the color.

      Then try giving the color a lower alpha value.

      2. A rounded button#

      Create an object representing a button.

      Give it a position, size and color.

      Draw it as a rounded rectangle.

      Then draw its outline.

      Try changing the roundness.

      What happens when you make the roundness very small?

      What happens when you make it larger?

      3. Two points#

      Create two meaningful points in your scene.

      For example:

      const leftPoint = {
  x: 50,
  y: 100,
};

const rightPoint = {
  x: 250,
  y: 100,
};

      Draw a circle at each point.

      Then connect them using DrawLineV.

      Change their positions.

      Notice how the line follows them.

      4. A simple target#

      Make a target using circles.

      Create an object representing the target’s position.

      Use that same position with several drawing calls to create concentric circles.

      For example:

      large circle
medium circle
small circle

      Can you make the colors different?

      Can you make the middle circle partly transparent?

      5. A very simple object#

      Choose something simple:

      ball
car
button
target
window

      Represent it with a JavaScript object.

      Give it a position, size and color.

      Then draw it.

      Don’t add movement.

      Don’t add interaction.

      Just make the object exist in your program and use its information to draw it.

      Go back to the Scanner#

      We have already built something using Raylib: the Scanner.

      When we first built it, we probably had several independent variables:

      const scanStart = 0;
const scanWidth = 20;
const speed = 1;

      And we had other values describing the things being scanned.

      Now we know about objects.

      So go back to the Scanner assignment.

      Don’t change what the Scanner does.

      Instead, ask a different question:

      What things exist in this program?

      There is a scanner.

      There are ranges.

      Perhaps the scanner could be represented by one object.

      Perhaps each range could be represented by an object.

      Then ask:

      What information belongs together?

      For example:

      const scanner = {
  x: 0,
  width: 20,
  speed: 1,
};

      and:

      const range = {
  x: 100,
  width: 50,
};

      These are just examples. Decide what makes sense for your program.

      The important part is not to copy these objects.

      The important part is to look at your existing program and discover its objects.

      This is something you will do repeatedly as your programs grow.

      We start with a collection of values.

      Then we notice that some values belong together.

      We give those values a name.

      And suddenly, instead of thinking about ten separate numbers, we can think about a few things.

      One last question#

      Look back at the programs you have written so far.

      You have used many values:

      x
y
width
height
color
speed

      Ask yourself:

      Which of these values describe the same thing?

      If x and y describe a position, perhaps they belong together.

      If width and height describe a size, perhaps they belong together.

      If four numbers describe a color, perhaps they belong together.

      If several values describe a thing in your program, perhaps those values belong together too.

      That is one of the most useful things objects give us.

      We can make our programs resemble the things we are thinking about.
