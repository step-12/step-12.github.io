      Drawing Text

      October 21, 2026
      Text, Fonts, Raylib

      Drawing text#

      We’ve spent a lot of time drawing things such as rectangles, circles and lines.

      But what if we want to put some words on the screen?

      Raylib provides DrawText for this.

      The basic API looks like this:

      r.DrawText("Hello, Raylib!", 20, 20, 24, r.WHITE);

      The arguments are:

      1. The text to draw.
      2. The x-coordinate.
      3. The y-coordinate.
      4. The font size.
      5. The color.

      For example:

      r.DrawText("Hello", 50, 50, 20, r.WHITE);
r.DrawText("Raylib", 50, 80, 30, r.YELLOW);

      The two pieces of text can have different positions, sizes and colors.

      Fonts#

      There is something interesting happening here.

      When we ask Raylib to draw:

      r.DrawText("Hello", 50, 50, 30, r.WHITE);

      where does the shape of each letter come from?

      A font describes how characters should look.

      A font contains information about the shapes of characters such as A, B, C, and so on. Raylib uses this information to work out what the characters should look like when they are drawn.

      The process of turning a description of a shape into pixels is called rasterisation.

      The screen is made up of pixels. Ultimately, the computer has to answer a question like:

      Which pixels should be lit up to make this letter look like an A?

      A simplified picture of what is happening is:

              font
          │
          ▼
    shape of the letter
          │
          ▼
      rasterisation
          │
          ▼
        pixels

      Why not just store letters as images?#

      You might wonder why we don’t simply store an image of every letter.

      We actually can.

      These are called bitmap fonts. A bitmap font stores each character as a collection of pixels.

      That works, but it creates a problem.

      Imagine that we have an image of the letter A that is 20 pixels tall.

      What happens when we want to draw the same font at 50 pixels tall?

      We could make another image.

      And then another for 60 pixels.

      And another for 100 pixels.

      We would need many different images to represent the same font at different sizes. Scaling a small bitmap image up also tends to make the characters look jagged.

      A font that describes the shape of a character can instead be rasterised at the size we need.

      So the important distinction is:

      Bitmap font

"A" → stored as pixels


Shape-based font

"A" → stored as a description of its shape
          ↓
       rasterise
          ↓
       pixels
