      Textures

      October 19, 2026
      Textures, Raylib

      Additional Raylib API#

      So far, we’ve learned how to draw a few basic shapes with Raylib.

      We’ve also learned how to work with objects in Raylib, including Color and Vector2.

      In this post, we’ll add a few more tools to our drawing vocabulary:

      • drawing onto a render texture

      The goal here is simple: learn what these APIs let us do and get comfortable using them.

      We will not try to understand everything happening inside Raylib. Where there is an interesting idea underneath an API, we’ll take a brief look at it.

      Drawing somewhere else#

      Until now, we’ve drawn directly onto the window.

      For example:

      r.DrawCircle(100, 100, 50, r.RED);

      The circle appears on the window.

      But imagine that we wanted to draw something somewhere else first.

      Why might we want that?

      Perhaps we want to construct a complicated picture once and then display it several times.

      Or perhaps we want to draw something over several frames and keep what we drew.

      We need another drawing surface.

      Imagine that Raylib gives us another invisible canvas:

                        draw
                   │
                   ▼
        ┌─────────────────────┐
        │                     │
        │   another canvas    │
        │         ●           │
        │                     │
        └─────────────────────┘
                   │
                   │ show it
                   ▼
        ┌─────────────────────┐
        │       WINDOW        │
        │         ●           │
        └─────────────────────┘

      Instead of drawing directly onto the window, we draw onto this other canvas.

      Then we can put that canvas onto the window.

      This is the basic idea of a render texture.

      A render texture#

      Raylib lets us create one with:

      const target = r.LoadRenderTexture(300, 200);

      Think of target as a picture that we can draw onto.

      To draw onto it, we temporarily change where Raylib sends drawing commands:

      r.BeginTextureMode(target);

r.DrawCircle(150, 100, 50, r.RED);

r.EndTextureMode();

      Between BeginTextureMode and EndTextureMode, our drawing commands go onto the render texture instead of the window.

      We can then draw the render texture onto the window:

      r.DrawTexture(
  target.texture,
  0,
  0,
  r.WHITE
);

      The complete idea is:

      const target = r.LoadRenderTexture(300, 200);

r.BeginTextureMode(target);

r.DrawCircle(150, 100, 50, r.RED);

r.EndTextureMode();

r.DrawTexture(target.texture, 0, 0, r.WHITE);

      Think about the flow:

      Create render texture
        ↓
Draw onto render texture
        ↓
Finish drawing onto render texture
        ↓
Draw render texture onto window

      The render texture is simply an image that we have the ability to draw onto.

      Drawing something once#

      Here’s one useful thing we can do with a render texture.

      Suppose we want to create a little picture and then use that picture repeatedly.

      We can create the render texture and draw onto it before the main loop.

      For example:

      const target = r.LoadRenderTexture(200, 200);

r.BeginTextureMode(target);

r.ClearBackground(r.BLACK);
r.DrawCircle(100, 100, 60, r.RED);
r.DrawCircle(80, 80, 15, r.WHITE);

r.EndTextureMode();

while (!r.WindowShouldClose()) {
  r.BeginDrawing();

  r.ClearBackground(r.DARKGRAY);

  r.DrawTexture(target.texture, 50, 50, r.WHITE);
  r.DrawTexture(target.texture, 300, 50, r.WHITE);
  r.DrawTexture(target.texture, 550, 50, r.WHITE);

  r.EndDrawing();
}

      We’ve created the picture once.

      Then, every frame, we simply draw that picture wherever we want it.

      Notice that we’re not redrawing the circles three times.

      We’ve made the picture once and are reusing it.

      Preserving a drawing#

      There is another interesting thing a render texture can do.

      Imagine that every frame we draw a circle at a new position.

      Normally, if we clear the window every frame, the previous circle disappears:

      Frame 1

        ●


Frame 2

             ●


Frame 3

                  ●

      Only the latest frame is visible.

      But what if we draw the circles onto a render texture and don’t clear the render texture?

      Then what we draw can remain there:

      Frame 1

        ●


Frame 2

        ●   ●


Frame 3

        ●   ●   ●

      The render texture remembers what we have already drawn onto it.

      For example:

      const target = r.LoadRenderTexture(600, 400);

while (!r.WindowShouldClose()) {
  r.BeginTextureMode(target);

  r.DrawCircle(x, y, 5, r.WHITE);

  r.EndTextureMode();

  r.BeginDrawing();

  r.ClearBackground(r.BLACK);

  r.DrawTexture(target.texture, 0, 0, r.WHITE);

  r.EndDrawing();
}

      Every frame, we add another circle to the render texture.

      The window itself is still cleared and redrawn every frame. The important difference is that the render texture is not being cleared, so the circles we’ve already drawn remain there.

      This gives us a simple way to create things such as trails or drawings that accumulate over time.

      Selecting part of a texture#

      So far, DrawTexture draws the entire texture.

      But sometimes we don’t want the entire thing.

      Imagine that our texture contains:

      ┌────────────────────────┐
│                        │
│       ┌──────┐         │
│       │      │         │
│       │      │         │
│       └──────┘         │
│                        │
└────────────────────────┘

      What if we only want to draw the rectangle in the middle?

      Raylib provides DrawTextureRec for this.

      The basic idea is:

      r.DrawTextureRec(
  texture,
  sourceRectangle,
  position,
  tint
);

      The sourceRectangle tells Raylib which part of the texture we want.

      For example:

      const source = {
  x: 50,
  y: 50,
  width: 100,
  height: 100
};

r.DrawTextureRec(
  target.texture,
  source,
  { x: 200, y: 100 },
  r.WHITE
);

      We are saying:

      Take this 100 × 100 rectangle from the texture and draw it at (200, 100).

      This is useful whenever a texture contains more than the part we currently want to display.

      The yellow outline marks the selected region in the original texture. On the right, DrawTextureRec draws only that region at its original size. The outline is a guide, so it is not included in the extracted image.

      Flipping#

      There is another useful trick.

      The width and height of the source rectangle can be negative.

      For example:

      const source = {
  x: 100,
  y: 0,
  width: -100,
  height: 100
};

      A negative width flips the selected region horizontally.

      Similarly, a negative height flips it vertically.

      This gives us a simple way to flip something without creating another image.

      These are the kinds of small tricks that become useful once you start combining Raylib’s drawing APIs.

      A few things to try#

      These exercises are deliberately small. The goal is to become comfortable with the new APIs.

      1. A reusable picture#

      Create a render texture before your drawing loop.

      Draw a small composition onto it using several Raylib primitives.

      Then display that same composition in three different places on the window.

      2. A drawing that remains#

      Create a render texture and draw a small circle onto it at a changing position each frame.

      Don’t clear the render texture.

      Use the result to create a trail.

      What you should have learned#

      By the end of this post, you should have added four ideas to your Raylib vocabulary:

      • Render textures — a render texture gives us another surface to draw onto. We can create a picture once, reuse it, or let a drawing accumulate over time.

      You don’t need to remember every API signature. You should be able to recognise what each API is for, read its documentation, and experiment with it.
