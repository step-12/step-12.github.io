    Intro to Git/GitHub

    September 25, 2026
    Git, Gh, Repo Creation, Gacp

    So far, whatever the raylib code you wrote has stored on your computer.

    Now think about these situations:

    • What if your laptop suddenly stops working?
    • What if you want your code reviewed by mentors or peers, may be during the weekend?
    • What if your laptop gets lost or damaged?
    • What if you want to access your code from another computer?
    • What if you are away from your laptop but need to look at your latest code?

    All of these point to the same problem: your code lives in exactly one place.

    So we need another copy of it, somewhere other than your laptop.

    That other copy is commonly called a:

    remote repository

    For now, don’t worry about how it is connected.

    Just think:

    Code on your computer 
     │
     │
     ▼
Stored on the internet

    A remote repository is a version of a software project stored on the internet.

    GitHub is a service that helps to store our code on the internet.

    But wait.

    Before we can send anything to the internet, that remote repository has to exist somewhere first.

    So the first question is:

    How do we create a repository on GitHub?

    gh#

    One way is to open GitHub in your browser and click through the buttons.

    But we are already in the terminal. Why leave it?

    There is a command available on your machine:

    gh

    gh is GitHub’s official command line tool.

    Think of it as:

    GitHub
   │
   │ from your terminal
   ▼
  gh

    gh talks to GitHub for you, without leaving the terminal.

    Step 1: Check that gh is available#

    Run:

    gh --version

    You should see something like:

    gh version 2.99.0 (2026-09-01)
https://github.com/cli/cli/releases/tag/v2.99.0

    If you see that, gh is installed on your machine.

    It’s okay if the version number is different. The important thing is that you see a version number.

    Step 2: Check that you are already logged in#

    Creating a repository means creating it under your GitHub account.

    So GitHub needs to know who you are.

    This has already been set up for you on your machine. Let’s just confirm it.

    Run:

    gh auth status

    You should see something like:

    github.com
  ✓ Logged in to github.com account your-username
  - Active account: true
  - Git operations protocol: https

    You may see some extra lines about GitHub token information. You can ignore those.

    If you see ✓ Logged in, you are good. Move on to the next step.

    But if you see something like:

    You are not logged into any GitHub hosts. To log in, run: gh auth login

    Then:

    Reach out to mentors.

    Step 3: Go to one of your projects#

    Example:

    workspace/raylib_exercises/
    program.js

    Move into that directory:

    cd workspace/raylib_exercises

    Step 4: Make sure it is a Git repository#

    Before GitHub can store your code, Git has to be tracking it on your computer.

    That’s the job of the other command:

    git

    git is the tool that keeps the history of your files — what changed, when it changed, and what the code looked like before.

    It does not talk to the internet. It works entirely on your machine.

    git  →  keeps history, on your computer
gh   →  talks to GitHub, on the internet

    Two commands, two different jobs.

    When you run:

    git init

    Git prepares this directory to be managed as a Git repository, allowing Git to keep track of changes made to the files inside it.

    That directory is now called a:

    Git repository

    So, at a basic level:

    Directory
    +
Git's tracking information
    ↓
Git repository

    For now:

    A Git repository is a directory that Git is managing so it can keep track of its history.

    Now you have:

    Git repository

    on your computer, but nothing on the GitHub yet.

    Step 5: Create the repository on GitHub#

    Run:

    gh repo create raylib_exercises --public --source=. --remote=origin

    That’s one line, but a lot is happening in it.

    Let’s break it down:

    gh repo create raylib_exercises
      ↓
create a repository named "raylib_exercises" on GitHub

--public
      ↓
anyone can see it

--source=.
      ↓
use the repository from your current directory

--remote=origin
      ↓
give the GitHub repository the nickname origin

    Once you run the command, you will see some output like this:

    ✓ Created repository charan/raylib_exercises on github.com
  https://github.com/charan/raylib_exercises
✓ Added remote https://github.com/charan/raylib_exercises.git

    Which means that the repository has been created on GitHub and your computer is now connected to it.

    Let’s look at two of them a bit more closely.

    --public

    Remember one of our original questions?

    What if you want your code reviewed by mentors or peers?

    A public repository means your mentors and peers can simply open the link and look at your code.

    --remote=origin

    This is the piece that links the two sides together:

    Your computer                GitHub
     │                          │
     └────── origin ────────────┘

    origin is just a name.

    It is the name your computer uses to refer to that repository on GitHub.

    Step 6: Open the repository in your browser#

    To open it in the browser:

    gh repo view --web

    The mental model#

    Your project now exists in two places.

       Your computer                    GitHub
     (local)                       (remote)

raylib_exercises/               raylib_exercises
    hello.js                        hello.js
        │                               ▲
        └──────── origin ───────────────┘

    The copy on your computer is called local.

    The copy on GitHub is called remote.

    local   →  where you write your code
remote  →  where your code is stored and shared

    You work on local. You send your changes to remote.

    For now, don’t worry about the specifics and about it’s internals etc.

    Just hold on to this:

    I write code locally. I send it to the remote, so that others can see it.

    gacp#

    Before we move on, let’s be clear about what we have actually done so far.

    We created the remote repository:

    gh repo create
      ↓
a place on GitHub to store this project

    That’s it.

    Creating the repository is a one-time job. You will not run gh repo create again for this project.

    But your code will keep changing.

    You will fix a bug today, add a feature tomorrow, change a colour the day after.

    None of those changes reach GitHub on their own.

    Create the repository  →  once
Send your changes      →  again and again

    So every time you change your code, you still need a way to say:

    “Send my latest changes to the remote repository.”

    That’s a different job from creating the repository.

    gacp is the command for that job.

    gacp is a command which helps us to send our code changes from our computer to the remote repository.

    you can use:

    gacp "fix greeting"

    How to use gacp#

    The basic syntax is:

    gacp [message]

    For example:

    gacp "fix greeting"

    Small example with gacp#

    Suppose you changed:

    function draw() {
  r.DrawText("Hello, world!", 10, 10, 20, r.RAYWHITE);
}

    to:

    function draw() {
  r.DrawText("Good morning, everyone!", 30, 30, 10, r.BLUE);
}

    you can run:

    gacp "fix greeting"

    This helps you to send your code changes to the remote repository.

    For now , don’t worry about what exactly happens when you run this command. Just know that it helps you to send your code changes to the remote repository.

    The very first gacp in a project may complain that your branch has no upstream branch. That is normal. Run git push -u origin main once, and gacp will work from then on.

    Tired of copying your template?#

    You built a raylib template:

    raylib_template/
├── main.js
├── sketch.js
└── geometry.js

    And every time you start a new project, you copy it:

    cp -R ~/workspace/raylib_template ~/workspace/moving_circle

    Copy again for the next one.

    And again for the one after that.

    It works, but look at what it depends on.

    Your template exists in exactly one place:

    ~/workspace/raylib_template

    on this laptop.

    That’s the same problem we started this whole blog with.

    And we already know the answer:

    Put it on GitHub.

    Then the template is not a directory on one laptop anymore.

    Step 1: Put the template on GitHub#

    Nothing new here. It is exactly what you did for your exercises.

    cd ~/workspace/raylib_template
git init
gh repo create raylib_template --public --source=. --remote=origin
gacp "add raylib template"
gh repo edit --template

    Only the last line is new.

    By default GitHub treats this like any other repository. That one command says something more specific:

    This repository is a starting point for other projects.

    All of this is a one-time job. You will not run these again for your template.

    Step 2: Start a new project from it#

    Now suppose you want to start moving_circle.

    Run these four lines:

    Please make sure to replace your-username with your actual GitHub username from the below command.

    cd ~/workspace
gh repo create moving_circle --template your-username/raylib_template --public --clone
cd moving_circle
git push -u origin main

    Let’s break it down.

    The second line is the important one:

    gh repo create moving_circle
      ↓
create a new repository named "moving_circle" on GitHub

--template your-username/raylib_template
      ↓
start it from my template

--public
      ↓
anyone can see it

--clone
      ↓
and bring a copy down to this computer

    You only need it once per project.

    If it says Everything up-to-date, that is fine too. It just means there was nothing new to send.

    Now look:

    moving_circle/
├── main.js
├── sketch.js
└── geometry.js

    All three files are there, exactly as in your template.

    Open sketch.js and start working.

    From here on, it is just:

    gacp "draw the circle"

    Sharing your code#

    Let’s go back to one of the questions we started with:

    What if you want your code reviewed by mentors or peers, may be during the weekend?

    We can answer it now.

    Your repository on GitHub has an address.

    To see it, run:

    gh repo view --web

    This opens your repository in the browser.

    Look at the address bar:

    https://github.com/your-username/raylib_exercises

    That is the link.

    Send that link to your mentor or your peer, and they can open your code from their own computer.

    And that closes the loop we opened at the beginning:

    Code only on your laptop
        │
        │  git  +  gh
        ▼
Code on GitHub
        │
        │  a link
        ▼
Your mentors and peers can see it
